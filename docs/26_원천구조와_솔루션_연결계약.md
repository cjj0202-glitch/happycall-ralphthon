# 원천 구조를 반영한 해피콜·WMS·TMS 연결 계약

2026-09-21 pc1 로컬 구조 조사 기반. 이 문서는 원천 레코드·운영 식별값·상담 답변 원문을 포함하지 않습니다. 상세 파일별 수신검증/통계/재현 스크립트는 pc1 `.local/raw-review/`에 보관하며 Git/Release에 올리지 않습니다. 파일수·크기 일치, 대표해시 일치, 전체 행 의미 검증은 별개입니다. 수신 사본 분석이며 운영 원본의 최신성을 보증하지 않습니다.

## 1. 세 자료의 행 단위와 역할

| 자료 | 실제 구조 | 제품에서 참고할 역할 | 이 자료만으로 확정할 수 없는 것 |
|---|---|---|---|
| 30 작업수집 gzip JSON | PICKING/SORTING 공정별 출고상품 작업 스냅샷 | 피킹 방식·피킹/분류 기록·계획/실적 슈트·출고상품 맥락 | 연속 소터 이동/BCR·정밀 경로·작업자 귀책·CCTV |
| 33 해피콜 gzip JSON | occ 접수집계, den 출고분모, dim 점포차원, org 부서차원, days 기간 | 문의유형/사유/원인/부서 어휘·조회 조건·통계 구조 | 개별 상담 녹취·개별 접수 ID와 출고 건의 직접 연결 |
| 33 answers CSV | 분류·사유·원인·답변 사례·가중 건수 | 가상 시나리오 작성 시 업무 패턴 참고 | 해당 접수의 확정 답변, 현재 SLA·실적 성과 |
| 36 방문지 실적 CSV | 배송일·센터·루트·방문순번별 점포/센터/차고지 방문행 | 계획·운행·점포 완료·모바일/단말 진출입·방문순서 | 개별 GPS 궤적, 주문/상품/토트, 실물 인도 확정 |

현재 사본에서 30과 36의 대상 기간은 겹치지 않습니다. 33에는 두 업태와 서로 다른 집계분모가 섞여 있으며, CVS 해피콜 시연에는 CVS만 명시적으로 선택합니다. 서로 다른 기간의 원천을 같은 사건의 WMS/TMS 결과라고 합치지 않습니다.

## 2. WMS 어댑터 상세설계

1. 수집 봉투는 sourceSystem/sourceFile/sourceHash/collectedAt/검증된 centerId를 가집니다. centerId가 원본 행에 없으므로 수집 출처에서 확인하지 못하면 미확인입니다. 점포코드로 센터를 역추정하지 않습니다.
2. 원본키 후보는 `(centerId,targetDate,shpId,skuCode,processType,snapshotId)`, 업무라인 후보는 `(centerId,targetDate,shpId,skuCode)`입니다. 스냅샷 중복제거와 공정 연결은 서로 다른 단계입니다. 반복 수집파일을 새 작업으로 세지 않습니다.
3. `pickType`, `processType`, `relsAsortMthodCd`, `pickedAt`, `sortedAt`, `schdChuteNo`, `rsltChuteNo`, `boxCode`, `locationCode`를 출처와 함께 보존합니다. `boxCode`를 실물 토트ID로 확정하려면 코드 정의가 필요합니다.
4. PICKING/SORTING 양쪽에 같은 주문·피킹·출고수량이 반복될 수 있습니다. 공정행 전체 SUM을 금지하고 업무라인의 정의된 기준 행에서 한 번만 집계합니다. BOX/EA·출고단위·포장입수는 별도로 유지하며 임의 환산하지 않습니다.
5. 실적 NULL, 스키마에 필드 없음, 비대상공정, 공정 실적 미확인을 구분합니다. 시각 역전은 검토 상태이며 타임라인 정렬로 원본을 고치지 않습니다. roundedUp 필드는 정밀 통과시각이 아닙니다. 타임존 확인 전 원본시각을 임의 UTC/KST 변환하지 않습니다.
6. 피킹→분류 애니메이션은 실제 연속 위치추적과 구분합니다. 이동/BCR 센서 이력·CCTV가 없으므로 현재 시연에는 독립 합성 event/media를 사용합니다. 화면이 보여주는 관측 차이는 휴먼에러 확정이 아닙니다.

## 3. TMS 어댑터 상세설계

원본헤더는 숫자 접두어와 한글 명칭을 보존해 버전별 매핑합니다. 키 후보는 `(배송일,센터,루트,방문순번)`이며 전파일 유일성 검사 전 전역 유일키로 확정하지 않습니다.

- `점포유형`으로 점포·센터·차고지를 나눕니다. 루트의 모든 방문행을 고객 점포 수나 점포배송 완료로 세지 않습니다.
- 배차일, 계획시각, 시작/종료, 점포행별 배송완료, 모바일/단말기 GPS 진입·이탈, keyIn을 별도 사실로 보존합니다. 이름이 배송완료인 열과 루트 완료시각을 혼동하지 않습니다.
- HH:mm만 있는 점착 계획시각은 `localTime`으로 보관합니다. 배차일+시간을 바로 timestamp로 조합하지 않고 야간 경계/업무일 규칙을 확인합니다. 실제 일시에는 전일·익일이 존재할 수 있습니다.
- 상태가 완료여도 완료시각이 없을 수 있습니다. 강제/모바일강제 등 기록 방법도 보존하며 시각을 만들어 채우지 않습니다. GPS 진입은 현장 접근 근거이고 실물 인도의 증거가 아닙니다.
- 점포 위치 좌표, 보고 위치, GPS 수집건수와 실제 이동 궤적을 구분합니다. 방문순서를 잇는 선은 개념 경로이며 실제 도로 주행 궤적이라고 표시하지 않습니다.
- 점포명만으로 해피콜/WMS를 자동 조인하지 않습니다. 센터·유효기간을 포함한 점포코드/별칭 매핑과 모호성 판정이 필요합니다.

## 4. 해피콜 어댑터·AI 정제 상세설계

`occ`의 연도/일자/점포코드/대분류/사유/원인/처리부서와 접수건수는 집계행입니다. 코드가 문자열이면 선행0을 보존합니다. NULL이 없더라도 '원인파악중'·'미지정' 등 의미상 미확인 상태는 `causeStatus=unknown`으로 해석합니다.

업무 용어인 미입고/오입고와 시연의 미도착/오출고를 동일 코드로 무조건 치환하지 않습니다. 원분류를 유지하고 상품미입고·차량미도착·타상품수령 등의 시나리오 조건을 함께 정의해 좁혀 사용합니다. 부서 마스터는 허용 부서 추천의 후보사전으로 참고하며 과거 집계만으로 현재 이관 담당자를 확정하지 않습니다.

메타 기간과 실제 행의 날짜범위를 각각 검증하고, 전년/금년 YTD를 연속 기간으로 간주하지 않습니다. `den` 출고분모와 답변 CSV 가중건수는 접수행 수와 다른 측정량입니다. 답변 CSV에는 개별 접수 연결키가 없어 사례 하나를 해당 사건의 회신으로 자동 채택하지 않습니다.

원본 자유서술은 외부 AI 호출에 넣지 않습니다. 시연은 독립 합성 대본과 입력으로 진행하며 원문→STT→AI 제안→사람 확정을 분리합니다. 구조화 출력은 주문 주장과 수령 주장을 분리하고, 근거 인용/불확실성/수량·단위·부서의 확인 여부를 보존합니다.

## 5. 사건 연결과 UI 표시 계약

사건 연결은 `caseId → 확인된 점포ID + 업무일 + 주문/출고키 + 배차/방문키`를 따라가야 합니다. 현재 사본은 그 교차키를 모두 제공하지 않으므로 실데이터의 종단 사건 연결은 미검증입니다.

근거 카드에는 sourceSystem, sourceRecordKey, observedAt, observedAtPrecision, timezoneStatus, sourceAsOf, recordStatus, relationStatus, synthetic를 둡니다. `relationStatus`는 exact/needs_review/unlinked로 분리합니다. 날짜·코드·매핑 충돌 시 자동 채택을 차단하고 사람이 확인할 후보만 보여줍니다. 원문 진술·시스템 기록·AI 추정·합성 설명을 한 사실 등급으로 합치지 않습니다.

미등록 공정 영상은 '영상 없음'입니다. 합성 영상은 eventId/caseId/cameraId/구간이 명시된 경우에만 연결합니다. 같은 MP4를 여러 실제 작업의 CCTV로 재사용하지 않습니다.

## 6. 구현 전 통과할 데이터 반례

| 반례 | 기대 결과 |
|---|---|
| 동일 스냅샷을 두 번 읽음 | 작업량·실적 증가 없음, 원천 목록에는 수집이력 보존 |
| 같은 출고상품의 PICKING/SORTING 수량 | 전체 SUM으로 이중계상하지 않음 |
| 구버전 JSON에 필드가 없음 | 누락을 보존하고 실적0으로 보충하지 않음 |
| 피킹만 있는 bypass | 분류 실패·누락으로 단정하지 않음 |
| 분류시각이 피킹보다 빠름/타임존 미상 | 충돌 표시, 인위적인 정상 순서 재작성 없음 |
| 점포명은 같고 날짜·센터·루트가 다름 | 자동 조인 차단 |
| 완료상태+완료시각없음 | 상태와 시각의 불일치를 보존 |
| 계획 HH:mm와 전일/익일 방문 | 업무일 규칙 확인 전 날짜 확정 없음 |
| 센터/차고지 방문행 | 점포 배송 KPI·상담 근거의 점포행에서 제외 |
| 원인파악중이나 NULL아님 | 원인 미확인 유지 |
| 답변집계와 접수집계 분모차이 | 비율·정확도·건수를 상호 대체하지 않음 |
| 원본매핑 없는 합성영상 | 실제 작업·휴먼에러 확인 증거로 채택하지 않음 |

pc2는 문의유형·미확인·원문보존을 음성/접수 UX에, pc3는 공정행·시각품질·영상제약을 WMS에, pc4는 방문유형·계획/실적·기록방법을 TMS에 반영합니다. 원본 DB나 나머지 기간 전체를 먼저 확보할 필요는 없습니다. 실제 연결 검증 단계에서 기간이 겹치는 작업수집분, 점포코드/별칭 매핑, 문의와 출고/배차의 연결키 정의를 우선 확보합니다.
