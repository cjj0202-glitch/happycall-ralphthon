## 1. Clone 또는 안전한 수동 업데이트

PowerShell에서 실행합니다. 예시의 `C:\00.프로젝트`가 이 PC에 실제로 있는지 확인하고, 없다면 사용자가 정한 작업 폴더로 바꿉니다. `gh`가 없거나 private 저장소 접근에 실패하면 그 결과를 메인에게 보고합니다.

```powershell
gh auth status
gh api user --jq .login
gh repo view cjj0202-glitch/happycall-ralphthon --json nameWithOwner
# 처음 받는 PC에서만, 실제 작업 폴더로 이동한 후:
gh repo clone cjj0202-glitch/happycall-ralphthon
Set-Location -LiteralPath '.\happycall-ralphthon'
```

기존 체크아웃은 작업 중인 파일을 먼저 확인합니다. 아래 업데이트는 한 번씩 수동으로 실행하며 루프에 넣지 않습니다.

```powershell
git status --short
git branch --show-current
git remote -v
git fetch origin
git log --oneline --left-right HEAD...origin/main
git diff --stat HEAD..origin/main
git diff HEAD..origin/main -- channel/pcs.json scripts/mailbox_watch.py scripts/start_mailbox_watch.ps1 scripts/stop_mailbox_watch.ps1
# main 브랜치이고 로컬 변경이 없으며 원격 변경을 검토한 뒤에만:
git merge --ff-only origin/main
```

변경 파일이 있거나 브랜치가 다르거나 ff-only가 거부되면 중단하고 메인에게 상태를 보고합니다. 자동 `pull` 반복, 강제 초기화, 임의 stash를 사용하지 않습니다. 받은 코드가 곧 다음 실행 코드입니다.

## 2. 실제 PC 등록

```powershell
python channel/whoami.py
python channel/whoami.py --hostname
gh api user --jq .login
python scripts/preflight.py
```

hostname·GitHub login·희망 역할·HEAD를 메인에게 보고합니다. hostname은 실제 출력 그대로 전달합니다. 슬롯/역할은 메인이 결정하며, 미등록 PC에서는 편지함 수신·발송·watch를 하지 않습니다. preflight의 `PENDING`을 PASS로 바꾸지 않습니다. 메인이 `channel/pcs.json`을 반영한 뒤 위의 수동 업데이트를 거쳐 다시 신원을 확인합니다.

## 3. 등록 후 실행

저장소 루트의 PowerShell에서 실행합니다. `python` 대신 필요한 경우 실제 Python 실행 파일 경로를 사용할 수 있습니다. Python과 인증된 `gh`가 필요합니다.

```powershell
python scripts/mailbox_watch.py check
# 최초 세션에서 열린 편지는 1회 확인:
python channel/mail.py inbox
python scripts/mailbox_watch.py once
python scripts/mailbox_watch.py start
# 같은 명령을 또 실행하면 ALREADY_RUNNING과 기존 PID를 출력해야 합니다.
python scripts/mailbox_watch.py check
```

기본 실행은 `python -u <절대경로>\channel\mail.py watch --interval 30`을 숨김 창으로 띄웁니다. `RALPH_PC` 환경변수가 있으면 중단합니다. hostname 유일 매칭, 등록 GitHub 계정, 자기 inbox를 대조합니다. Check는 편지 목록을 읽지 않습니다. 미등록일 때는 읽기 전용 preflight와 준비 보고만 출력하고 exit 2로 끝납니다. preflight는 로컬 `.local/preflight.json`을 기록합니다.

| 모드 | 동작 |
|---|---|
| 기본 / `start` | 숨김 감시, PID/로그 기록, 중복 실행 방지 |
| `check` / `status` | 등록·GitHub 인증·실행 프로세스·저장 상태 대조 |
| `once` | `watch --once` 1회; 이미 실행 중이면 먼저 중지 |
| `foreground` | 현재 터미널에서 `watch --bell`; Ctrl+C로 종료 |

foreground와 once도 실행 잠금을 사용합니다. 직접 실행한 다른 `mail.py watch`가 있으면 중복 기동을 거부하므로 해당 터미널에서 먼저 종료합니다. 기본 숨김 감시는 로그에 쓰며 소리/데스크톱 알림은 보장하지 않습니다. **터미널 감시 알림은 Codex 대화 자동 재개가 아닙니다.** 자동화 연결은 별도 작업입니다.

PowerShell `.ps1` 두 파일은 같은 Python 런처를 호출하는 선택 래퍼입니다. 실행 정책이 허용하는 PC에서만 사용합니다. 기본 안내는 모든 PC에서 위 Python 명령을 사용합니다.

## 4. 상태·로그·중지·재시작

```powershell
Get-Content -LiteralPath '.local\mailbox-watch.json'
Get-Content -LiteralPath '.local\mailbox-watch.stdout.log' -Tail 30
Get-Content -LiteralPath '.local\mailbox-watch.stderr.log' -Tail 30
Get-Item -LiteralPath '.mailbox_state.pc1.json' # 실제 자기 슬롯으로 바꿈
python scripts/mailbox_watch.py stop
python scripts/mailbox_watch.py start
```

메타데이터의 `process_id`, `command_line`, `created_ticks`와 Check의 `verified_process=True`를 대조합니다. PID 파일만으로 생존을 판정하지 않습니다. 시작 안내는 기동 증거이며 GitHub 조회 성공 증거는 아닙니다. 자기 `.mailbox_state.<슬롯>.json` 갱신 시각과 로그를 함께 확인합니다. 정상 무변화 폴링은 추가 출력이 없습니다. Watch는 받은 편지·보낸 편지의 신규 open/댓글 수 증가/열림·닫힘 변화를 감지하며 본문 편집 알림은 지원하지 않습니다. 조회 상한은 라벨당 1000건이며 상한 도달을 성공으로 처리하지 않습니다.

stop은 저장한 PID·프로세스 생성 시각·실행 파일·저장소·명령줄이 모두 일치할 때만 그 프로세스를 중지합니다. 다른 프로세스나 PID 재사용을 발견하면 중지하지 않습니다. 이미 종료된 PID는 오래된 상태 파일만 정리합니다. foreground는 원래 터미널에서 Ctrl+C로 종료합니다.

stdout/stderr 로그는 중지 시 보존하고 다음 Background 시작 때 덮어씁니다. 장애 증거가 필요하면 재시작 전에 두 로그를 별도 보관합니다. 전원 재시작 후에는 자동 실행되지 않으므로 등록 확인 후 직접 시작합니다.

| 증상 | 조치 |
|---|---|
| PowerShell 래퍼 실행 정책 차단 | 위 Python 주명령 사용; PowerShell 정책 변경 없음 |
| PENDING 미등록/계정 불일치 | 실제 hostname/login을 메인에게 보고하고 등록 반영 후 재확인 |
| 조회 실패 | 네트워크·`gh auth status`·저장소 접근 확인. watch는 실패 횟수에 따라 최대 300초 간격으로 재시도 |
| ALREADY_RUNNING | 표시 PID를 Check로 대조; 주기를 바꾸려면 stop 후 start |
| 잠금 사용 중 / unmanaged watcher | Foreground/Once/다른 터미널 감시가 있는지 확인하고 그 실행을 종료 |
| PID/명령 불일치 | 로그·state·실제 프로세스 대조를 메인에게 보고; PID만 보고 kill하지 않음 |
| 시작 직후 종료 | stderr와 Python 경로 확인; 살아 있는 감시기 수부터 확인하고 재시도 |
