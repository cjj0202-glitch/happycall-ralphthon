## 2. 브라우저 연결 순서

1. [Vercel 로그인](https://vercel.com/login)에서 그룹 주소를 넣고 이메일 로그인합니다.
2. **이번 로그인 시도에 대응하는** 인증 메일의 번호를 입력합니다. 여러 팀이 공유하는 계정이므로 다른 로그인 메일을 혼동하지 않고 순서대로 진행합니다. 인증번호는 GitHub나 안내 문서에 기록하지 않습니다.
3. 왼쪽 위 워크스페이스에서 **52g Studio (Enterprise)**를 선택합니다. 개인 Hobby에 머물면 프로젝트가 안 보일 수 있습니다.
4. **g-23만** 엽니다. 다른 팀 프로젝트는 열거나 수정·배포하지 않습니다.
5. g-23의 **Connect Git Repository**에서 우리 제품 저장소를 연결합니다. 신규 프로젝트를 임의로 만들지 않습니다.
6. 제품 경로·프레임워크·빌드 설정을 확인한 뒤 H02에서 Preview를 검증합니다. 이 저장소의 제품 예정 경로는 `apps/web`이므로 실제 앱이 생성된 뒤 Root Directory를 그 경로로 지정합니다. 문서/채널 루트를 앱인 것처럼 배포하지 않습니다.

GitHub 저장소 연결이 새 앱 권한 설치를 요구하면 요청 범위를 확인합니다. 가능한 경우 필요한 저장소만 선택하며, 회사 전체 저장소 접근을 기본값으로 확대하지 않습니다. 정확한 UI와 권한 요청은 로그인 후 실제 화면에서 확인해야 합니다.

## 3. CLI는 별도 인증·연결

브라우저 로그인이 성공해도 이 PC의 CLI 인증이 자동 완료됐다고 가정하지 않습니다. CLI 59.23.2는 설치되어 있고 기존 `whoami` 결과는 login_required였습니다.

```powershell
vercel login
# 브라우저에서 위 이메일 방식으로 올바른 계정인지 확인 후 승인
vercel whoami
# 실제 앱이 만들어진 뒤 제품 폴더에서
vercel link
```

팀 선택은 표시 이름 **52g Studio**, 프로젝트 선택은 **g-23**을 확인합니다. 표시 이름을 team slug라고 추정해 `--scope`에 넣지 않습니다. 로그인 후 실제 팀 식별자를 읽고 필요할 때만 CLI 인자로 사용합니다. `.vercel/project.json`은 로컬 연결 정보이며 GitHub에서 제외합니다.

## 4. 현재 상태와 완료선

현재는 공식 연결 방법을 확인하고 hackathon02 이메일 인증을 요청해 **Check your email / 인증번호 입력 화면까지 확인**했습니다. OTP 인증·워크스페이스 선택·GitHub 연결·CLI 인증·배포 완료는 확인되지 않았습니다. 이 파일은 완료 보고가 아닙니다.

H01 완료선: 올바른 계정, 52g Studio, 기존 g-23, 제품 폴더 링크를 실제 확인한 기록. H02 완료선: 실제 빌드·Preview URL·JS/데이터/영상·두 시나리오·오류 모드·접근 권한 확인. 인증을 완료하지 못해도 사전 준비와 로컬 구현은 계속합니다.

개인 회사 메일의 그룹 연결 해제는 챔피언스리그 종료 후 운영진이 처리하며, 조기 해제를 원하면 운영진에게 요청하라는 안내가 있습니다. 이번 설정 작업에서 그룹 구성이나 다른 팀 권한을 수정하지 않습니다.

### 15:21 KST 재요청 관측
