## 3. 새 메인이 첫 회의 전에 할 수 있는 일

신원/상태 확인, 규정과 설계 읽기, 미확인 항목 정리, 팀원 준비 보고 수집, 킷의 기존 자료 읽기다. 스모크 도구가 만든 미디어를 실제 재생하지 않았다면 P01을 끝냈다고 하지 않는다. B01 사용자 선택 전에 새 UI·대규모 코드 골격을 만들거나 P0 범위를 확정하지 않는다.

팀원 PC가 미등록이면 `whoami` 결과와 읽기 전용 `preflight`까지만 받고, 편지함 조회·처리·제품 구현·저장소 수정은 시작시키지 않는다. 보고서가 도착한 사실과 해당 PC가 실제 준비를 통과한 사실을 구분한다. 메인 PC의 경로·16개 전역 업무 스킬·인증 상태를 다른 PC에도 있다고 가정하지 않는다.

추가로 확인할 운영상의 경계: `.ps1` 실행은 pc1 정책에 막혔으며 정책을 해제하지 않았다. 작업표 검사기는 기록 구조와 해시를 검사하지만 사람 발언·실측의 진실을 판단하지 않는다. 원격 push는 상대 PC 적용 완료가 아니므로 각각의 HEAD와 검사 결과를 받는다. 같은 PC의 Claude와 공유 체크아웃을 쓸 경우 범위를 나눠 명시 경로만 커밋한다.

## 4. 제출·증거에서 놓치지 말 것

세부는 docs/09·10·11이 정본이다. 주요 로그 파일은 실제 Goal 입력과 결과를 포함해야 한다. 제출 업로드 한도(파일1GiB/팀10GiB), 발표자료90MiB/최대5페이지와 HowLong 로컬 분석 한도(100파일·파일256MiB·합계512MiB)를 혼동하지 않는다. 문제/Goal 9/21 17:30, 로그 9/22 10:00은 권장 시각이고 최종 고정은 9/22 12:00이다.

제품 목표 수치는 아직 성과가 아니다: 두 흐름×3회=6/6, 20개 입력 접수 필드 정확도≥90% 목표, 12개 경계에서 근거 없는 확정0, 같은 빌드3회+오프라인1회, 업무시간50%감소 목표. 측정하지 않은 6분/8화면 예시를 Before 실측으로 발표하지 않는다.
