## 1. 실행 전

`GOAL.md`는 최신 요구·방법론·배점·완료선을 담은 전체 **미실행 초안**입니다. 실제 Goal 시작 요청으로 실행한 뒤, 입력 원문 전체를 `.local/submission/goal-used.md`에 보존합니다. DEC-013의 일반 대화 기반 구현 착수는 Goal 실행이 아니며, 과거 작업에 Goal을 소급하지 않습니다. 이후 지시를 수정하면 원문을 덮어써서 과거 입력처럼 만들지 말고 시각·변경 내용·이유를 `.local/submission/goal-changes.md`에 추가합니다. 제출란에는 실제 사용 원문을 넣습니다.

지금까지의 준비·구현·검증도 실제 기록이지만, 아직 실행하지 않은 Goal의 실행 증거로 대신할 수 없습니다. 시작 시 이미 구현된 범위와 남은 검증을 구분하며 현재 진입점은 PROMPT_team.md와 docs/22입니다. [공식 Goal 문서](https://learn.chatgpt.com/docs/long-running-work)는 결과·제약·검증 조건을 명시하고 기존 권한 범위 안에서 이어가는 기능으로 설명합니다.

## 2. 각 PC에서 남길 것

| 시점 | 기록 |
|---|---|
| 시작 | 실제 슬롯·모델·강도·HEAD·Goal 원문·시각 |
| 작업 | task ID, 커밋, 실행 명령, 기대/실측, 실패와 수정 |
| 개입 | 무엇 때문에 어떤 판단을 추가했는지 |
| 완료 | 완료 기준 대조·미달·한계·결과물 경로 |
| 제출 준비 | 주요 세션 선택 이유, 로그 SHA256·크기·중복 여부·비밀정보 점검 |

Codex 세션 JSONL의 실제 위치는 각 PC에서 확인합니다. 일반적인 사용자 폴더 예시는 `%USERPROFILE%\.codex\sessions`이며 설정에 따라 다를 수 있습니다. Claude 로그를 Codex JSONL로 꾸미거나 빈 이벤트를 추가하지 않습니다.

`scripts/log_inventory.py --input <실제JSONL경로>`는 지정한 파일의 크기·해시·형식 검사만 하고 대화 내용을 출력하지 않습니다. `.local/log-manifest.json`에 로컬 결과를 남깁니다. 이 도구가 비밀정보 부재나 공식 심사 점수를 보증하지 않습니다.

## 3. 원본 보존과 제출용 사본

원본 JSONL과 ZIP은 `.local/submission/` 또는 각 PC의 로컬 보관 폴더에 둡니다. GitHub에 올리는 것은 설계·코드·합성 fixture·검증 보고서입니다. 로그에는 사내 경로·대화·도구 출력이 포함될 수 있으므로 공개 링크와 GitHub Release에 올리지 않습니다.

주요 세션은 `/goal` 입력과 결과를 포함한 **JSONL 1개**를 선택합니다. 4대의 다른 로그가 필요하면 나머지를 **ZIP 1개**로 묶습니다. 완전히 같은 파일은 중복 제거하고 포크·리플레이의 부분 겹침은 설명합니다. 총량은 제출 1GiB/파일·10GiB/팀과 HowLong 256MiB/파일·512MiB/전체·100파일을 각각 검사합니다.

로그를 편집해 성공 기록을 만들지 않습니다. 비밀정보를 발견하면 원본은 로컬에 보존하고 제출용 사본의 필요한 부분만 마스킹하며 사유·범위를 기록합니다. 형식과 공식 수용 여부는 제출 화면/운영진 안내로 확인합니다. 준비·검증 이력과 로그가 서로 다른 결론이면 먼저 실제 파일을 다시 확인합니다.

## 4. HowLong과 공식 제출

브라우저 로컬 분석은 선택적으로 수행합니다. 결과의 실행 수는 턴 수, 최장 기록은 완료가 확인된 실행입니다. 분석 JSON/기록판은 보조 증거이며 제출 확인증이 아닙니다. 긴 실행을 만들기 위해 잠들거나 불필요한 반복을 시키지 않습니다.

U00에서 팀명과 대표 권한·필드 제한을 확인합니다. U01은 문제/실제 Goal 초기 제출, L02는 로그 준비, U02는 네 항목 최종 제출과 저장/제출 완료 상태 확인입니다. 인증이 필요한 공식 사이트에 자동으로 로그를 보내지 않습니다. 제출 요청과 실제 대상 파일을 확인한 뒤 수행합니다.
