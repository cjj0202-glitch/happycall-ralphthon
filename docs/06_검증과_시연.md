# 검증·시연·제출 설계

DEC-013~015와 `PROMPT_team.md`·`GOAL.md`에 맞춘 검증 기준입니다. **아래 목표는 실행 결과가 아닙니다.** 실제 실행 현황은 `CURRENT_TODO.md`·`reports/e2e/`에서 확인하며 14개 브라우저 검사나 19개 서버 검사로 20입력·12경계·6회 완주를 대신하지 않습니다. 사람 관찰·업무시간 50% 감소는 미검증으로 유지합니다.

## 1. 평가 데이터와 정답

합성 평가 입력 20개를 먼저 고정합니다. 미도착·오출 각 8개, 빈 발화·모호한 점포·상충 수량·지원하지 않는 문의 각 1개입니다. 근거 누락/충돌/다른 점포/다른 토트/빈 발화/API 실패의 12개 경계 평가를 별도 목록·분모로 기록합니다. 일부 입력을 재사용하더라도 20입력 필드 평가와 12경계 결과를 별도로 판정합니다. fixture를 만들 때 입력 ID와 기대 필드를 `tests/eval/cases.json`에 기록합니다.

UI에 넣은 정답 문장을 그대로 비교하는 테스트만으로 통과시키지 않습니다. 표현을 바꾼 발화, null과 0, 바뀐 상품, 관계없는 영상, 기록이 늦게 들어오는 상태를 검사합니다. 생성기와 같은 로직으로 기대값을 다시 계산하지 않고 사람이 작은 표본의 원본 행과 대조합니다.

| 검사 | 기대 결과 | 증거 |
|---|---|---|
| 정상 접수 | 필수 필드와 근거 발화 ID 일치 | 입력/출력/정답의 필드별 비교 |
| CASE-0001 누락 | 해당 점포의 tms.stops[].actual=null과 미확인 유지, 처리 상태와 물류 사실 구분 | SYN fixture + API + 화면 |
| CASE-0002 오출고 | 주문18EA/수령진술1BOX를 구분, 상담입력1EA의 단위만 정정 | 전사/진술 근거 + AI 출력 + 사람 수정 |
| 다른 점포·토트 | 근거·영상으로 채택하지 않음 | 거절된 ID와 필터 이유 |
| 중복 클릭 | UI 중복 동작을 막는지 확인. 분산 멱등성은 현재 미구현 | 버튼 상태·이력 전후, 미구현 한계 |
| 케이스 전환 | 이전 영상/답변 초기화 | A→B 전환 화면 |
| 404 영상/네트워크 단절 | 대체 모드와 사유 표시, 핵심 경로 유지 | 장애 주입 로그·화면 |
| 재실행 | 초기화 뒤 같은 결과 | 빌드 SHA·초기화 절차·3회 표 |

## 2. 단계별 통과 조건

1. 계약: 필수 타입/참조/null/키 관계를 검사합니다. 정상 입력 통과·불량 입력 실패를 모두 확인합니다.
2. 단위: 근거 선택과 상태 전이 등 실수하면 잘못된 판단을 만드는 로직을 검사합니다.
3. 통합: 각 워커의 실제 산출물을 붙여 두 케이스를 완주합니다. 더미만 통과하면 통합 완료가 아닙니다.
4. 화면: loading/empty/error/stale/ready, 키보드 조작, 영상 재생, 다른 케이스 전환을 직접 확인합니다.
5. 리허설: 동일 빌드 3회 + 오프라인 1회. 건너뜀은 통과 분모에 넣지 않습니다.

운영 도구는 `python -m unittest discover -s tests -v`, `python ops/tasks.py check`로 검증합니다. 제품 명령은 현재 `apps/web/package.json`, `pyproject.toml`, `tests/e2e/`와 docs/20에 맞춥니다. 아직 없는 테스트 명령을 통과했다고 기록하지 않습니다.

## 3. 결선 5분 대본과 3분 축약 연습

공식 기준은 **발표 5분·질의응답 3분·발표자료 최대 5페이지**입니다. 아래 표는 장애/축약 연습용 3분 동선입니다. 실제 결선 대본은 문제 40초 + Goal/위임 50초 + 시연 150초 + 검증/한계 60초로 확장합니다. 질문 3분은 발표 뒤 별도입니다.

| 구간 | 보여줄 것 | 말할 핵심 |
|---|---|---|
| 0:00~0:25 | 문의와 흩어진 기록 | 상담자가 근거 확인에 시간을 쓰는 문제 |
| 0:25~1:10 | 미도착 접수·발화 근거 | 입력을 구조화하되 추정 필드는 비워 둠 |
| 1:10~1:45 | 계획은 있으나 실적 없음 | 기록 누락을 미도착 사실로 바꾸지 않고 사람 확인 |
| 1:45~2:15 | 오출 차이와 연결된 영상 | 키가 일치하는 자료를 한 흐름으로 확인 |
| 2:15~2:40 | 상담 이관→센터 회신→경영주 조회 | 미완료 조치가 있으면 처리 중, 최종 회신·조치 완료 후 종결 |
| 2:40~3:00 | 실측 표·현재 한계 | 합성 평가 성과, 실제 AI/재생 모드, 다음 단계 |

30초 축약: CASE-0001 → 도착 기록 없음 → 근거 클릭 → 확인 요청 초안. 오출과 장애 시연을 넣더라도 실제 Goal·위임·실패 수정 근거를 설명할 시간을 남깁니다.

## 5. 이번 필수 실증과 First Bolt 구분

- 실제 음성: WAV를 입력한 STT와 GPT의 실제 requestId·모드·응답·오류를 보존합니다. 고정 대본이나 replay를 실제 전사 성공으로 세지 않습니다. 주문/수령 수량 혼동처럼 스키마는 통과해도 의미가 틀린 반례를 포함합니다.
- 텍스트: 경영주 제출 원문 보존→STT 없는 실제 정제→상담 검토·이관→센터 회신→경영주 조회를 확인합니다. 신규 INT-* replay 불가(409)를 결함 없이 성공한 AI 분석으로 표시하지 않습니다.
- 보호: 사람 미확인 이관, 점포/대상/부서 누락, 잘못된 역할 회신, 잔여 조치 종결, 이관 후 접수 덮어쓰기, 다른 케이스 근거 채택을 거부하는 양성·음성 사례를 대조합니다. 전체 배송 수량 null과 명시적0은 보존합니다.
- WMS/TMS: WMS30·TMS36 참고의 의미, 피킹/분류·방문순서·계획/실적·기준시각, 합성 영상/지도 설명 표시, 3개 화면 폭·미디어 끝까지 재생을 검증합니다. 실제 회사 시스템 연결을 주장하지 않습니다.
- Bolt: 접수 오류/정제와 근거 사실/미확인 두 실험을 나누고 가설→관찰→수정 하나→동일조건 재시험을 남깁니다. DEC-013에 따라 현재 관찰자는 AI Playwright이며 실제 사람 Silent Test·만족도·업무효과가 아닙니다.
- 공식 점수: 활용20·Goal20·위임30·검증30마다 증거 링크와 충분/보완/미확인을 표시합니다. 목표→실행→실패→수정 커밋→재검증 연결을 남기며 예상 획득 점수를 만들지 않습니다.
- `/goal`: `GOAL.md`는 미실행 초안입니다. 실제로 입력한 원문·HEAD·모델/강도·시각·원본 로그가 확보되어야 실행 증거로 인정합니다. 원본 JSONL/ZIP은 GitHub/Release에 업로드하지 않습니다.
