# 검증·시연·제출 설계

## 1. 평가 데이터와 정답

합성 평가 입력 20개를 먼저 고정합니다. 미도착·오출 각 8개, 빈 발화·모호한 점포·상충 수량·지원하지 않는 문의 각 1개입니다. 그중 12개는 근거 누락/충돌/다른 점포/다른 토트/빈 발화/API 실패의 경계 검사를 겸합니다. fixture를 만들 때 입력 ID와 기대 필드를 `tests/eval/cases.json`에 기록합니다.

UI에 넣은 정답 문장을 그대로 비교하는 테스트만으로 통과시키지 않습니다. 표현을 바꾼 발화, null과 0, 바뀐 상품, 관계없는 영상, 기록이 늦게 들어오는 상태를 검사합니다. 생성기와 같은 로직으로 기대값을 다시 계산하지 않고 사람이 작은 표본의 원본 행과 대조합니다.

| 검사 | 기대 결과 | 증거 |
|---|---|---|
| 정상 접수 | 필수 필드와 근거 발화 ID 일치 | 입력/출력/정답의 필드별 비교 |
| CASE-0001 누락 | needs_review, actual_arrival_time=null 보존 | 원본 행 + bundle + 화면 |
| 오출 | 기대/출고 상품·수량 차이 표시 | 두 원본 행 + 비교 결과 |
| 다른 점포·토트 | 근거·영상으로 채택하지 않음 | 거절된 ID와 필터 이유 |
| 중복 클릭 | 저장 이력 1건 | requestId와 이력 전후 개수 |
| 케이스 전환 | 이전 영상/답변 초기화 | A→B 전환 화면 |
| 404 영상/네트워크 단절 | 대체 모드와 사유 표시, 핵심 경로 유지 | 장애 주입 로그·화면 |
| 재실행 | 초기화 뒤 같은 결과 | 빌드 SHA·초기화 절차·3회 표 |

## 2. 단계별 통과 조건

1. 계약: 필수 타입/참조/null/키 관계를 검사합니다. 정상 입력 통과·불량 입력 실패를 모두 확인합니다.
2. 단위: 근거 선택과 상태 전이 등 실수하면 잘못된 판단을 만드는 로직을 검사합니다.
3. 통합: 각 워커의 실제 산출물을 붙여 두 케이스를 완주합니다. 더미만 통과하면 통합 완료가 아닙니다.
4. 화면: loading/empty/error/stale/ready, 키보드 조작, 영상 재생, 다른 케이스 전환을 직접 확인합니다.
5. 리허설: 동일 빌드 3회 + 오프라인 1회. 건너뜀은 통과 분모에 넣지 않습니다.

운영 도구는 `python -m unittest discover -s tests -v`, `python ops/tasks.py check`로 검증합니다. 제품의 빌드/테스트 명령은 S02 스캐폴딩 시 실제 package/lock에 맞춰 README에 고정합니다. 아직 없는 테스트 명령을 통과했다고 기록하지 않습니다.

## 3. 결선 5분 대본과 3분 축약 연습

공식 기준은 **발표 5분·질의응답 3분·발표자료 최대 5페이지**입니다. 아래 표는 장애/축약 연습용 3분 동선입니다. 실제 결선 대본은 문제 40초 + Goal/위임 50초 + 시연 150초 + 검증/한계 60초로 확장합니다. 질문 3분은 발표 뒤 별도입니다.

| 구간 | 보여줄 것 | 말할 핵심 |
|---|---|---|
| 0:00~0:25 | 문의와 흩어진 기록 | 상담자가 근거 확인에 시간을 쓰는 문제 |
| 0:25~1:10 | 미도착 접수·발화 근거 | 입력을 구조화하되 추정 필드는 비워 둠 |
| 1:10~1:45 | 계획은 있으나 실적 없음 | 기록 누락을 미도착 사실로 바꾸지 않고 사람 확인 |
| 1:45~2:15 | 오출 차이와 연결된 영상 | 키가 일치하는 자료를 한 흐름으로 확인 |
| 2:15~2:40 | 답변·이관·이력 | 담당자가 검토하고 조치를 확정 |
| 2:40~3:00 | 실측 표·현재 한계 | 합성 평가 성과, 실제 AI/재생 모드, 다음 단계 |

30초 축약: CASE-0001 → 도착 기록 없음 → 근거 클릭 → 확인 요청 초안. 오출과 장애 시연을 넣더라도 실제 Goal·위임·실패 수정 근거를 설명할 시간을 남깁니다.

## 4. 제출 묶음

- `reports/release-check.md`: commit/tag·실행 URL·실행 명령·알려진 한계·mode.
- `reports/evaluation.md`: 20입력 필드 비교, 12경계 결과, 6회 흐름 결과, 실패/건너뜀.
- `reports/benchmark.md`: Before/After 원시 측정, 표본 수, PC/빌드/시각, 계산식.
- `demo/script.md`: 실제 발표 시간에 맞춘 대본·버튼 순서·백업 전환.
- Release 자산: 합성 음성/영상, 화면 녹화, 필요 시 실행 묶음. 각 파일 SHA256과 다운로드 방법.
- README: 다른 노트북에서 재현하는 순서. private 저장소 접근권한은 제출 규정과 대조.
- 실제 Goal 원문·주요 Codex JSONL 1개·선택적 나머지 로그 ZIP 1개는 별도 제출 경로로 준비합니다. JSONL은 GitHub에 올리지 않습니다.
- 공식 제출은 대표 계정에서 네 항목을 확인하고 **9/22 12:00 이전** 완료해야 합니다. U02에 저장/제출 완료 상태·시각을 기록합니다.

배포 로그가 성공이어도 브라우저에서 HTML·JS·데이터·영상이 실제로 열리는지 확인합니다. HTTP 200 하나로 시연 성공을 대신하지 않습니다.
