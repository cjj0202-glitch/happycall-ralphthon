# 다른 노트북에서 미리 준비하기

최초 준비는 각 노트북에서 합니다. 이 PC에서 다른 3대의 설치·로그인을 완료했다고 대신 판정하지 않습니다. ChatGPT 계정이 서로 달라도 같은 GitHub 저장소를 읽을 권한이 있으면 이 자료와 편지함을 공유할 수 있습니다. 계정 간 대화 기록이 자동으로 합쳐지는 방식은 아닙니다.

## 1. 계정과 다운로드

팀원은 본인 GitHub 계정으로 두 private 저장소 초대를 수락합니다. 초대할 계정명을 아직 받지 못했으므로 이번 작업에서 임의 초대하지 않았습니다.

```powershell
# Git과 GitHub CLI가 없을 때만 설치
winget install --id Git.Git --exact
winget install --id GitHub.cli --exact
# PowerShell을 다시 열고 본인 계정으로 인증
gh auth login
gh auth status
# 본인 PC의 원하는 개발 폴더에서, 두 폴더가 나란히 생기게 실행
gh repo clone cjj0202-glitch/happycall-ralphthon
gh repo clone cjj0202-glitch/hackathon-ai-kit
cd happycall-ralphthon
```

이미 clone한 경우 새로 받지 않습니다. `git status --short`로 변경을 확인하고, 깨끗한 작업 폴더에서 `git pull --ff-only` 합니다. 충돌·갈림이 있으면 현재 변경을 보존한 상태로 메인에게 알립니다.

## 2. 설치와 점검

```powershell
# 기본 동작은 읽기 전용 점검
powershell -NoProfile -File scripts/prepare_windows.ps1
# 필요한 기본 도구가 없으면 설치 옵션
powershell -NoProfile -File scripts/prepare_windows.ps1 -InstallTools
# Codex 데스크톱만 쓸 경우 CLI는 선택. Vercel도 배포 담당 외에는 선택
powershell -NoProfile -File scripts/prepare_windows.ps1 -InstallAgentCli -InstallVercel
```

새 설치 직후에는 PATH 반영을 위해 터미널을 다시 엽니다. 실행 정책으로 파일이 막히면 조직의 허용 절차를 따르거나 문서에 적힌 개별 명령을 실행합니다. 임의로 보안 정책을 해제하지 않습니다.

```powershell
python scripts/preflight.py
python channel/whoami.py --hostname
python ops/tasks.py status
python -m unittest discover -s tests -v
```

`.local/preflight.json`은 로컬에 생성되며 git에서 제외합니다. 토큰·비밀번호는 수집하지 않습니다. 신원이 미등록이면 PENDING이 정상이며 남의 슬롯을 환경변수로 지정하지 않습니다. hostname·GitHub 계정·희망 역할을 메인에게 전달하고 등록된 `pcs.json`을 받은 후 다시 검사합니다.

메인이 요청하면 보고서를 `reports/readiness/pc2.json`처럼 **자기 슬롯 이름**으로 복사한 뒤 해당 branch에 올립니다. pc1은 세 PC의 각각 다른 hostname·등록 계정·HEAD·시각을 확인합니다. IP는 점검 결과에 수집하지 않습니다.

## 4. Vercel은 로그인 가능할 때

현재 확인: 이 PC CLI 설치됨, `whoami`는 login_required. 사용자 제공 메일은 `hackathon02-1948`의 **g-23 프로젝트 Administrator** 안내입니다. team slug와 project ID는 메일만으로 알 수 없습니다.

```powershell
vercel login
vercel whoami
vercel teams ls
# 제품 앱 폴더에서 실행. 기존 g-23을 선택하고 정확한 팀을 확인
vercel link
vercel project inspect g-23
```

`vercel link` 질문에서 올바른 팀과 **기존 프로젝트 g-23**을 선택합니다. 목록에 없으면 권한을 받은 계정으로 로그인했는지 확인하고 중단합니다. 새 프로젝트를 임의 생성하지 않습니다. 제품 코드가 아직 없으므로 지금 운영/문서 저장소 루트를 배포 폴더로 연결하지 않습니다.

연결은 `.vercel/project.json`에 기록됩니다(로컬 전용). `vercel`은 실제 Preview 배포 명령이므로 사전 점검 단계에서 실행하지 않습니다. 로그인·프로젝트·Root Directory·빌드 명령·합성 자산 공개 범위를 확인한 다음 H02에서 배포를 검증합니다. [공식 CLI link 문서](https://vercel.com/docs/cli/link).
