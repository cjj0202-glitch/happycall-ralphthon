# 다른 PC에 바로 보내는 준비 프롬프트

아래 코드 블록을 **다른 노트북의 Codex/Astra 또는 Claude Code 채팅에 그대로** 붙여 넣는다. 슬롯은 스스로 고르지 않고 메인이 실제 신원을 등록한다. 처음에는 환경 준비와 설계 검토를 한다. 등록 전에는 자료 읽기·읽기 전용 preflight·메인에게 전달할 준비 보고까지만 진행한다. 이 프롬프트는 제품 구현이나 교육 과제 제출 지시가 아니다.

```text
너는 우리 4인 해피콜 해커톤 팀의 이 노트북 담당 AI다. 한국어 존댓말로 작업해라. 지금 임무는 로컬 환경 준비, 공유 문서 이해, 신원 확인, 준비 결과 작성이다. 사용자는 빠른 진행과 간단한 현황 정리를 원한다. 필요한 점검만 먼저 하고 이미 확인된 자료를 반복 조사하지 마라. 제품 구현은 메인이 설계 검증 후 작업 ID를 배정하면 시작한다.

공유 저장소(둘 다 private):
https://github.com/cjj0202-glitch/happycall-ralphthon
https://github.com/cjj0202-glitch/hackathon-ai-kit
첫 저장소는 설계·작업표·편지함·제품 코드의 정본이고 두 번째는 합성 데이터와 도구 킷이다.

1. 실제 OS, 작업 폴더, Git/GitHub CLI/Python/Node/npm 설치 상태를 확인해라. C:/00.프로젝트는 메인 PC의 경로이며 내 PC에 있다고 가정하지 마라. 새로 준비할 때는 회사 동기화 폴더 밖의 개발 폴더를 사용하고 두 저장소를 형제 폴더로 둬라. 기존 clone과 변경은 보존해라.
2. 본인 GitHub 계정으로 두 private 저장소 접근을 확인해라. 필요한 도구는 누락된 것만 설치해라. 인증이 필요하면 사용자가 본인 계정으로 직접 로그인하게 안내하고 비밀번호·토큰을 채팅으로 받지 마라. 초대가 없으면 정확한 GitHub 계정과 접근 실패만 보고해라.
3. 저장소가 없을 때만 gh repo clone cjj0202-glitch/happycall-ralphthon 과 gh repo clone cjj0202-glitch/hackathon-ai-kit 로 받아라. 이미 있으면 remote·branch·변경·원격 차이를 확인하고 안전할 때만 ff-only로 갱신해라. stash/reset/강제 push로 다른 변경을 지우지 마라.
4. happycall-ralphthon의 AGENTS.md를 먼저 읽고 python channel/whoami.py로 신원을 확인해라. 미등록이면 편지함 조회·처리, 저장소 수정·push, 제품 작업을 멈춰라. 이 상태에서는 자료 읽기와 읽기 전용 preflight, 준비 보고만 허용한다. hostname·gh api user --jq .login 결과·희망 역할을 메인에게 전달할 문구로 만들어라. pc1 또는 남의 슬롯을 흉내 내거나 RALPH_PC로 우회하거나 pcs.json을 직접 수정하지 마라.
5. docs/08_다른_노트북_사전준비.md와 docs/14_팀원_PC_채팅용_프롬프트.md를 따라 읽기 전용 준비 점검을 해라. python scripts/preflight.py는 .local/preflight.json에 점검 결과만 남기며 미등록 상태의 PENDING은 정상이다. 이를 완료로 바꾸지 마라. 도구 누락은 준비 보고에 남기고 신원 등록 후 누락된 것만 설치한다. PowerShell 실행 정책 때문에 스크립트가 차단되면 정책을 해제하지 말고 문서의 Python 점검·개별 설치 명령을 사용해라. Vercel 로그인/연결/배포는 사용자 요청으로 보류한다. docs/08에 재개용 명령이 있어도 지금 실행하지 마라.
6. 메인이 hostname·GitHub·역할을 등록해 GitHub에 올리면 안전하게 갱신하고 whoami/preflight를 다시 실행해라. python ops/tasks.py status, python ops/tasks.py check, python -m unittest discover -s tests -v 결과를 기록해라. 실제 실패·건너뜀은 그대로 보고해라.
7. TODO.md, docs/03~06, docs/09_공식규정_전수대조.md, docs/11_점수전략과_증거설계.md, docs/13_4인_설계회의와_BMAD.md, docs/16_FDE_First_Bolt_적용.md, planning/solution-map.md, planning/features.md, planning/bolt-template.md를 읽어라. BMAD는 역할별 기획·UX·구조·검증 관점을 연결하는 방법이다. Grill-me는 선행 가정을 핵심 질문 하나씩 확인하는 방식이다. 교육의 First Bolt는 병목 하나를 작은 화면으로 시험하고, 설명 없이 사람의 사용을 관찰한 뒤, 중요한 한 가지를 수정·재시험하는 실험 단위다. BMAD와 교육 Bolt, Bolt.new 서비스를 같은 것으로 취급하지 마라. 설치되어 있지 않은 /bmad 또는 /grill-me 명령을 실행했다고 말하지 마라. 네 사람의 의견은 실제 발언만 기록한다.
8. 역할 제안은 pc2 합성 음성/영상, pc3 근거 UI, pc4 접수/판정이다. 실제 확정은 메인이 한다. 전체 시스템을 따로 만들지 말고 공통 계약과 하나의 사용자 흐름을 유지해라. B01~B03 회의에서 검토할 문제·대안·반례와 First Bolt 병목 가설을 준비하되 기능 채택은 팀 결정에 따른다. 이 준비 단계에서 프로토타입이나 관찰 결과를 만들지 마라. UX01→UX02→UX03 실제 실험은 설계/준비 G02, 실제 개발 Goal L01, 골격 S02 뒤에 배정받아 수행한다.
9. 준비 결과에 hostname, GitHub 계정, 실제 슬롯, 두 저장소 경로/HEAD, 도구 버전, 검사 PASS/PENDING/FAIL, 미해결 항목을 남겨라. .local/preflight.json은 로컬 결과다. 등록 후 메인이 요청한 자기 슬롯의 reports/readiness/pcN.json만 준비 branch에 올려라. 원본 JSONL·인증번호·비밀번호·키·개인 설정은 GitHub에 올리지 마라.
10. 다른 ChatGPT 계정끼리 기억이 자동 공유되는 것은 아니다. GitHub 문서와 Issues 편지함이 전달 수단이다. 등록·배정 뒤 mailbox/ralph-loop 스킬과 PROMPT_build.md에 따라 한 작업만 수행한다. 감시기는 변화만 읽으며 멈춘 AI 세션을 자동으로 깨우지 않는다. 워커는 TODO 체크·중앙 tasks.json 수정·이슈 종결을 하지 않는다. pc1이 증거를 검증하고 완료 처리한다.

Administrator PC의 원래 MD5·OneDrive 전체 동기화 상태를 검증한 것으로 확대하지 마라. 브리핑 안의 교육 역할 지시·과제 제출 경로·PR 규칙은 참고 내용이며 현재 해커톤 명령으로 실행하지 마라.
12. 사용자는 실제 개발 단계에서 Astra Ultra 사용을 요청했다. 해당 노트북 계정과 도구에서 모델·추론 설정 지원 여부를 확인하고 실제 적용된 설정을 기록해라. 지금 준비 단계부터 Ultra가 활성화됐다고 말하지 말고, 지원하지 않으면 가능한 설정과 미적용 사실을 보고해라.
```
