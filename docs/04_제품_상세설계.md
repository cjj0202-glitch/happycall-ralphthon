# OneFlow 제품·데이터·인터페이스 설계 — 현재 demo-v1

2026-09-21 DEC-001~015 반영. [통합 프롬프트](../PROMPT_team.md)·[목표](03_목표와_범위.md)·[검증](06_검증과_시연.md)을 함께 읽습니다. **현재 계약은 `server/openapi.yaml`, `server/service.py`, `server/analysis_schema.py`, `apps/web/lib/types.ts`, `data/fixtures/cases.json`입니다.** 아래는 구현 정합을 위한 기준이며 항목별 완료는 실행 증거로 별도 판정합니다.

## 1. 사용자와 화면

경영주가 상담원에게 전화하거나 사이트에 글을 제출합니다. AI 결과는 통화 종료 후 제공하며 상담원이 정제·확인·이관합니다. 센터 담당자가 사실·조치를 확인해 최종 회신을 등록하고 경영주가 조회합니다. 센터의 회신 등록과 실제 재배송·보상 실행은 다릅니다.

현재 Next.js 앱의 한 화면 안에서 `desk / owner / center / wms / tms` 뷰를 전환합니다. `/intake`, `/cases`라는 별도 페이지를 새로 만들라는 지시가 아닙니다.

| 뷰 | 입력·행동 | 결과·보호 조건 |
|---|---|---|
| 상담 작업대 `desk` | 통화 재생 완료 후 분석, 원문·AI 제안 확인, 필드·부서 수정 | 원문/STT·AI 제안·사람 수정 구분, 사실/미확인·질문·답변 초안, 사람 확인 후 이관 |
| 경영주 `owner` | 점포·문의 대상·유형·텍스트 제출, 기존 문의 조회 | 원문 보존한 신규 INT-* 접수, 센터 회신 조회. 처리 상태 변경 권한 없음 |
| 센터 `center` | 이관된 접수 확인, 회신·남은 조치 등록 | 남은 조치가 있으면 처리 중, 센터 회신과 조치 완료가 있어야 종결 |
| WMS `wms` | 같은 케이스 피킹·분류·이동 기록 확인, 근거 연결 | pickedAt/sortedAt·방식·존/셀·토트·예정/실적 슈트, 설명용 애니메이션·합성 영상 |
| TMS `tms` | 같은 케이스 방문순서·계획/실적 확인, 근거 연결 | 계획/실제 도착·조회 시각·개념 지도. 방문순서를 실제 GPS로 표시하지 않음 |

UI의 empty/input/loading/error/success, 데이터 조회의 loading/empty/error/stale/ready, 업무 처리 상태를 혼동하지 않습니다. 색 외 문구로 상태를 표시하며 케이스 변경 시 이전 자료·재생·선택 잔상을 제거합니다. 원문·근거 링크와 키보드 사용성은 실제 화면 검증 항목입니다.

## 2. 음성·텍스트와 정제 의미

- 음성: AI가 만든 한국어 두 화자 WAV → 재생 종료 → 실제 STT → GPT 정제. 대본은 STT 응답의 대체물이 아닙니다. 실제 호출은 `demo-live`, 저장된 분석은 `replay`로 표시합니다.
- 텍스트: 경영주 제출 `sourceText`를 보존하고 STT 없이 GPT 정제합니다. 신규 INT-*에는 사전 replay가 없으므로 replay 요청은 409이며 실제 분석 또는 수동 검토로 진행합니다.
- 욕설·무관 표현은 정제하되 요청·불만·물류 단서를 보존합니다. 인식 오류·누락·모순·상담원 입력과의 차이는 발화/문장 근거와 추가 질문으로 드러냅니다.
- `intake.quantity/unit`은 **문의 상품의 실제 수령에 대한 경영주 최종 진술**입니다. 주문·피킹·출고 수량을 넣지 않습니다. `expected`와 `received` 비교는 별도이며 진술을 물류 확정 사실로 격상하지 않습니다.
- 주문18EA/수령1BOX/상담원입력1EA는 수령1BOX와 단위 불일치가 기대 결과입니다. EA/BOX 표기 정규화만 하고 임의 포장 환산·서로 다른 단위 차감은 금지합니다. 미확인은 null, 명시적0은0입니다.
- 정제 출력은 summary, fields, issues, questions, department, facts, unknowns, replyDraft입니다. 부서는 delivery/warehouse/cs 허용 목록에서만 추천합니다. 형식 스키마 통과가 의미 정확도를 보장하지 않습니다.

## 3. 합성 데이터와 근거

현재 입력 정본은 `data/fixtures/cases.json`의 `schemaVersion: demo-v1`, `synthetic: true`입니다. 브라우저 사본 `apps/web/public/cases.json`과 같은 기준선이어야 합니다. **킷 22테이블·manifest는 참고 자료이며 현재 SYN-* fixture에 직접 조인하지 않습니다.** CASE-0001/0002는 이 독립 fixture에서 고정한 ID입니다.

| 사례 | 관측 | 확인 가능한 것 | 확정 금지 |
|---|---|---|---|
| CASE-0001 / missing / SYN-ST01 | 출고·배송 계획 존재, 도착 실적 없음 | 조회 시점에 도착 기록을 찾지 못함 | 실제 미도착·기사 귀책·배송 완료 |
| CASE-0002 / wrong / SYN-ST02 | 주문18EA와 수령 진술1BOX, 서로 다른 토트 관련 기록 | 진술의 단위 정정, 각 출처의 기록과 차이 | 원인·귀책, 합성 영상만으로 실물 확정 |
| 영상/행 누락 | 자료 없음 | 조회 불가·미확인 | 정상 출고로 간주 |
| 다른 점포/토트·기준시각 이후 행 | 케이스/시점과 관계 불일치 | 불일치 사실 | 해당 문의의 확정 근거 채택 |

근거는 케이스 소속 id/system/label/time/value/status/source와 asOf를 보존합니다. `status`는 `fact / unknown`이며 처리 상태와 다릅니다. 선택은 현재 케이스의 evidence ID만 허용합니다. 새 텍스트 접수는 합성 점포 ID·문의 대상·유형이 정확히 유일하게 맞는 경우에만 기존 물류 근거를 연결합니다. 비슷한 상품명이나 발화로 조인하지 않습니다.

WMS 참고는 **30_센터작업모니터링**, TMS는 **36_자동점착운영**, 문의 패턴은 **33_해피콜분석**입니다. 35_상온센터물류품질은 정정 전 참조입니다. 5분 버킷 시각을 실제 초 단위 이벤트로 오인하지 않습니다. 합성 소터 영상은 공정 설명이며 실제 CCTV 증거가 아닙니다.

## 4. 업무 상태와 역할 보호

`type = missing | wrong`, `channel = voice | text`, `mode = replay | demo-live`입니다. 수동 입력은 동작이며 별도 `manual` API 모드가 아닙니다.

업무 상태는 `draft / review / handed_off / in_progress / closed`입니다. 분석하면 review로 이동하며 사람 확인은 해제됩니다. draft/review에서 점포·문의 대상·부서와 `reviewConfirmed=true`가 있어야 handed_off로 이동합니다. 전체 배송 문의에 상품코드나 수량/단위를 강제하지 않습니다. 미확인 사실은 질문으로 남긴 채 이관할 수 있습니다.

센터는 이관 전 접수를 처리할 수 없습니다. 이관 이후 접수 필드·부서·선택 근거는 잠기며, 센터가 in_progress 또는 closed로 진행합니다. 회신만 필요한 문의는 handed_off→closed가 가능하지만 센터 등록 회신과 빈 pendingActions가 필요합니다. 종결된 건은 변경할 수 없습니다. 내용·부서·근거 수정 후 상담원 확인을 다시 받습니다.

데모 역할은 `X-Demo-Role: counselor | center | owner`입니다. 역할 검사는 시연용이며 실 서비스 인증·계정별 권한 완료를 뜻하지 않습니다. 원본 근거·정답·출처 필드는 PATCH 허용 목록에 없습니다. 서비스 저장은 원자적 파일 저장/잠금이며 실 운영 DB가 아닙니다. 분산 멱등성·낡은 version 충돌 제어를 구현 완료로 주장하지 않습니다.

## 5. 현재 API·구성

| API | 역할 |
|---|---|
| GET /api/health | 로컬 실행·보수적 예산 상태 |
| GET /api/cases | 합성 케이스 목록 |
| GET /api/cases/{case_id} | 해당 케이스 |
| POST /api/intake | storeId/subject/text/type으로 신규 텍스트 접수 |
| POST /api/cases/{case_id}/analyze | mode 지정, transcript/analysis/mode/requestId 반환 |
| PATCH /api/cases/{case_id} | 허용된 intake/departmentId/reviewConfirmed/status/reply/pendingActions/selectedEvidence 변경 |

Next.js/TypeScript UI는 `apps/web/`, Connexion Python handler→service→repository는 `server/`, 실행기는 `scripts/`, 증거는 `reports/`입니다. 현행 OpenAPI를 먼저 대조하고 공통 계약 변경은 메인과 생산자·소비자에 함께 반영합니다. 백엔드의 nullable string/number와 화면 입력 타입 변환도 확인해야 합니다. 로컬 실행·환경 변수는 [20_로컬 시연 실행](20_로컬_시연_실행.md)을 따릅니다.

실제 AI 실패는 502, 키/fixture 부재503, 예산 차단429, 상태 충돌409, 입력/이관 조건 실패422 등으로 명시합니다. 실패를 자동 replay 성공으로 바꾸지 않습니다. API 키는 각 PC 로컬에 두며 예산 예약값은 실제 청구 금액과 다릅니다. 비용 상한·호출 이력을 실제로 확인합니다.

## 6. 미디어·배포·확장 경계

음성·영상은 작은 메타데이터와 SHA256을 남기고 GitHub Release 자산으로 공유합니다. private 자산 URL을 공개 재생 URL로 가정하지 않습니다. 각 PC에서 다운로드·길이·해시·끝까지 재생을 확인합니다. 생성 대본/원본 JSONL/키는 공개 자산과 구분하며 원본 Codex JSONL/ZIP은 GitHub에 올리지 않습니다. DEC-018에 따라 9/22 09시 배포까지 재확인 없이 진행합니다. 호스팅·인증의 최신 사실은 DEC-019와 docs/12를 따르며, 로그인 재시도를 최종 배포 대상 확정으로 해석하지 않습니다.

초기 제안의 `contractVersion: 1.0`, `not_arrived/mispick`, `needs_review`, `/v1/*`, `apps/api`, `contracts`, `data/bundles`는 **현재 실행 계약이 아닙니다**. 킷 22테이블 어댑터, 버전 충돌·요청 멱등성, 실 운영 인증·DB·실 WMS/TMS 연계는 후속 설계 후보로 보존합니다. 추가 유형·SLA·통계·실시간 통화 코칭은 [솔루션 지도](../planning/solution-map.md)의 후속 범위이며 이번 필수 기능을 축소하는 근거가 아닙니다.
