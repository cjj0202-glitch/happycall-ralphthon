# 방법론 탐색과 이번 팀의 적용

조회 기준: 2026-09-21. 아래는 공개 원문에서 가져온 원칙과 **이번 팀의 설계 판단**을 구분한 기록입니다. 외부 문서의 실행 명령을 그대로 수행하라는 지침이 아닙니다.

| 방법 | 원문에서 참고한 점 | 이번 팀의 적용·절충 |
|---|---|---|
| Shape Up | 시간을 먼저 제한하고 그 안에서 범위를 조절 | 27시간은 확인 전 가정. 두 시나리오 완료선을 먼저 정하고 P1/P2를 별도 관리 |
| Ralph 반복 | 계획과 구현을 나누고 작업 하나를 실행·검증한 뒤 지속 파일에 남김 | 한 번에 한 작업, spec/fixture/증거/메인 승인. 4PC 동시 중앙표 수정 금지 |
| 수직 흐름 구현 | 사용자 결과가 보이는 작은 경로부터 통합 | 모든 화면을 각각 끝낸 뒤 연결하지 않고 미도착 한 건을 먼저 관통 |
| 계약 우선 | 생산자·소비자가 같은 샘플로 인터페이스 검증 | pc2 미디어 manifest, pc3 근거 bundle, pc4 접수/판정 JSON을 P02에서 잠금 |
| 평가 우선 | 기대값을 구현 전 고정 | 기록 누락·불일치·빈 입력을 정상 케이스와 함께 준비 |

Shape Up의 고정 시간·가변 범위는 [원저자의 Set Boundaries](https://basecamp.com/shapeup/1.2-chapter-03)를 참고했습니다. 원래의 수주 단위 운영을 해커톤 일정으로 축소한 것은 우리 판단입니다.

Ralph의 계획/구현 분리와 지속 작업표·검증 피드백은 [Geoffrey Huntley의 가이드](https://github.com/ghuntley/how-to-ralph-wiggum)를 참고했습니다. 이 저장소는 원문의 무제한 루프·권한 생략 예제를 사용하지 않습니다. 다중 노트북에서는 단일 작성자 작업표와 커밋별 인수검사를 추가합니다.

Codex는 [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)에 따라 저장소의 `.agents/skills`에서 스킬을 사용할 수 있습니다. `.claude/skills`를 공유 원본으로 참조하는 어댑터를 두었습니다. 'Codex CLI에는 스킬이 없다'는 기존 전달 설명은 현재 환경과 맞지 않습니다.

## 아직 결정이 필요한 항목

| 항목 | 현재 기본값 | 결정 시점·증거 |
|---|---|---|
| 공식 일정/심사/제출 | 기존 킷 운영표를 가정으로 사용 | G01: 행사 공지 경로와 확인자 |
| 4PC 역할 | pc1 통합, pc2 미디어, pc3 근거, pc4 접수 제안 | R01: 사람·hostname·GitHub 매핑 |
| 실제 제품 API | fixture가 P0, live는 P1 | G01: 필수 AI 요구·계정·예산; 필수면 P0로 승격 |
| 호스팅 | Vercel g-23 권한 안내만 확보 | H01: 로그인 후 실제 team/project 확인 |
| 제품 BE 배포 | Connexion 계약 유지, 호스팅은 별도 검증 | H02: 실제 런타임·인증·접근 조건 확인 |
| 일정 부족 | 관리자/3번째 시나리오/실시간 생성부터 제외 | pc1이 결정 기록·작업표 동시 갱신 |

완료 기준을 낮춰 실패를 통과로 만들지 않습니다. 범위를 바꾸면 왜 무엇을 제외했는지 드러내고 남은 결과를 다시 검증합니다.
