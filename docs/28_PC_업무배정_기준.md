# 4PC 업무 배정·검증·인수 기준

2026-09-21 사용자 요청: 다른 PC가 공동 기억 없이도 효과적·효율적으로 작업하도록 배정 기준을 통일합니다. 기존 docs24의 소유권·docs25의 검증 단계·mailbox의 6칸을 유지하며 이 문서를 모든 후속 배정의 정본으로 사용합니다.

## 무엇을 누구에게 맡기는가

**사용자가 얻는 결과 하나를 카드 하나로 배정합니다.** “고급스럽게 개선”처럼 종료 조건이 없는 지시를 보내지 않습니다. 구현 방법은 담당자가 선택하되 계약·완료 조건·금지할 오판은 메인이 고정합니다.

| 판단 순서 | 기준 |
|---|---|
| 1. 우선순위 | P0: 다른 사건 혼입·오확인·데이터 손실·권한/비용 문제 → P1: 핵심 흐름 중단/품질 미달 → P2: 시각·속도 고도화 |
| 2. 의존성 | 필요한 입력/계약이 준비된 작업부터. 의존 입력이 없으면 독립 설계·반례 준비까지만 배정 |
| 3. 담당 | 기존 소유자·도구 실행 가능 여부·현재 부하로 선택. 같은 PC의 보조 세션을 다른 PC로 세지 않음 |
| 4. 크기 | 20~40분 안에 검토 가능한 첫 결과, 이후 증거로 확장. 긴 영상은 대표3프레임/짧은 동작을 먼저 검수 |
| 5. 병렬성 | PC당 구현 카드1개. 같은 PC 내부 보조 작업은 서로 다른 파일 또는 읽기 전용 검토로만 분리 |
| 6. 재사용 | 승인 fixture·자산·검사·원장 재사용. 전체 재생성/전체 테스트 반복은 변경 영향이나 실패가 있을 때만 |

pc1은 공통 계약/API/부모 화면/fixture/manifest/중앙 작업표/통합·배포, pc2는 통화, pc3는 WMS·CCTV, pc4는 TMS·교차검증을 소유합니다. 공용 파일 수정이 필요하면 제안 diff·필요 props를 주고 pc1이 반영합니다. 타인 코드를 되돌려 성공시키지 않습니다.

## 배정 전 필수 입력

메인은 다음이 모두 들어간 카드만 발송합니다. 조사 가능한 사실을 사용자에게 다시 질문하지 않습니다.

1. **작업 ID·이슈·실제 PC/계정·기준 SHA·기존 결과 SHA**. 다른 PC의 경로를 추정하지 않습니다.
2. **사용자 결과·이번 범위·제외 범위·우선순위**. 성공하는 구체 행동을 한 문장으로 씁니다.
3. **소유 파일·읽기 전용 의존 파일·인터페이스**. case/event/time/source/null 규칙과 필요한 입력 위치를 적습니다.
4. **상세설계와 첫 결과**. BMAD 네 관점, 작은 Bolt의 가설/관측/핵심 수정, 제출할 중간 결과를 정합니다.
5. **완료 조건과 검증 입력·기대값**. 정상·반례·경계·실패/복구, 실행환경·버전·결과물 해시를 명시합니다.
6. **시점·자원·중단 조건·인계 형식**. 미확인/미실행을 PASS로 바꾸지 않고 실패 증거를 보존합니다.

## 복사해 채우는 6칸 카드

```text
결론: [작업ID / P0·P1·P2] <실제 PC·계정>이 <사용자 결과 하나>를 담당합니다.

왜 지금:
- 사용자 요구/현재 문제, 기준 main SHA, 수신한 기존 결과 SHA
- 정본 문서 경로, 실제 저장소 절대경로, 의존 입력 준비 여부

해줘야 할 일:
- 이번 결과와 범위 / 이번에 바꾸지 않을 범위
- 소유 파일 / 읽기 전용 파일 / props·데이터·출처·시각 계약
- 상세설계 → 첫 작은 결과 → 구현·실행 → 반례 → 수정·재검

실행 명령:
- 실제 본인 저장소로 이동, whoami·GitHub·HEAD·변경 확인
- fetch 후 정본/계약 diff 검토, 본인 기존 branch 재사용
- 해당 작업 재현 명령과 입력, 명시 경로 커밋·push·원격 SHA 대조

검증 방법 + 기대값:
- 정상 / 잘못된 입력 / 경계 / 오류·복구 각각의 기대 결과
- 첫 결과 목표시각과 최종 결과 목표시각(완료 확약이 아님)
- 실행한 분모·PASS/FAIL/SKIP·환경·콘솔·자산/빌드 SHA
- 미실행 범위, 제품 버전이 바뀌면 다시 확인할 항목

중단 조건 + 인계:
- 소유 충돌/권한 거부/원천·키 공개/예산 초과는 해당 경로 중단
- 30분 진전 없음 또는 같은 실패3회면 원인·대안·독립 진행항목 회신
- 같은 이슈에 결과 SHA/명시 파일/사용자 결과/명령/기대·실측/
  발견 결함/수정/동일조건 재검/한계/메인 연결점을 남김
```

## 검증과 메인 인수

**배정 발송 → 담당 ACK → 설계/첫 결과 → 구현 결과 제출 → 독립 검증 → 통합 → 같은 빌드 회귀 → 인수**를 구분합니다. 정상 샘플이 실제로 통과하는 양성 대조군과 잘못된 샘플이 차단되는 반례를 함께 봅니다. 안전 게이트를 새로 만들면 허용/차단을 뒤집는 변이 검사도 수행합니다.

- 동작 증거: 실제 컴포넌트·HTTP·브라우저 등 무엇을 실행했는지 적습니다. 정적 검색/SSR을 사용자 클릭·저장·영상 재생으로 세지 않습니다.
- UI/미디어: 데스크톱/태블릿/모바일, 키보드·중복 클릭·느린 응답·오류 복구, 실제 재생/탐색/음량을 해당 변경에 맞게 검사합니다. 스크린샷·프로세스 시작만으로 완료하지 않습니다.
- 전체 흐름: 동일 빌드·자산에서 두 사례 각각3회. “전체 음성 청취” 검사는 1배속 처음부터 실제 끝까지이며 끝 seek 후 ended는 별도 검사입니다. 과거 셸의6회 결과를 신규 모듈에 소급하지 않습니다.
- 독립 검토: 구현자의 자기 검사와 다른 입력·경로로 재현합니다. 지적마다 명령·실제 출력이 필요하며 재현되지 않은 추측으로 불필요한 수정을 시키지 않습니다.
- P0/P1이 남으면 해당 기능은 인수하지 않습니다. 핵심 흐름을 막지 않는 P2는 명시한 잔여 항목으로 보존할 수 있습니다. 전체 품질 기준을 낮추거나 실패를 삭제하지 않습니다.

수정 요청에는 **현상·영향·재현 입력·기대/실측·관련 SHA/파일·소유자·재시험 기준**을 넣습니다. 같은 문제를 여러 PC에 동시에 고치게 하지 않습니다. 메인이 직접 수정할 때는 소유권 변경/수정 범위를 같은 이슈에 남깁니다.

## 비용·통신·점수 증거

모델 호출은 메인의 기존 예산 원장과 명시 실행을 따릅니다. PC별 원장·자동 유료 재시도·임의 구독을 만들지 않습니다. 대용량 합성 영상/blend는 후보 Release+SHA, 원천 도면·업무행·키·원본 로그는 로컬에 둡니다.

새 배정은 실제 업무가 있을 때만 보냅니다. 기존 N02/N03/N04의 후속은 #8/#9/#10 댓글을 사용하고, ACK가 없다는 이유로 중복 이슈를 만들지 않습니다. watcher는 변경 감지, 자동 재개·착수는 별도 증거입니다. 무변화 상태 메시지를 반복하지 않습니다.

공식 점수는 docs09~11의 활용20·Goal20·결과 위임30·검증30입니다. 카드의 **완료 기준 → 실행 결과 → 실패 → 수정 → 같은 조건 재검**을 연결해 증거를 남깁니다. 이 절차를 썼다는 이유만으로 점수나 인수 완료를 선언하지 않습니다. 45개 작업표와 N01~N04 인수 절차는 기존 happycall-night-ops를 따릅니다.
