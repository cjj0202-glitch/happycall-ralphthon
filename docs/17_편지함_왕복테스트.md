# 다른 PC 준비 후 편지함 왕복 테스트

목적은 **실제 PC에서 같은 저장소의 자기 편지를 읽고 메인에게 회신하는지** 확인하는 것이다. 단위검사·메인의 발송 성공만으로 다른 PC 수신 완료라고 하지 않는다. 현재 pc2~4가 미등록이므로 왕복 실험은 아직 미실시다.

## 1. 먼저 준비

팀원은 [14 준비 프롬프트](14_팀원_PC_채팅용_프롬프트.md)를 사용한다. `channel/whoami.py`의 슬롯과 실제 hostname/GitHub가 등록값과 일치해야 한다. 미등록이면 메인에게 등록 정보를 채팅으로 전달하고 편지 처리 전에 멈춘다. 메인이 등록을 공유한 뒤 안전하게 갱신해 재검사한다.

메인은 저장소 라벨과 고정 상태 이슈가 이미 있는지 확인한다. `python channel/setup.py`는 계획 조회용이며, 기존 설정이 있는데 `--apply`를 반복할 필요가 없다. `gh auth status`와 두 private 저장소 접근을 해당 PC에서 확인한다.

## 2. 왕복 — PC마다 테스트 이슈 한 개

아래 pc2는 예시다. 메인이 실제 등록한 대상 하나를 선택한다. 동일 대상의 진행 중 TEST 이슈가 있으면 재사용하고, 실패할 때 새 이슈를 계속 만들지 않는다.

1. **워커:** 등록 후 `python channel/mail.py inbox`로 자기 열린 편지를 한 번 확인한다. `python channel/mail.py watch --once`로 변경 감지 기준을 만든다.
2. **메인:** `MAILTEST-pc2-날짜-시각`처럼 비밀이 아닌 고유 테스트 문구를 정한다. UTF-8 본문 파일에 아래 내용을 채우고 한 번 보낸다.

```powershell
python channel/mail.py send --to pc2 --type A --title "[TEST] pc2 편지함 왕복 확인" --body-file .local/mailtest-pc2.md
```

본문에는 배경, 수행할 일, **그 PC의 실제 경로**에서 실행할 명령, 기대값, 중단 조건, 회신할 내용을 쓴다. 테스트 문구는 공유 가능한 표식이며 인증번호·키를 사용하지 않는다.

3. **워커:** 다음 호출에서 새 편지 알림을 확인하고 해당 이슈를 읽는다.

```powershell
python channel/mail.py watch --once
python channel/mail.py inbox
python channel/mail.py read 실제번호
```

`to:자기슬롯`, 발신 pc1, 제목 TEST, 본문 테스트 문구를 대조한다. 자기 앞으로 온 TEST만 처리한다. 회신을 로컬 UTF-8 파일에 작성한다.

```text
테스트 문구: 받은 본문의 값을 그대로
슬롯 / hostname / 실제 GitHub 계정:
수신한 이슈 URL / HEAD:
받은 시각(KST) / 실행한 명령:
기대: 내 슬롯 TEST 한 건 / 실제:
오류 또는 미확인:
```

```powershell
python channel/mail.py reply 실제번호 --body-file .local/mailtest-reply.md
```

4. **메인:** 같은 이슈를 다시 읽어 문구·실제 회신자·등록 hostname·HEAD를 확인한다. 워커가 다른 워커에게 중계 편지를 만들지 않았는지 확인한다. 결과를 `reports/channel/pc2-mailbox.md`에 기록한다.
5. **메인:** 일치하면 `python channel/mail.py done 실제번호 --evidence "테스트 문구·등록 PC 회신·HEAD·수신시각을 대조함; 증거 파일 경로"`로 테스트 이슈를 닫는다. 워커가 스스로 닫거나 `--force-no-reply`로 우회하지 않는다.
6. **워커:** 종결 변화 확인 후, 추가 변화가 없는 `watch --once` 재호출에서 출력 0줄인지 확인한다. 별도 터미널의 상시 감시는 필요할 때 `python channel/mail.py watch --interval 30 --bell`로 실행한다. 감시기는 편지를 새로 만들거나 멈춘 AI 세션을 자동 재개하지 않는다.

## 3. 통과 기준

| 항목 | 기대 | 기록 |
|---|---|---|
| 신원 | 실제 hostname/GitHub/슬롯 일치 | whoami와 preflight |
| 수신 | 메인이 지정한 자기 슬롯 TEST 확인 | 이슈 URL·문구·KST |
| 회신 | 동일 이슈에 같은 문구와 실제 PC 증거 | 회신 링크·회신 계정 |
| 검증 | 메인이 등록값·문구·HEAD 대조 | reports/channel/pcN-mailbox.md |
| 종결 | 메인이 회신 검증 후 닫음 | closed 상태·시각 |
| 무변화 | 초기화와 변화 처리 뒤 추가 변화 없을 때 watch --once 출력0 | 실행시각·출력 줄 수 |

지연이면 회신을 기다리고 현재 세션이 실제 실행 중인지 확인한다. 401/403, 미등록, 테스트 문구 불일치, 대상 불일치가 나오면 그 자리에서 실패 증거를 남긴다. 다른 계정 토큰 복사나 남의 슬롯 지정으로 우회하지 않는다.

pc2~4 각각 실제 왕복 기록이 생겨야 해당 PC 준비 완료의 근거가 된다. 이 문서는 절차 준비 완료일 뿐, 원격 세 대의 테스트 성공 보고가 아니다.
