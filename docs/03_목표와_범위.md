# OneFlow — 해커톤 목표와 완료선

작성 기준: 2026-09-21. 설계 기준선 v2. [공식 규정 대조](09_공식규정_전수대조.md)를 반영했습니다. 행사는 9/21~22이며 **제출은 9/22 12:00**, 결선은 발표 5분·질의응답 3분·자료 최대 5페이지입니다. G01은 로그인 뒤 추가 안내와 API 예산 등 남은 팀 조건을 확인합니다.

## 1. 우리가 풀 문제

점포의 미도착·오출 문의를 받은 상담 담당자가 흩어진 통화·발주·피킹·출고·배송·영상 기록을 확인하느라 판단이 늦어지고, 기록이 없는 부분을 추측으로 채우기 쉽습니다. **문의 한 건에서 근거를 모으고, 확인된 사실과 추가 확인할 것을 분리해 다음 조치를 결정하는 화면**을 만듭니다.

제품 이름은 OneFlow. 첫 사용자는 상담 담당자, 두 번째 사용자는 물류센터 확인 담당자입니다. 고객에게 자동으로 보상하거나 재배송을 확약하는 시스템은 이번 범위가 아닙니다.

## 2. 끝났다고 할 수 있는 상태

아래 다섯 가지를 모두 만족하면 이번 해커톤의 제품 작업을 끝냅니다.

1. 미도착·오출 **2개 시나리오**가 접수 → 근거 조회 → 답변 초안 → 사람 확인/이관까지 연결됩니다.
2. 접수 필드와 답변의 사실 문장을 누르면 근거 발화 또는 원본 행으로 이동합니다. 근거가 없으면 비어 있다는 사실이 보입니다.
3. CASE-0001의 도착 실적 누락을 실제 미도착으로 단정하지 않습니다. 다른 점포·토트의 영상으로 결론 내리지 않습니다.
4. 같은 빌드를 초기화한 뒤 핵심 시연 **3회 연속** 성공하고, 네트워크가 끊겨도 명시적으로 표시된 대체 시연이 됩니다.
5. 실행 가능한 산출물·재현 방법·검증 결과·5분 발표 대본·최대 5페이지 자료·백업 녹화가 GitHub 기준선에 연결됩니다. 실제 Goal 원문과 주요 Codex JSONL은 별도로 보존·점검하고 공식 제출 완료 상태를 확인합니다.

이것은 합성 데이터로 검증하는 해커톤 제품입니다. 실제 물류망의 운영 효과, 개인정보 처리, 회사 시스템 연동, 운영 수준 보안 인증을 완료했다는 주장은 하지 않습니다.

## 3. 범위

| 등급 | 포함 | 완료선 |
|---|---|---|
| P0 | 2개 접수 흐름, 구조화 접수서, 근거 표·영상, 사람 확인, 이력, 오류·대체 모드, 검증·시연 | 제출 필수 |
| P1 | 실제 음성 인식·모델 추출 연결, 단순 조회 시나리오 | P0 안정화 뒤. 공개 심사 기준에서 제품 내부 유료 AI API 사용 의무는 확인하지 못함 |
| P2 | 파손 시나리오, 관리자 통계, 실시간 영상 생성, 운영 DB, 고급 검색 | 이번 기본 계획에서 제외 |
| 제외 | 실제 점포/고객 자료·음성, 실제 CCTV, 무인 보상·재배송, 회사 운영 시스템 쓰기 | 구현하지 않음 |

P0의 재생 데이터 모드는 접수 경험과 근거 판정을 검증하는 모드입니다. **실제 모델 호출이 없으면 '실시간 AI 추출'로 발표하지 않습니다.** API 호출이 가능한 경우 동일 계약의 live 공급자를 P1로 연결합니다. 실제 Astra/Codex 개발 실행과 Goal·로그 제출은 필수 준비로 관리하며 제품 내부 API 호출과 구분합니다. 데모 링크·영상 링크·발표자료는 공식 제출 항목이므로 호스팅/접근 경로 확인을 제출 필수로 옮깁니다. Vercel 인증이 없으면 대체 실행/영상 경로의 수용 여부를 운영진에게 확인합니다.

## 4. 지표와 측정

| 지표 | 목표 | 방법·분모 |
|---|---|---|
| 핵심 경로 완주 | 6/6 | 2시나리오 × 초기화 후 3회, 클릭별 기대 결과 기록 |
| 근거 없는 확정 | 0건 | 누락·충돌·다른 점포·다른 토트·빈 발화·API 실패 포함 12개 평가 입력 |
| 접수 핵심 필드 | 20개 입력의 각 필드 정답 기록, 전체 ≥90% 목표 | 점포·문의 유형·상품·수량·요청. 누락 정답은 null이며 강제 추정은 오답 |
| 기록 누락 시 안전 처리 | 12/12 평가 입력의 기대 상태 일치 | 수동 검토 필요·추가 질문·정상 조회를 정답 파일로 고정 |
| 근거 조회 체감 속도 | 로컬 fixture p95 <2초 목표 | 같은 PC·20회·데이터/빌드 SHA 기록. 실서비스 성능으로 일반화 금지 |
| 시연 안정성 | 3/3 + 오프라인 1/1 | 동일 릴리스와 초기화 절차로 측정 |
| 업무 시간·전환 감소 | 중앙값 50% 감소 목표, 미달도 실측 공개 | 3명 × 2케이스의 대응 비교. 순서 교차 배정, 시작/종료 정의 고정 |

킷에 있는 '6분', '화면 전환 8회'는 예시입니다. Before는 아직 미측정입니다. 업무 시간은 문의 내용이 제시된 순간부터 근거를 포함한 답변/이관 초안 저장까지 측정합니다. 영상 로딩·오류 복구도 포함합니다.
