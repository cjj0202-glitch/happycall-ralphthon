# OneFlow — 해커톤 목표와 완료선

**현재 실행 기준은 DEC-001~015·[통합 프롬프트](../PROMPT_team.md)·[미실행 /goal 초안](../GOAL.md)입니다.** 실제 STT/GPT, 경영주 텍스트 접수·회신 조회, 센터 최종 회신까지 이번 필수 범위입니다. 코드 계약은 [04](04_제품_상세설계.md)에 맞춥니다. B01~B03 전체 완료나 4인 각각의 동의를 뜻하지 않습니다. 전체 솔루션의 확장 후보는 [솔루션 지도](../planning/solution-map.md), 진행 방법은 [4인 설계회의](13_4인_설계회의와_BMAD.md)와 [First Bolt 실험](16_FDE_First_Bolt_적용.md)을 참고합니다.

작성 기준: 2026-09-21. 설계 기준선 v3(DEC-015 정합화). [공식 규정 대조](09_공식규정_전수대조.md)를 반영했습니다. 행사는 9/21~22이며 **제출은 9/22 12:00**, 결선은 발표 5분·질의응답 3분·자료 최대 5페이지입니다. G01은 로그인 뒤 추가 안내와 API 예산 등 남은 팀 조건을 확인합니다.

## 1. 우리가 풀 문제

최신 역할 결정(DEC-009): 상담원은 문의 접수의 정제·확인·이관을 맡고, **센터 담당자가 사실·조치 결과를 확인해 경영주에게 최종 회신**합니다. 초기 협업자 설명을 이 최종 회신 책임까지 구체화하며, 남은 조치가 있으면 처리 중이며 센터 최종 회신과 조치 완료 후 종결합니다(DEC-010·013).

점포의 미도착·오출 문의를 받은 상담 담당자가 흩어진 통화·발주·피킹·출고·배송·영상 기록을 확인하느라 판단이 늦어지고, 기록이 없는 부분을 추측으로 채우기 쉽습니다. **문의 한 건에서 근거를 모으고, 확인된 사실과 추가 확인할 것을 분리해 다음 조치를 결정하는 화면**을 만듭니다.

제품 이름은 OneFlow(작업명). 첫 사용자는 **점포 문의를 받는 상담 담당자**, 센터 담당자는 **이관받은 문의의 확인·조치 및 최종 회신 책임자**입니다. 이 사용자 구분은 2026-09-21 메인 사용자의 직접 지시로 결정했습니다([DEC-001](../planning/decisions.md)). 다른 팀원 세 사람의 개별 의견과 나머지 범위·완료선은 아직 확인 중입니다. 고객에게 자동으로 보상하거나 재배송을 확약하는 시스템은 이번 범위가 아닙니다.

## 2. 끝났다고 할 수 있는 상태

### 결정된 문의 여정

경영주가 필요한 내용을 말하며 시작합니다. 상담 담당자가 **문의 접수 → WMS·TMS 등 근거 조회 → 확인된 사실과 미확인 구분 → 답변 초안 작성 → 담당자 확인 및 이관**을 수행합니다. 센터 담당자가 이관받아 추가 확인·조치·최종 회신을 등록하고 경영주가 조회합니다. 이번 목업은 **미도착·오출고 두 유형**을 우선 연결하고 이후 문의 유형을 추가합니다([DEC-002](../planning/decisions.md)).

통화 종료 후 실제 STT/GPT 처리와 경영주 사이트 텍스트 제출을 공통 접수로 연결합니다. 경영주 접수·회신 조회, 상담 작업대, 센터 회신, 별도 WMS·TMS 화면이 이번 범위입니다. WMS/TMS는 독립 SYN-* 합성 데이터이며 실 회사 시스템 접속은 포함하지 않습니다.

### 제품 전체 완료선 기준안

아래 다섯 가지를 모두 만족하면 이번 해커톤의 제품 작업을 끝냅니다.

1. 미도착·오출고 **2개 시나리오**와 음성/텍스트 **2개 인입 경로**가 접수 → 근거 조회 → 답변 초안 → 상담원 확인/이관 → 센터 최종 회신·조치 완료 → 경영주 조회로 연결됩니다. 실제 STT/GPT 결과와 명시적 replay를 구분합니다.
2. 접수 필드와 답변의 사실 문장을 누르면 근거 발화 또는 원본 행으로 이동합니다. 근거가 없으면 비어 있다는 사실이 보입니다.
3. CASE-0001의 도착 실적 누락을 실제 미도착으로 단정하지 않습니다. 다른 점포·토트의 영상으로 결론 내리지 않습니다.
4. 같은 빌드를 초기화한 뒤 핵심 시연 **3회 연속** 성공하고, 네트워크가 끊겨도 명시적으로 표시된 대체 시연이 됩니다.
5. 실행 가능한 산출물·재현 방법·검증 결과·5분 발표 대본·최대 5페이지 자료·백업 녹화가 GitHub 기준선에 연결됩니다. 실제 Goal 원문과 주요 Codex JSONL은 별도로 보존·점검하고 공식 제출 완료 상태를 확인합니다.

이것은 합성 데이터로 검증하는 해커톤 제품입니다. 실제 물류망의 운영 효과, 개인정보 처리, 회사 시스템 연동, 운영 수준 보안 인증을 완료했다는 주장은 하지 않습니다.

## 3. 범위

| 등급 | 포함 | 완료선 |
|---|---|---|
| P0 | 미도착·오출고, 실제 통화 STT/GPT·텍스트 정제, 경영주 접수/회신 조회, 상담 확인·이관, 센터 회신·종결, 별도 WMS/TMS·애니메이션·지도·합성 영상, 역할·상태 보호, 검증·시연 | 사용자 결정에 따른 이번 필수 |
| P1 | 단순 조회 등 추가 업무 유형 | P0 안정화 이후 별도 채택. 실제 STT/GPT는 P0로 승격됨 |
| P2 | 파손 시나리오, 관리자 통계, 실시간 영상 생성, 운영 DB, 고급 검색 | 이번 기본 계획에서 제외 |
| 제외 | 실제 점포/고객 자료·음성, 실제 CCTV, 무인 보상·재배송, 회사 운영 시스템 쓰기 | 구현하지 않음 |

P0는 **실제 API 시연과 명시적 replay 복구를 모두** 준비합니다. 실제 API 의무는 공식 규정에서 도출한 것이 아니라 DEC-011·013의 사용자 결정입니다. 실제 호출이 없거나 실패하면 live 성공으로 발표하지 않습니다. Vercel은 사용자 재개 요청까지 보류하며 로컬 시연·허용된 영상/접근 경로를 준비합니다. 실제 Goal 시작·로그 보존·제출은 제품 구현과 별도로 증명합니다.

## 4. 지표와 측정

| 지표 | 목표 | 방법·분모 |
|---|---|---|
| 핵심 경로 완주 | 6/6 | 2시나리오 × 초기화 후 3회, 클릭별 기대 결과 기록 |
| 근거 없는 확정 | 0건 | 누락·충돌·다른 점포·다른 토트·빈 발화·API 실패 포함 12개 평가 입력 |
| 접수 핵심 필드 | 20개 입력의 각 필드 정답 기록, 전체 ≥90% 목표 | 점포·문의 유형·상품/대상·수량·단위·요청. 누락 정답은 null이며 강제 추정은 오답 |
| 기록 누락 시 안전 처리 | 12/12 평가 입력의 기대 상태 일치 | 수동 검토 필요·추가 질문·정상 조회를 정답 파일로 고정 |
| 근거 조회 체감 속도 | 로컬 fixture p95 <2초 목표 | 같은 PC·20회·데이터/빌드 SHA 기록. 실서비스 성능으로 일반화 금지 |
| 시연 안정성 | 3/3 + 오프라인 1/1 | 동일 릴리스와 초기화 절차로 측정 |
| 업무 시간·전환 감소 | 중앙값 50% 감소 목표, 미달도 실측 공개 | 3명 × 2케이스의 대응 비교. 순서 교차 배정, 시작/종료 정의 고정 |

킷에 있는 '6분', '화면 전환 8회'는 예시입니다. Before는 아직 미측정입니다. 업무 시간은 문의 내용이 제시된 순간부터 근거를 포함한 답변/이관 초안 저장까지 측정합니다. 영상 로딩·오류 복구도 포함합니다.

## 5. 현재 상태를 확인하는 정본

- 제품 구현·검증 현황: `CURRENT_TODO.md`, `reports/e2e/`, 실제 코드와 재현 결과. 문서의 요구사항을 구현 완료로 세지 않습니다.

- 20입력·12경계·6회 완주·3명 비교/업무시간 50% 목표는 실행 결과를 확보하기 전까지 미검증입니다. 다른 브라우저/서버 검사 수로 대체하지 않습니다.
- `GOAL.md`는 미실행 초안입니다. 실제 Goal·로그·공식 제출은 별도 확인하며 Vercel은 보류입니다.
