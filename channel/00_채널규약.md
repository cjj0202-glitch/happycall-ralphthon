# 채널 규약 — GitHub Issues 편지함

> 원본: 사내 `_PC간채널` (2026-08-17 개설, 처리완료 1,433건 전수 측정).
> 이 문서는 그 규약 중 **측정으로 살아남은 것만** GitHub 으로 옮긴 것입니다.
> 퇴화가 확인된 규약(`긴급도`·`회신` 머리글 필드, `_to_` 수신 세션 지정)은 가져오지 않았습니다.

---

## 1. 왜 GitHub Issues 인가

노트북 4대가 랄프 루프로 **동시에** 돕니다. 채널에 필요한 성질은 세 가지입니다.

| 필요 | 파일(git) | **Issues** |
|---|---|---|
| 4대 동시 쓰기 | 충돌. 랄프 루프는 충돌을 못 푼다 | **원리적으로 충돌 없음** |
| 받는 쪽이 clone 없이 읽기 | 불가 | **`gh` 한 줄** |
| 미처리/처리완료 구분 | 폴더 이동 + `__done` 접미 규약 | **open / closed 가 이미 그것** |

원본 채널이 파일이었던 이유는 사내 GitHub 이 없어서였습니다. 그 제약이 여기서는 없습니다.

🚨 **다만 Issues 는 네트워크가 있어야 합니다.** 행사장 와이파이가 끊기면 편지가 안 갑니다.
끊겼을 때의 대체 경로는 [운영설계 §네트워크가 끊기면](../docs/00_랄프톤_운영설계.md)에 있습니다.

## 2. 주소 체계

```
to:pc1  to:pc2  to:pc3  to:pc4     수신처 — 받은편지함이 곧 이 라벨이다
from:pc1 …                          발신처 — 라벨로도, 머리글로도 남긴다
```

슬롯 ↔ 역할 ↔ hostname ↔ GitHub 계정 매핑은 [`pcs.json`](pcs.json) 한 곳에만 있습니다.
역할이 정해지면 그 파일의 `role` 만 채우면 라벨·템플릿·보드가 전부 따라옵니다.

### 🚨 등록되지 않은 PC 는 편지함이 없다

`whoami.py` 는 hostname 으로 슬롯을 찾고, **못 찾으면 「미등록」을 반환합니다.**
기본 슬롯으로 떨어뜨리지 않습니다.

이것은 불편이 아니라 **설계**입니다. 원본 채널에서 이진 분기(`... if 개발PC else 운영PC`)를
그대로 뒀더니 노트북이 **운영PC 편지함을 자기 것으로 읽었습니다.** 남의 편지를 처리하는
사고입니다. 그래서 「모르면 안 준다」가 기본값입니다.

## 3. 유형 — 무엇을 편지로 만들고 무엇을 만들지 않는가

원본 채널 1,433건을 전수로 나눈 결과입니다. **비중은 실측입니다.**

| 유형 | 비중 | 편지로? | 왜 |
|---|---:|---|---|
| **B** 상태 보고·회신 | **51.5%** | ❌ **아니다** | 「했다·결과는 이렇다」. 상대에게 남는 실행이 없다 → `mail.py status --set` |
| **E** 경고·정정·철회 | 17.5% | ✅ + 긴급 | 「누가 언제 무엇을 철회했는가」가 사후에 필요하다 |
| **A** 즉시 조치 요청 | 14.4% | ✅ | 상대가 실행한 뒤 증거를 되짚어야 한다 |
| **D** 규칙·설계 전달 | 6.0% | ✅ | 정의상 나중에 다시 본다 |
| **H** 교차검증·판정 정련 | 5.8%* | ❌ | 산출물이 「다음에 어떻게 잴 것인가」뿐 → 코멘트로 끝낸다 |
| **C** 결정·합의 요청 | 2.4% | ✅ | 사람 승인이 껴서 최장 지연(15.6시간)을 만든 유형. **일찍 띄운다** |
| **G** 감시 개시·종료 | 1.4% | ❌ | 회신 도달률 10%. 아무도 안 읽는 순수 상태 신호 |
| **F** 자료·시크릿 전달 | 1.0% | ✅ | 🚨 값이 아니라 **경로**만 |

```
편지로   A · C · D · E · F   = 41.3%
편지 아님 B · G · H          = 58.7%
```

🎯 **절반 이상이 편지가 아닙니다.** 이것을 안 지키면 편지함이 상태보고로 덮여
진짜 지시가 묻힙니다. 그게 이 표의 존재 이유입니다.

## 4. 편지 쓰는 법 — 6칸

상대는 **이 대화의 앞부분을 모릅니다.** 이슈 템플릿이 이 6칸을 강제합니다.

| 칸 | 내용 |
|---|---|
| 1) 결론 | 첫 줄. 목록에는 제목만 뜬다. 인사·서론 금지 |
| 2) 왜 지금 | 배경 2~3줄 |
| 3) 해줘야 할 일 | 체크박스 |
| 4) 실행 명령 | 복붙 가능하게. 🚨 **상대 PC 기준 절대경로** |
| 5) 검증 방법 + **기대값** | 「에러 없음」은 검증이 아니다 |
| 6) 중단 조건 | 「거부되면 멈추고 회신」 |

### 🚨 기대값을 함께 적는다

원본 실측: *「`modules_unregistered` 키가 새로 생기고 값이 0」* 이라는 기대값이 있어서,
받는 쪽이 *「그 키가 아예 없다」* 를 **구 코드의 증거로** 쓸 수 있었습니다.
기대값이 없으면 받는 쪽은 **자기 자로 재서 통과시킵니다.**

## 5. 받는 법

```bash
python channel/mail.py inbox        # 내 앞 열린 편지만
python channel/mail.py read 12      # 본문 + 회신 전부
```

### 🚨 「그쪽」이라고 쓰지 않는다

한 PC 에 세션이 여럿입니다. 원본 채널에서 실제로 이랬습니다.

```
개발PC 에 세션이 둘이었고, 운영PC 가 둘을 «그쪽» 하나로 합쳐 읽었다.
 → 「그쪽이 「빌드 필요」로 보신 것과 다릅니다」 라는 회신이 왔는데,
    그 판단을 낸 것은 다른 세션이었다.
    받은 쪽은 자기가 한 적 없는 판단을 자기 것으로 되돌려받았다.
```

```
✗  「그쪽이 …로 보신 것과 다릅니다」
✅ 「pc3/wms 가 …로 보신 것과 다릅니다」
```

🎯 **«도구가 해 주니 규칙이 필요 없다» 가 이 규약이 깨진 방식입니다.**
GitHub 이 작성자를 붙여 줍니다. 붙은 것을 **쓰는 것**은 별개 층입니다.

## 6. 닫는 법 — 회신 없이 닫지 않는다

```bash
python channel/mail.py done 12 --evidence "PID 5092 · 기동 10:25:53 · 27건 반환 · 콘솔오류 0"
```

`--evidence` 없이는 닫히지 않습니다. 정말 회신이 필요 없으면 사유를 적습니다.

```bash
python channel/mail.py done 12 --force-no-reply "중복 발송분 — #11 에서 이미 처리"
```

이 게이트는 원본에서 **실제로 일했습니다**: `--force-no-reply` 사유가 68건 남았고
그중 「회신: 필요」였던 것은 **0건**이었습니다. 막는 장치가 아니라 **적게 만드는** 장치입니다.

🚨 GitHub Actions 가 한 겹 더 봅니다 — 코멘트 없이 닫힌 이슈는 **자동으로 다시 열립니다.**

---

## 7. 「보냄」은 「읽음」이 아니다

`gh issue create` 성공은 **도달**입니다. 읽었는지는 **회신으로만** 압니다.

원본 실측(파일 채널 기준)이 참고가 됩니다 — 첫 회신 지연 **중앙 5.9분**, 15분 이내 88.7%.
단 **양쪽이 깨어 있을 때만** 그렇고, 아니면 p90 이 9.2시간으로 튀는 이봉 분포였습니다.
랄프 루프는 계속 깨어 있으므로 앞쪽 분포에 가깝겠지만, **「조용하다」를 「안 했다」로 읽지 마십시오.**

## 8. 금기 6가지

| # | 금기 | 왜 |
|---|---|---|
| 1 | 신원 확인 없이 상태 변경을 시키지 않는다 | 잘못된 PC 에서 명령이 돈다 (원본에서 실제로 막았다) |
| 2 | 같은 대상에 둘이 동시에 손대지 않는다 | 선점을 이슈 코멘트로 선언하고, 물러난 쪽은 **무엇을 안 했는지** 적는다 |
| 3 | 남의 워킹트리에 `git stash` 를 쓰지 않는다 | 목록을 모르는 사람이 못 찾는다 |
| 4 | 내 세션에서 막힌 일을 남에게 시키지 않는다 | 권한 세탁 |
| 5 | 상대 판정을 그대로 믿고 되돌리지 않는다 | 아래 참조 |
| 6 | 시크릿 값을 본문에 붙여넣지 않는다 | 경로만. `mail.py` 가 발송 전에 검사한다 |

### 금기 5 — 틀린 판정도 근거를 갖추고 온다

원본에서 이런 회신이 왔습니다. **관측은 정직했고 명령도 맞았습니다.**

```
「f2bee45 가 도달하지 않았습니다. git cat-file -t f2bee45 -> Not a valid object name」
「2시간 뒤 재측정에도 그대로라 «동기화 지연»으로 보기 어렵습니다」
```

**틀린 것은 시간 축이었습니다.** 그 2시간은 *자기* push 기준이었고, 상대 push 로부터는
11분이었습니다. 12분 뒤 같은 곳에서 성공했습니다.

> **관측을 보낼 때는 「무엇을·언제·어디서 잰 것인가」를 함께 적습니다.**
> 받을 때는 **그 기준이 내 기준인지 상대 기준인지** 먼저 봅니다.
