# 시제품 신뢰성 — 초안 보존과 저장 결과 확인

2026-09-21 / 후속 제품 빌드. PC4 검증 기준 bfc8543은 변경하지 않습니다.

## 관찰한 병목과 이번 수정

격리 서버 8841–8844에서 상담 초안·센터 회신·추가 중인 조치가 메뉴 왕복으로 사라졌습니다. 실제 PATCH 200을 서버에 전달하고 응답만 차단하면 저장되었는데도 화면은 재시도만 안내했습니다. 정상 화면에는 최신 목록을 다시 읽는 동작이 없었습니다. AI Playwright 관찰이며 실제 사람 관찰로 주장하지 않습니다.

## 상태와 복구 계약

- 초안은 이 브라우저 페이지 메모리에만 보관합니다. 역할과 접수 번호를 키로 분리하여 메뉴·접수 왕복 후 복원합니다. 녹음 재생 상태와 완료 게이트는 보관하지 않습니다. 다른 녹음으로 이동하면 재생을 종료하고 완료 상태를 다시 검증합니다.
- 작성 내용이 있으면 브라우저 전체 새로고침·닫기에 기본 이탈 경고를 요청합니다. 브라우저 강제 종료·기기 장애까지 복원하는 영구 저장은 이번 범위가 아닙니다. 화면에 한계를 안내합니다.
- 목록 새로고침은 서버 목록과 최종 확인 시각만 갱신합니다. 편집 시작 시점의 revision이나 초안을 자동 교체하지 않습니다. 조회 중에도 현재 화면은 유지합니다.
- 서버와 편집 revision이 다르면 저장을 막고 최신 서버 내용과 현재 초안을 나란히 대조합니다. `서버 내용 사용`은 초안을 명시적으로 교체하고, `내 초안 유지 · 다시 확인`은 대조 후 새 기준으로 편집을 계속하며 상담원 확인 체크를 해제합니다. 최신 접수가 이관·종결되면 해당 역할의 기존 잠금을 유지합니다.
- 요청이 전달되었을 수 있는 네트워크 단절·응답 시간 초과·5xx·성공 응답 해석 실패는 저장 실패로 단정하지 않습니다. 저장 여부 조회를 먼저 제공하고 재시도 버튼을 잠급니다. 조회된 현재 값과 요청 내용이 같으면 서버에서 같은 내용을 확인했다고 안내하며, 다르면 대조 후 선택합니다.
- 신규 텍스트 접수는 UUID v4를 생성하고 `X-Idempotency-Key`로 보냅니다. 미확정 시 입력과 키를 유지하고 `GET /api/intake-attempts/{key}`로 확인합니다. 404는 원 요청 지연 가능성을 배제하지 못하므로 새 키 발급 근거로 쓰지 않습니다. 동일 본문·동일 키로만 재시도합니다. 저장 확인 또는 확정적 거절 후에만 입력을 새로 편집합니다.

## 검증 계획

1. 같은 사례/다른 사례 메뉴 왕복, 상담 확인 해제, 센터 회신·추가 중 조치 및 경영주 입력 보존.
2. 3개 독립 browser context에서 경영주 접수 → 상담 최신 목록 → 실제 PATCH 이관 → 센터 새로고침·실제 회신 → 경영주 새로고침으로 전달 확인.
3. 외부 context 수정 후 기존 폼 저장 409 또는 사전 차단, 서버 조회·대조·명시 선택 전 자동 덮어쓰기 0회.
4. PATCH 및 POST 서버 처리 후 응답만 abort: 저장 확인/동일키 재시도, 신규 접수 증가 정확히 1건.
5. 1440/1024/390px에서 수평 넘침과 복구 버튼, 키보드 동작 및 beforeunload 기본 경고를 검증합니다. 오디오 게이트와 기존 시나리오는 후속 통합 검사에서 반복합니다.

새 디자인 값이나 UI 라이브러리를 도입하지 않습니다. 기존 토큰과 notice/panel/button 패턴으로 초안 상태·최신 확인·복구 선택을 가까이 배치합니다.
