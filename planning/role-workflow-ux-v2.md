# 역할 업무 UX v2 — 실제 과업을 먼저 배치

2026-09-21 사용자 재검 요청에 따라 실제 Claude Code2.1.278에 고정 소스와 design-brief/redesign-existing-projects 스킬을 전달하고 독립 텍스트 검토를 받았습니다. 메인은 기존 IAB 화면을 직접 측정했습니다. Claude의 코드 추론과 실제 렌더 결과를 구분하며 사람 사용성 테스트로 표현하지 않습니다.

## 변경 전 관측과 목표

1201×791에서 상담원 통화 제목 y715, 저장/전달 버튼 y2665였습니다. 헤더118px·페이지제목84px·동기화/초안97px가 실제 업무를 아래로 밀었습니다. 원문 대조는 기본 접힘이고 좁은 두 열 때문에 왼쪽에 빈 공간이 남았습니다. 센터의 전체 목록 열람에서는 이관요약334px·회신452px로 갈렸습니다.

역할은 선택한 탭으로, 사건은 사건 제목으로 구분합니다. 첫 화면은 처리할 건과 실제 대조 도구를 보여주고, 이후 과업은 한 번의 키보드/클릭 이동으로 찾게 합니다. 접수와 이관·회신의 상태 의미는 바꾸지 않습니다.

## 이번 구현 계약

1. 브랜드·역할 탐색을 간결하게 하고, 동기화/분석방식/초안 안내를 유틸 행에 모읍니다. 페이지 h1은 접근성에 유지합니다. 초안이 다른 역할에 있어도 글로벌 경고의 의미를 명확히 합니다.
2. 사건 머리글과 현재 단계 안내를 모읍니다. 원문·접수 편집·근거·전달, 센터의 조사·조치·회신은 실제 앵커로 이동합니다. Desk/Center/CallReview를 새 단계마다 unmount하지 않습니다.
3. 각 편집 필드에 AI 제안과 현재 값의 차이를 바로 표시합니다. 긴5행 상세대조표를 입력폼 앞에 추가하는 제안은 폼을 다시 밀어내므로 채택하지 않습니다. 고급 대조 기능은 보존합니다.
4. 음성에서는 화자별 대화록을, 웹에서는 입력 원문을 기본 공개합니다. 음성 제작용 합성 원대본과 실제STT/저장 대화록 출처는 구분합니다. 긴 대화록은 접근 가능한 스크롤 영역으로 제한합니다.
5. 전달·회신이 차단된 구체 조건을 행동 근처에 표시합니다. 기존 canTransfer/blocked·revision·미확정 저장 복구·사람 확인·조치 완료·음성 재생 gate는 그대로입니다. 화면의 anchor 이동은 저장이나 확인 완료를 실행하지 않습니다.

색·폰트·크기는 기존 토큰만 사용하고 UI라이브러리를 추가하지 않습니다. 카카오톡·Teams 실제발송은 별도 최종연동 단계입니다.
