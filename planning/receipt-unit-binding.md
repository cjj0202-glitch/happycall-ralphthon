# 제안 수량·단위의 같은 상품 근거 묶기

2026-09-22 / pc1 로컬 보조 작업 / 메인 인수 전 설계.

## 사용자 과업과 결함

상담원은 정제 접수에서 해당 상품에 대해 발화로 뒷받침되는 제안값만 확인해야 합니다. `푸른달봉투 수령량은 4이고 별빛차는 2박스를 받았습니다.`에서 봉투 4와 다른 상품 BOX를 결합하면 잘못된 접수입니다. 현재 코드는 한 범위 안의 수량·단위를 별도 집합으로 모아 `(4, BOX)`를 보존합니다. 기대는 `(4, null)`입니다.

기준 HEAD `bc2435195eebd0ec8ad0661b04b0c5a18d0d6d1a`. 수정 전 직접 함수 실행에서 위 입력 `(4, BOX)`, 봉투 단독 `수령량은 4입니다.`는 `(4, null)`, 봉투 `4개를 받았습니다.`는 `(4, EA)`를 확인했습니다.

## 수정 계약

1. 기존 `_scopes`의 주문/수령, 현재/과거, 부정·미래·미확인 및 명시적 생략 연결 판정을 유지합니다. 모든 과거 문의를 거절하는 변경은 하지 않습니다.
2. 허용된 범위에서도 수량/단위 표현을 해당 상품에 연결합니다. 상품보다 앞선 다른 상품 값, 대상과 값 사이에 다른 상품을 끼운 표현을 대상의 값으로 지원하지 않습니다. 명시적 생략 범위도 같은 원칙으로 검사합니다.
3. 수량+단위를 원문 쌍으로 보존합니다. 서로 다른 쌍의 수량과 단위를 조합하지 않습니다. 수량만 명시된 진술은 수량만 지원하고 단위만 알려진 진술은 단위만 지원합니다.
4. 제안된 값을 지원/제거할 뿐 새 값 추출·null 자동 채움·단위 환산을 하지 않습니다. 근거를 찾기 어려운 표현은 값 삭제와 기존 상위 정제의 확인 안내로 연결합니다.
5. `live.py`와 실제 저장 데이터·원장은 수정하지 않습니다. 별도 FIX-W05 누락 단위 안내 작업과 분리합니다.

## 구현된 경계

`_value_belongs_to_target`은 값보다 앞선 가장 가까운 동일 상품 이름에서 값 표현까지의 연결을 검사합니다. 대상보다 앞선 값은 거절하고, 그 사이에 허용된 조사·수량 역할·시간 표현 외의 다른 이름/수치가 있으면 지원하지 않습니다. 대상 이름이 생략된 범위는 기존 `_scopes`에서 명시적 생략으로 연결된 경우에만 들어옵니다. 이 어휘 연결 검사는 새로운 상품명을 추론하지 않습니다.

`supported_values`는 `(수량, 단위)` 쌍, `(수량, null)`, `(null, 단위)`를 모으고 제안값에 대응하는 근거만 보존합니다. 수량 제안이 있으면 원문의 같은 수량 쌍에 있는 단위만 지원합니다. 수량 없는 별도 단위 진술도 그 수량에 붙이지 않습니다. 수량 제안 자체가 null이면 원문에 있는 해당 상품 단위만 보존할 수 있습니다. 제안 단위가 null이면 자동 채우지 않습니다.

독립검토에서 자연스러운 `이번에/오늘 오전에/정확히`를 버리는 P2 회귀가 확인되어 시간 연결을 구조적으로 보완했습니다. 날짜/최근 시점 + 조사, 오전·오후 등 시간대 + 조사, 숫자 시/분 + 조사는 값 앞에 올 수 있습니다. `정확히/딱`은 제한된 강조부사로 허용합니다. 숫자 시/분은 수량 근거 집합에 넣지 않으며 임의 상품 이름을 허용하는 정규식으로 확대하지 않습니다. 같은 시간 표현 뒤 다른 상품이 오는 반례도 유지합니다.

지원되는 연결 표현은 제한되어 있어 복잡한 삽입 설명이나 새로운 표현은 확인 대상으로 남을 수 있습니다. 자연어의 모든 상품 귀속을 판정하는 완전한 의미 해석기로 주장하지 않습니다. 변경 범위 밖인 화자·진술 진위·실인도 판정과 실제 모델 정확도는 별도입니다.
