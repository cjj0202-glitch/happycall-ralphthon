# 단위 자동 추출 누락의 상담원 검토 안내

2026-09-22 / pc1 / 독립 검토를 반영한 구현 전 설계. 기존 `supported_values`의 값 보존·제거 계약을 유지합니다.

## 사용자 문제와 범위

저장된 FIX-W05 응답은 원문에 현재 수령 상품의 `4개`가 있지만 모델이 `unit=null`을 제안했습니다. 현재 화면은 `단위 미확인`과 경영주 추가 질문을 보여 줍니다. 원문에 정보가 없는 경우와 AI가 추출하지 못한 경우가 구분되지 않아 상담원이 이미 받은 답을 다시 물을 수 있습니다.

이번 변경은 상담원의 원문 대조를 돕습니다. 누락한 단위를 자동으로 채우거나 원문을 실제 입고의 증거로 확정하지 않습니다. 모델의 원응답과 고객 요청을 보존하며, 추가 질문은 고객의 요청 필드에 넣지 않습니다. 이 안내가 추가돼도 기존 평가의 단위 값 오답이 정답으로 바뀐 것은 아닙니다.

## 수정 동작

1. 단위 후보를 추출하지 않습니다. 현재 검사를 통과해 남아 있는 수령 상품과 인용문이 있고 unit가 null이면, `issues`에 자동 확인 미완료라는 안내와 그 인용문을 그대로 제공합니다. 인용의 존재가 현재 수령·특정 단위 정답·실제 입고 확인의 증거라고 표현하지 않습니다.
2. 수령 누락값 안내는 이미 구현된 `receipt_followup`의 원문 대조→원문에서도 불명확할 때 경영주 확인 순서를 사용합니다. `checked_claim`이 별도로 만들던 무조건 경영주 재질문은 제거해 같은 누락에 대한 고정 질문 두 개를 하나로 줄입니다. 주문 안내도 주문 맥락에서 원문 대조를 먼저 안내합니다.
3. 원문에 단위가 실제로 있는 사례와 없는 사례 모두 null 값을 보존합니다. 접수 필드에 새 값을 쓰거나, 원문에 단위가 없다고 단정하거나, 고객 요청 필드에 추가 질문을 넣지 않습니다.
4. UI는 기존 `issue.message/evidence` 표시 계약을 사용합니다. 상담 편집기의 질문 영역은 `확인할 항목`/`추가 확인 메모`, 대조 상세 영역은 `통화 후 확인할 항목`으로 바꿔 상담원의 원문 검토도 포함합니다. 기존 요약의 `단위 미확인`은 정제 값 상태이며 그대로 유지합니다. 값 저장/메모 반영 동작은 이 문구 변경에서 바꾸지 않습니다.
5. 기존 모델의 자유 미확인 문장을 광범위한 문자열 필터로 삭제하지 않습니다. 모델 제안 표시와 새로운 서버 안내를 구분합니다. 새 안내가 모델 원응답의 오류나 단위 추출 정확도를 개선했다고 보고하지 않습니다.

UI 실측에서 확인 항목 번호 `01`이 너비7.37px/높이33px로 두 줄에 나뉘었습니다(기존1280px 화면). 번호와 추가 아이콘의 flex 축소를 막고 번호를 한 줄로 유지합니다. 기존 토큰·색·간격을 유지하며 390/768/1280px에서 실제 번호 높이와 수평 넘침을 확인합니다. 새 서버를 기동하거나 기존 초안/접수를 변경하지 않습니다.

## 수용 검사

### 구현 전 독립 검토 판정 — 후보 방식 보류

기존 `supported_values`를 EA/BOX로 각각 호출해 유일한 후보를 고르는 것만으로는 충분하지 않습니다. 독립 검토자가 `지난주 푸른달봉투 4개를 받았습니다.`에서 현재 수령 안내로 잘못 이어질 수 있는 과거 문맥과, `푸른달봉투 수령량은 4이고 별빛차는 2박스를 받았습니다.`에서 대상 수량 4에 다른 상품의 BOX가 붙어 `(4, BOX)`로 남는 반례를 재현했습니다. 후자는 실제 저장 모델 응답에서 발생했다고 확인한 것이 아니라 원문 근거 판정 함수의 합성 반례입니다.

따라서 후보 단위를 특정하는 방식은 폐기했습니다. 별도 [수량·단위 귀속 설계](receipt-unit-binding.md)는 기존 근거 판정의 상품별 값 연결을 보완합니다. 이 안내는 그 결과 값이 미확인이라는 사실과 상담원의 원문 검토 순서만 표현합니다. 과거 전용 발화를 모두 무효로 만들거나 null 단위를 채워 넣지 않습니다.

먼저 수정 전 실패를 고정합니다. 직접 `4개`의 모델 단위 누락, 원문 자체의 단위 미제시, 정상 EA/BOX, 주문의 누락, unit와 quantity 모두 null, 인용 근거 거절을 대조합니다. 값·고객 요청·원문 불변, 정확한 인용 또는 인용 안내 부재, 고정 질문의 중복 제거를 확인합니다. 안내를 제거하거나 잘못된 단위를 채우는 메모리 변이를 검출해야 합니다. 자연어 근거 판정의 별도 회귀 결과와 합산하지 않습니다.

저장된 21:06 FIX-W05 응답은 실제 `LiveAnalyzer`의 무과금 client/budget double로 재처리합니다. 과거 실제 모델 호출 결과에 대한 후처리 검증이며 새 모델 정확도 평가가 아닙니다. 기존 두 흐름 ASGI·근거 정제 검사를 영향 범위로 재검합니다. 실제 브라우저의 새 AI 분석은 현재 실행 API와 source가 달라 별도 통합 검수로 남깁니다.
