# 고객 요청과 AI 추가 확인의 분리

2026-09-21 · 실제 4호출 run `20260921T120622Z-657e60bdb7` 후속 수정.

고객이 주문·라벨 확인만 요청했는데, 모델이 단위 확인까지 고객 요청 필드에 쓴 오류를 수정합니다. 단위가 null인 모델 추출 누락과 서버가 원문에 없는 고객 요청을 표시하는 문제를 분리합니다. 이번에는 수량·단위 값을 추론하여 채우지 않습니다.

## 계약과 소유

공개 JSON 스키마는 유지합니다. `fields.request`는 모델의 자유문 요약 대신, transcript에 실제로 포함되고 요청 행위가 확인되는 `draftContext.requestQuote`를 보존한 문자열입니다. 표시용 공백·욕설 순화만 허용하고 새 행동·조건·숫자·업무 결과를 덧붙이지 않습니다. AI가 필요하다고 판단한 단위 등 추가 확인은 `questions`에만 둡니다.

인용이 없거나 위조·합성되어 있으면 request는 null이며 원문 대조 질문을 남깁니다. 서술·완료·향후 요청 예정·요청 사실 부정·예문 속 명령을 실제 고객 요청으로 승격하지 않습니다. `내일 확인해 주세요`나 `확정하지 말아 주세요`는 현재의 유효한 요청이며 그대로 보존합니다. 명시된 요청을 서술문의 일반 부정·미래 단어만으로 지우지 않습니다.

소유 파일: `server/live.py`, 새 `server/request_grounding.py`, 새 `tests/test_request_grounding.py`, 기존 `tests/test_analysis_repair.py`의 request 기대 assertion에 한정한 계약 갱신, 본 문서와 `reports/request-grounding.md`. 새 모듈은 메인이 배포 whitelist에 포함합니다. UI·수량 귀속 모듈·스키마·정답·기존 결과·원장·기존 보고서는 수정하지 않습니다.

## 검증 단위

1. 원문 요청에 없는 단위 확인, 서술문·부정·미래·완료·인용 예문, 인용 없음/위조를 새 합성 반례로 실패시킵니다.
2. 양성 요청, 부정형 요구, 미래 시각의 현재 요청, 강한 불만·긴급성·조건을 원문 또는 명시 순화 형태로 보존합니다.
3. 수령량이 문의 대상이고 해당 필드가 비었을 때 AI 추가 질문만 보완합니다. 단위가 비었다는 이유로 고객 요청을 바꾸거나 과거 단위를 넣지 않습니다. 배송 전체 문의에 불필요한 수량을 강제하지 않습니다.
4. 저장 원응답 4건과 기존 32건을 새 로컬 출력으로 재처리합니다. 기존 원본 해시, 자동 필드 불변, 요청 인용별 변화·null·허위 요청 제거를 확인합니다. 새 모델 호출은 0건입니다.
5. 기존 테스트의 자유문 보존 기대는 새 계약에 맞춰 원문 일치/허위 요청 제외의 더 강한 assertion으로 변경하고 실패 이력을 남깁니다. 전체 의미 정확도나 라이브 품질 상승은 독립 판정 전 주장하지 않습니다.

## 후속 반례: 인용문의 명사형 부정·과거 전달·가정

동결 뒤 자체 반례에서 `“라벨을 확인해 주세요.”라는 문장은 요청이 아닙니다.`의 내부 명령이 현재 요청으로 채택됐습니다. 메인의 수정 승인에 따라 이 반례와 과거 전달·가정 인용을 먼저 실패 검사에 추가합니다. 인용 주변의 `요청이 아닙니다`, `부탁이 아니에요`, `전달받았습니다`, `들었습니다`, `라고 한다면`은 현재 요청을 뒷받침하지 않습니다. 반면 `박스 말고 개로 확인해 주세요`, `라벨이 다르다면 주문서를 확인해 주세요`처럼 요청 자체의 제외 조건이나 실행 조건은 현재 요청으로 유지합니다. 새 결과 경로에 재처리하며 기존 출력은 덮어쓰지 않습니다.

## 독립 R02·R04·R05·R06 보완 단위

독립 9반례 중 네 실패만 후속 단위로 보완합니다. `부탁하려고 합니다`처럼 요청 행위 자체의 미래 의도는 현재 요청과 구분하고, `반송 방법 안내 요청입니다`처럼 동작·대상을 가진 명사형 요청은 보존합니다. `주세요`, `해 주세요`처럼 동작·대상이 없는 끝부분만의 인용은 자동 복원하지 않고 검토 대상으로 남깁니다.

철회는 인용 뒤 같은 화자의 발화까지 대조합니다. `그 요청은 취소합니다`는 중간에 다른 현재 요청이 없을 때 직전 요청의 철회로 처리하고, 대상이 명시된 철회는 요청 대상 용어의 겹침을 확인합니다. 별도 반송 요청을 취소했다고 라벨 확인 요청을 지우지 않습니다. 상담원 등 다른 화자의 발화는 경영주의 철회로 사용하지 않습니다. 이는 인접한 같은 화자 문장의 명시 철회와 단순 대상 대조를 지원하는 한정 계약이며, 대화 전체의 대명사·공동참조를 해석한다는 보장은 아닙니다.

원 독립 스크립트·결과·기대는 불변으로 보존합니다. 네 반례와 동일대상/다른대상/중간별도요청/금지형 철회의 양음성 회귀를 먼저 실패시키고, 원 스크립트의 출력 위치만 바꾼 로컬 사본으로 9반례와 저장 36건을 다시 대조합니다.
