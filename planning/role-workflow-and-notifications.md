# 역할별 업무 흐름과 최종 알림 범위

2026-09-21 사용자 중간점검: 상담원과 센터 담당자의 업무 순서대로 핵심 기능을 직관적으로 배치합니다. 카카오톡·Teams 푸시는 최종 완성 범위에 포함합니다. 아래는 설계이며 발송·연동 완료 기록이 아닙니다.

## 이번 UI 변경

기존 골격은 같은 급의 다섯 기능 메뉴와 접수 전량 카드 다음에 작업 내용이 이어집니다. 새 골격은 **역할 선택 → 상태별 처리 목록 → 선택한 문의의 현재 단계와 다음 행동**입니다. WMS/TMS는 선택 사건의 근거 조사 화면이며, 돌아오면 원래 역할·사건·작성 중 내용을 유지합니다.

| 역할 | 시작 목록 | 처리 순서 | 완료선 |
|---|---|---|---|
| 상담원 | 접수·확인 대기, 센터 전달, 완료 | 통화 종료/입력 원문 확인 → AI 정제 대조·수정 → 물류 근거와 미확인 확인 → 부서·사람 확인 후 이관 | 서버가 이관 저장을 확인 |
| 센터 담당자 | 새 이관, 처리 중, 완료 | 전달 내용 확인 → WMS/TMS·CCTV 조사 → 조치 기록 → 경영주 회신 | 회신 등록과 남은 조치 완료가 함께 충족 |
| 경영주 | 본 시제품의 접수·회신 화면 | 문의 제출 → 처리 상태 조회 → 센터가 등록한 회신 확인 | 해당 문의의 회신 조회 |

역할 탭은 시제품의 업무 화면 선택입니다. 실제 사용자 인증·접근 권한 검증 완료로 표시하지 않습니다. 목록을 분류해도 원본 접수나 테스트 데이터를 삭제하지 않습니다. 빈 큐는 빈 상태를 보여주며 다른 상태의 사건을 몰래 선택하지 않습니다.

현재 단계 하나만 강조합니다. 분석 실행·저장·이관·종결이 경쟁하지 않도록 주 행동을 현재 과업에 맞추고 보조 동작을 구분합니다. CallReview의 실제 재생 완료 게이트, 원문/AI/사람 수정 구분, revision 충돌·저장 미확정 복구, 역할별 초안 키와 이관 후 잠금은 보존합니다.

## 디자인 브리프와 작은 검증

CRUD 입력 대장의 Split-Pane 워크벤치 패턴을 사용합니다. 넓은 화면은 처리 목록과 사건 작업을 분리하고 좁은 화면은 목록 높이를 제한한 세로 흐름으로 전환합니다. 새 영구 탐색 메뉴를 추가하지 않습니다. `apps/web/app/tokens.css`의 surface/border/text/action/focus/status 및 간격·크기·폰트 토큰을 재사용합니다. 외부 스킬의 팔레트·폰트·장식 모션은 가져오지 않습니다.

첫 가설은 “업무 역할에 맞는 대기 건과 다음 행동을 찾아 원래 사건으로 돌아올 수 있다”입니다. 구현 전 실제 열린 화면에는22개 접수가 역할 구분 없이 나열됐습니다. 코드에서는 센터→물류 시 PATCH역할이 상담원으로 바뀌고 복귀가 상담으로 고정된 것을 확인했습니다. 목록/역할/복귀 변경 후 같은 조건에서 선택사건·초안 보존·빈 목록·검색·이관 후 조회를 검사합니다. 실제 사람 과업 관찰은 아직 하지 않았습니다.

## 최종 카카오톡·Teams 알림

외부 채널 발송은 별도 연동 단계입니다. 현재 화면에 실제 발송한 것처럼 성공 배지나 가짜 전송 이력을 만들지 않습니다.

| 확정된 업무 사건 | 수신 역할·채널 후보 | 알림 목적 |
|---|---|---|
| 사람 확인 후 이관 저장 성공 | 담당 센터·Teams | 새 이관 접수와 해당 사건 열기 |
| 센터의 추가 확인 요청 등록 | 담당 상담원·Teams | 빠진 내용 확인과 같은 접수 복귀 |
| 센터의 회신이 등록됨 | 경영주·카카오톡, 상담원·Teams | 접수별 회신 조회 안내 |
| 후속 조치가 남은 중간 회신 | 해당 담당자·Teams, 경영주 안내는 명시 정책 적용 | 처리 중 상태와 다음 조치 확인 |

예상 UI는 사건 상세의 알림 이력과 채널 연결 상태입니다. 핵심 처리 버튼에 채널 설정을 섞지 않습니다. 초안 편집·버튼 클릭만으로 알리지 않고, 서버가 실제 상태 변경을 저장한 사건을 기준으로 알림을 생성합니다. 같은 사건/revision/수신처/채널은 중복 생성하지 않습니다. 전송 대기·발송 확인·실패·연결 안 됨·결과 미확정을 구분하고, 응답 유실을 성공으로 표시하지 않습니다.

최종 연결 전 확인할 입력은 채널 계정과 발신 권한, 수신 대상 매핑, 템플릿, 공급자 응답·중복 방지 방식, 비용/개인정보 범위입니다. 아직 공급자 API·계정 권한·실제 수신을 검증하지 않았습니다. 담당자는 메인 pc1이며 실제 외부 발송 범위는 구체 수신 대상이 준비된 뒤 별도 명시합니다. 메시지는 최소한의 접수 식별·상태·안전한 상세 링크만 담고 통화 원문·욕설·비밀정보를 복사하지 않습니다.

완료 검증은 저장 실패 시0발송, 동일 사건 중복0, 역할·수신처 분리, 조회 링크의 사건 일치, 실패/미확정 복구, 최종 등록 회신과 메시지 일치, 실제 채널에서의 수신 증거입니다. 목업·단위검사만으로 외부 수신 완료를 표시하지 않습니다.
