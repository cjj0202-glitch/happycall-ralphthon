# 한국어 상담 대본·음성 품질 수용 기준

2026-09-21 22:14 KST. 작성: pc1의 음성 품질 기준 담당 AI. 이 문서는 사용자 지적을 해결하기 위한 제작·검증 계약이며 합성·청취·제품 교체 완료 보고가 아닙니다. 이 파일만 추가했고 다른 담당자의 원고·음원·코드·manifest는 수정하지 않았습니다.

## 현재 판정과 적용 범위

사용자가 v3 한국어 통화를 직접 듣고 “매우 어색해”라고 말한 **실제 부정 청취 피드백 1건**이 있습니다. 따라서 기존 음원의 **한국어 자연스러움 요구는 미통과**입니다. 이전 PCM 동일성·무음 삽입·해시·재생 종료·자막 검사는 기술 동작 증거이며 이 지적을 해소한 증거가 아닙니다. 1건의 의견을 다수 이용자의 만족도나 MOS로 환산하지 않습니다.

새 원고는 [전문 대본 후보](korean-call-v4-script.md)와 [JSON 정본 후보](korean-call-v4-script.json)를 따릅니다. 관측 당시 JSON SHA256은 `c68b739d84cee98dc22cd9673eac288bffbf8e805b389824be0daf3e4b84eabb`이며 CASE-0001 14턴·필수 사실 7개, CASE-0002 14턴·필수 사실 9개, 합계 28턴·16개 사실입니다. 원고가 바뀌면 이 기준 SHA의 결과를 새 원고에 소급하지 않습니다.

기존 [미디어 전체 품질 기준](production-quality.md)의 영상·통합 기준은 유지합니다. 그 문서의 OpenAI marin/cedar 제작 경로와 약 -18 LUFS 목표는 과거 제작안입니다. 이번 음성 교체의 후보 선정·라이선스·자연스러움 판정에는 본 문서를 추가 적용합니다. 특정 공급자 채택을 미리 확정하지 않습니다.

22:14 초안 작성 당시 클로바더빙 접근은 미확인이었습니다. 이후 메인이 사용자 직접 로그인·아라 상담원/승표 선택·4턴 프리뷰 합성과 재생을 확인했습니다. [22:22 실제 접근·프리뷰 보고](../../reports/media/clova-dubbing-preview-20260921.md)를 현재 상태로 참조합니다. 공식 음원 파일의 로컬 수신·음향 측정·청취 품질·제품 채택은 아직 미확인입니다. 일반 계정 접근이 회사 상용 서비스 탑재 권한의 확인을 뜻하지 않습니다.

## 원칙과 판정 상태

- 사실 보존·공식 사용 권리·오류 방지는 필수 게이트입니다. 듣기 좋은 음색 점수로 실패를 상쇄하지 않습니다.
- 자연스러움은 실제 오디오를 들어야 평가합니다. 파일명·파형·ASR 정확도·국내 기업이라는 출처만으로 판정하지 않습니다.
- 아래 음향·편집·주관 평가 수치는 모두 **이번 시제품을 위한 내부 제안 기준**입니다. 방송 표준·업계 인증·공식 공급자 품질 보증이 아닙니다.
- `PASS`는 해당 입력·음원 SHA·평가 범위의 기대값을 직접 대조했을 때만 씁니다. `FAIL`은 재현된 위반, `NOT_RUN`은 미실행, `UNVERIFIED`는 자료·권리·도구·판정자가 부족한 경우입니다. 실패 이력은 수정 후에도 남깁니다.
- 실제 한국어 청취자의 결과와 오디오를 직접 소비한 AI 검토자의 결과는 별도 열로 기록합니다. 텍스트만 읽은 AI 검토를 청취로 세지 않으며, AI 점수를 사람 점수나 사람 동의로 표시하지 않습니다.

| 보이스 | 허용된 프리셋 2종과 한국어 지원을 실제 확인 | 공급자·모델·voice ID·표시명·언어·스타일 설정 |

공식 다운로드 파일을 그대로 써야 하는 조건이면 **LUFS 목표를 맞추려고 파일을 변형하지 않습니다**. 공식 편집기 안에서 허용된 속도·쉼·볼륨 조정을 먼저 사용합니다. 외부 조립이 허용되지 않으면 공식 프로젝트에서 두 화자 대화 완성본을 내보내는 경로를 선택합니다. 공식 다운로드가 안 되거나 권리 확인이 안 된 프리뷰를 브라우저 내부 스트림 추출·화면 녹음으로 대체하지 않습니다.

평가 중 체감 음량 차이는 청취 플레이어의 볼륨으로 맞춰 들을 수 있으나 이는 원본 파일의 정규화 완료가 아닙니다. 재생 볼륨과 각 파일의 실제 측정값을 함께 적습니다. 명확한 허용 근거가 생긴 때만 원본을 보존하고 별도 파생본을 생성해 새 SHA를 부여합니다.

| 필수 게이트 | 확인할 내용 | 실패 예 |

대본 편집의 제안 문턱은 기존 원고의 5축 각 3/4 이상·합계 17/20 이상을 그대로 사용합니다. 축은 대화 연결, 불만·응대 현실성, 정정 이해도, 정보 밀도, 발음 원고 충실성입니다. 대본 작가와 별도 검토자가 정확한 턴 ID·문제 문장·수정 이유를 남깁니다. 이 대본 점수와 아래 실제 음성 점수는 합산하지 않습니다.

상담 현실성에는 한 번에 한 질문, 직전 발화에 대한 반응, 짧은 오류 인정, 업무 권한에 맞는 후속 안내가 필요합니다. 문어체 접수 항목 낭독·매번 같은 사과·억지 추임새·과장된 성우 연기·길이 채우기 문장은 수정 대상으로 삼습니다. 새 욕설을 만들어 정제 성능을 연출하지 않습니다.

## Q2: 20~30초 공급자별 프리뷰

한 번에 전체 두 통을 생산하지 않습니다. 원고·화자 역할·초기 설정을 고정한 짧은 후보를 먼저 공식 경로로 생성합니다. 호출 수·문자/크레딧·비용은 메인이 현재 실제 예산과 계정 조건을 확인한 한 단위로 관리하며 실패를 자동 재시도하지 않습니다.

| 우선 구간 | 평가 목적 | 제작 조건 |
|---|---|---|
| W03~W05, 3턴 | 상담원 오청·경영주 정정·상담원 인정, 두 음색과 숫자·단위 | 발음 원고 130자. 길이 20~30초 목표, 실제 합성 후 측정 |
| M06~M09, 4턴 | 경영주 추측·상담원 확인 질문·미확인 안내 | 발음 원고 144자. 우선 구간 통과 후 필요한 두 번째 샘플 |

20~30초는 비교 부담을 줄이는 제안입니다. 단위를 잘라내거나 속도를 과도하게 늘려 길이만 맞추지 않습니다. 공급자 특성상 30초를 넘으면 실제 길이와 이유를 남기고 동일한 턴 집합으로 비교합니다. 원고가 제안한 더 긴 W02~W07 비교는 첫 프리뷰를 통과한 후보의 후속 확인에 사용할 수 있습니다.

공급자 A/B는 동일 spokenText·턴 순서·화자 역할을 사용합니다. 공급자별 기능이 다르면 실제 설정과 지원하지 않는 항목을 드러냅니다. 기존 v3 대 새 v4는 원고와 음성이 동시에 바뀌므로 종합 선호 비교이며 공급자만의 효과로 해석하지 않습니다. 평가 순서 A/B를 교차하고 이름을 숨길 수 있으면 음원 A/B로 청취하되 실제 실시하지 않은 블라인드 시험을 기재하지 않습니다.

## Q3: 한국어 음성 청취와 기술 기준

실제 음성의 내부 평가표는 다음 5축을 각 1~5점으로 기록합니다. **제안 문턱은 각 4점 이상, 합계 21/25 이상**입니다. 이는 MOS가 아니며, 평가자 수·신원 유형·음원 버전·정확한 시간 구간을 함께 적는 작업용 점검표입니다. 점수만 남기지 않고 불합격 이유 또는 남는 한계를 반드시 기록합니다.

| 음성 축 | 4점 이상을 제안하는 상태 | 즉시 수정할 현상 |
|---|---|---|
| 한국어 억양 | 질문·확인·사과·불만의 말끝이 자연스럽게 구분됨 | 외국어식 강세, 모든 문장이 같은 상승 억양, 기계적인 문장 단절 |
| 발음·명료도 | 점포·상품·숫자·부정·단위를 첫 청취에 알아들을 수 있음 | 열여덟/여덟, 한 개/한 박스 혼동, 음절 누락·반복 |
| 두 화자 구분 | 눈을 보지 않아도 2명임을 구분하고 같은 역할의 음색이 유지됨 | 턴마다 목소리가 바뀌거나 두 역할이 거의 같은 음색 |
| 대화 속도·쉼 | 의미 단위와 상대 반응이 연결되고 정정은 또렷함 | 문장 중간 긴 침묵, 급한 기계 낭독, 정정 덮어쓰기·겹침 |
| 감정·업무 말투 | 차분한 상담원과 답답한 경영주를 절제해서 전달 | 광고·뉴스·동화 낭독, 과장된 분노, 매번 동일한 사과 톤 |

중요 사실이 잘못 들리면 총점과 무관하게 FAIL입니다. 특히 W03 “한 개”, W04 “한 개가 아니라 한 박스”, W05 “제가 잘못 들었습니다”, 미도착의 “제 생각이에요”·시각 미확인을 실제 음원에서 확인합니다. ASR 결과가 맞아도 사람이 듣기 어색할 수 있으므로 두 축을 별도로 판정합니다.

| 기술 항목 | 내부 제안 기준·판정 방법 | 권리·측정 한계 |
|---|---|---|
| 전체 길이 | 각 통 60~90초 목표. 실제 decoded sample 수 / sample rate와 플레이어 duration 대조 | 짧거나 길면 정보 밀도·자연스러움으로 재검토. 길이만 맞추기 위한 문장·무음 추가 금지 |
| 속도 | 한국어 발음 원고를 기준으로 유성 구간 약 4~7음절/초를 초기 점검 범위로 사용 | 공식 정상 범위가 아님. VAD·음절 집계 규칙을 기록하고 수치로 억양 평가 대체 금지 |
| 화자 사이 쉼 | 원고 pauseAfterMs 120~450ms를 초기값으로 사용. 공급자 말미 쉼까지 포함한 실제값 확인 | 모든 턴 고정 간격 금지. 의미 없는 1초 초과 공백은 구간별 재검토 |
| 통합 음량 | 전체 약 -18 LUFS, 허용 목표 -20~-16 LUFS | 원본 변경 불가 조건이면 측정·청취 후 공식 편집기 수정 또는 후보 재선정. 외부 정규화 강행 금지 |
| 화자 간 음량 | 동일 조건으로 계산한 역할별 active-speech 평균 차이 3dB 이내 목표 | 짧은 턴의 LUFS는 불안정. 계측 방법·대상 구간을 함께 적고 자동 통과 금지 |
| 피크·클리핑 | true peak -1dBTP 이하 목표, 확인된 audible clipping 0건·평탄하게 잘린 파형 0구간 | 단일 최대 샘플 값만으로 모든 클리핑 유무를 단정하지 않음. 측정 도구·필터·실제 값 보존 |
| 시작·끝 | 첫 음절과 문장 말미 잘림 0건, 마지막 발화 뒤 자연스러운 종결 | 새 음원 실제 끝부분 재생 필요. 파일 길이 정상으로 대체 금지 |
| 배경·가공 | 음악·과장된 전화 잡음·효과음 0개, 두 화자 정정 구간 겹침 0개 | 음색 결함을 필터로 가리지 않음. 필요한 가공은 공식 조건 범위 안에서만 |
| 자막 동기 | 턴별 실측 start/end. 음절 시작·끝과 차이 ±200ms 목표, 핵심 정정 구간 ±150ms 목표 | 실제 음원 28턴 전수 확인. 문자 수·옛 8턴 시간표로 계산 금지 |
| 파일·전송 | 실제 MIME/인코딩/채널/sample rate/길이/bytes/SHA 기록. 앱과 STT가 지원하는 형식 | 공식 다운로드 원본 보존. 포맷 변환은 허용될 때만 별도 파생본 |

청취 환경도 남깁니다. 헤드폰 또는 스피커 종류, 재생 1.0배속, 플레이어 볼륨, 주변 소음, 평가자 유형을 기록합니다. 평가자가 조건을 알 수 없으면 미확인으로 둡니다. 사용자 실제 청취를 기다리는 동안 기술 검증·통합 준비는 진행할 수 있지만 사람 청취 승인란을 AI가 대신 체크하지 않습니다.

## Q4: 전체 합성과 통합 검증

프리뷰의 사실·권리·명료도·자연스러움에서 알려진 중대 결함이 해결된 후보로 전체 28턴을 생성합니다. 같은 화자 ID·모델·기본 발음 규칙을 유지하고, 달라진 설정은 턴별 기록합니다. 공급자가 지원하지 않는 감정·쉼 지시는 발화 텍스트에 붙이지 않습니다.

전체 음원은 2개 통을 처음부터 끝까지 1.0배속으로 확인합니다. 짧은 프리뷰 통과가 28턴 전체 통과가 아닙니다. 16개 사실·28턴·두 화자·정정·불만·요청·미확인에 대해 실제 음원과 전사를 대조하고 문장 누락·반복·순서 변경을 찾습니다. 원고를 STT 정답으로 미리 주입하거나 화면에 실제 전사로 표시하지 않습니다.

| 통합 검사 | 기대 동작 |
|---|---|
| 자산 등록 | 선택된 새 WAV와 manifest·버전 URL·fixture 2사본·턴 타임라인의 SHA/길이/원고가 일치 |
| 자연 재생 종료 | 각 통을 사용자 재생으로 자연 종료한 뒤 정제 버튼 활성화. 끝으로 seek·시간 조작만으로 통과하지 않음 |
| 재생 상태 | 재생/정지/구간·배속/자막 선택 후 상태·시간이 일치, 새 버전 선택 시 이전 완료·분석 결과 재사용 없음 |
| 실제 AI 정제 | 새 실제 음원을 STT에 보내고 결과를 GPT 정제에 연결. 호출 종류·모델·실행시각·실패·비용 증거 분리 |
| 핵심 추출 | CASE1 상품별 quantity/unit=null·추측 보존·위치/ETA 요청. CASE2 주문18EA와 수령진술1BOX·상담원오청 구분·두 처리 요청 |
| 사람 확인 | AI 제안·원문·사람 수정 구분, 센터가 최종 회신. 음원 교체가 사람 확인을 생략시키지 않음 |
| 접근성·화면 | 키보드 조작·초점·자막 가독성, 390/768/1440px에서 겹침/가로넘침 없음. 실제 실행한 폭만 기록 |
| 동일 릴리스 시나리오 | 두 업무 흐름 각 3회 총6회, 동일 코드·원고·음원 버전으로 전체 검증 |

테스트용 replay/mock 정제 성공과 실제 STT/GPT 호출 성공을 별도로 적습니다. 기존 v3 자연재생·예전 고정 빌드6/6·기존32개 평가 결과는 새 음원 시험의 실행 분모가 아닙니다. 기존 회귀 검사는 보존하되 새 음원의 실패를 기존 점수로 가리지 않습니다.

## 실패·복구 시나리오

| 입력/조건 | 기대 동작·검증 |
|---|---|
| 404·전송 중단·잘못된 MIME·디코딩 실패 | 이해 가능한 오류와 재시도 제공. 끝난 통화로 처리하거나 분석을 자동 실행하지 않음 |
| SHA/크기 불일치·다른 케이스 자산 | 등록 음원 검증 실패, 조용히 다른 음원으로 대체하지 않음 |
| 음원 일부 잘림·0초·깨진 타임스탬프 | 후보 등록 실패, 끝부분·경계 오류를 보존하고 재제작 |
| 한 목소리로 두 역할 생성·정정 자동교정 | 후보 FAIL, voice 설정·원고를 확인하고 해당 실패 이력 보존 |
| STT 지연·오류·취소·정제 실패 | 재생 음원·원문·작성 중 사람 입력 보존. 실패를 성공 요약이나 원고 전사로 대신하지 않음 |
| 새 버전 음원 선택·페이지 새로고침 | 이전 자산의 완료·진행률·분석 결과가 새 자산에 붙지 않음 |
| 자동재생 차단·재생 권한 거부 | 직접 재생을 안내하고 사용자 동작 후 복구. 자동재생 성공으로 기록하지 않음 |
| 권리·표시 조건 미확인/불충족 | 후보를 제품/Release에서 채택하지 않음. 공식 경로·다른 적합 후보를 검토 |

각 검사는 정상 대조군, 잘못된 자산 또는 발화의 음성 대조군, 첫/끝/정정 경계, 잘못된 SHA·턴순서·단위·완료상태를 넣은 변이 대조군 중 해당 범위를 포함합니다. 검사기가 변이를 놓쳤다면 검증 범위를 보완하고 그 전 PASS의 한계를 남깁니다. 실행 권한 거부가 있으면 같은 동작을 다른 도구·PC로 우회하지 않고 해당 항목을 NOT_RUN으로 보존합니다.

증거 카드에는 작업 ID, PC·담당자, 코드/원고 SHA, 공급자·모델·2보이스 ID, 생성/다운로드 일시, 호출 수·비용, 공식 사용 조건, 원본·파생본 SHA와 관계, 실제 길이·음향값, 평가자 유형·구간별 의견, 실패·수정·같은 조건 재시험, 미실행 항목을 담습니다. 키·세션쿠키·고객 원문은 공유하지 않습니다.

이 문서 작성 시 G0~G5는 모두 인수 전입니다. 기존 v3의 자연스러움 미통과를 해소하는 기준을 정의했으며, 새 공급자 품질·새 대본 독립 점수·실제 합성·청취·STT·최종 배포가 통과했다고 선언하지 않습니다.
