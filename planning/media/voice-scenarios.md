## 남은 청취·재생 검증 계획

1. 같은 실제 출력장치·OS 앱별 음량에서 1배속, 앱 volume1, unmuted 상태를 먼저 기록한다. 필요하면 사용자가 편안한 청취 음량으로 정한 값을 기록해 v1/v2 비교에 동일하게 적용한다. 자동 브라우저 재생 완료와 사람 청취는 별도 분모다.
2. 대본·정답·AI 분석을 보여주기 전에 점포명, 주문 상품/수량/단위, 받은 상품/수량/단위, 상담원의 초기 기록, 경영주 정정을 받아 적는다. 작성 후 원대본과 대조하며 누락·오류·확신이 없는 답을 그대로 남긴다.
3. CASE1은 계획05시·현재07시, 전체 미수령 진술, 공사 추측, 미확정 도착시각을 구분했는지 확인한다. 점포명이 알아듣기 어렵다면 화면에서 임의 점포로 확정하지 않는다.
4. v1/v2 순서를 교차하고 시도·반복·출력장치·볼륨·정답노출 여부를 기록한다. 첫 청취와 재청취를 같은 분모로 합치지 않는다. 소수 시연 결과를 일반 인식률로 확장하지 않는다.
5. 선택 구간 재생·전체 끝까지 재생·seek로 끝 건너뛰기·mute·0볼륨·배속·404·음원누락·잘못된 시각은 별도 UI 검사로 확인한다. 구간 끝이나 오류가 전체 재생 완료 콜백을 만들면 실패다. 이 문서는 UI검사 PASS 보고가 아니다.

## 추가 생성은 제안 상태

현 단계에서는 v2를 유지하고 기존 구간 재생/출처/비교 UI로 검토를 돕는다. 아직 사람이 특정 발음 실패를 확인하지 않았으므로 재생성 후보를 확정하지 않는다.

후속 청취에서 문제가 재현되면 **실패한 발화만** 후보로 삼는다. 예를 들어 CASE2 발화2의 점포·상품명, 발화4의 단위 정정, 발화7의 오출고 용어 중 실제 실패한 한 발화의 속도 또는 발음 지시 한 조건만 바꿔 비교할 수 있다. 이는 계획이며 실행하지 않았다. 원래 의미·불만·1개→1박스 정정을 삭제하지 않고, 새 대본/지시/모델/음색/속도·SHA를 별도 후보로 기록한다.

필요 입력은 실제 실패 발화와 청취기록, 기준 원본 SHA, 바꿀 한 조건, 후보 수, 승인된 기존 API/예산 원장이다. 후보 수를 N개로 합의하면 예상 TTS 요청은 최대 N회이고, 별도 STT 비교를 승인하면 후보당 추가1회가 필요하다. 모델/단가와 기존 예산을 확인하기 전 달러 비용을 임의 계산하지 않는다. 신규 API 호출·원장 생성·Release·원본 교체는 pc2에서 수행하지 않고 pc1이 채택·공유한다. 현재 작업의 유료 호출은0회다.
