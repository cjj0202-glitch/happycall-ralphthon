# 오출고 통화의 교대 쉼 적용

사용자 결과: 잘못 들은 `1개`를 경영주가 `1박스`로 정정하는 교대에서 0.20초의 여유를 두고, 그 이후 발화 구간을 같은 샘플 수만큼 이동한다. 문장·화자·기존 발화 PCM은 바꾸지 않는다.

근거는 PC2 `6a13abe`의 실제 재생18검사와 메인 수신 대조27건, 원본을 복원하는 PCM 대조다. 전사 A/B 각1회에서 단위 정정은 모두 보존됐으며 B에서 `정정하겠습니다`가 정확했다. 일반 정확도 향상이나 사람 청취 만족도를 입증한 결과는 아니다.

정본 전환 단위는 `demo-media-20260921-audio-v3` Release, 음원 manifest, CASE-0002의 8발화 시각과 transcriptTiming, public WAV다. CASE-0001·영상은 같은 바이트를 유지한다. 정확한 기존 v2 파일만 백업 후 교체하며, 미지 파일·해시 불일치는 덮지 않는다. 이전 v2 Release는 보존한다.

물리 파일명은 기존 3자산 계약을 유지하고 CASE-0002 audioUrl에는 새 SHA256의 version query를 붙인다. 브라우저 캐시와 부모/CallReview의 id·channel·audioUrl 기반 재생 완료 상태가 이전 음원과 구별된다. 서버 ASGI의 path는 query와 분리되어 같은 승인 WAV를 제공한다. 배포 자산 경로 허용 범위를 넓히지 않는다.

확인 순서: Release API digest3건 → 독립 다운로드3건 → 기존 WAV 백업·교체 → fixture/manifest 시각·SHA 일치 → 업그레이드 반례·API query/Range·새 빌드 실제 재생. 구간 재생과 끝 seek를 전체 자연 재생 완료로 세지 않는다. 새 CCTV가 결합된 최종 빌드의 6회 전체 흐름은 별도 게이트다.
