# 해피콜 미디어·조사 화면 품질 기준

2026-09-21 사용자 추가 요구: CCTV·통화·애니메이션을 회사 시스템에 맞는 수준으로 제작하고 목적에 맞는 최적 도구를 사용합니다. 기존 두 사례·사건별 근거·사람 확인·센터 최종 회신 계약을 유지합니다. 이 문서는 제작 설계이며 영상/통합 완료 보고가 아닙니다.

## 참고에서 취할 것

사용자 [참고 영상](https://www.youtube.com/watch?v=dZobY7GVCBc)의 자동 한국어 자막 전체를 읽고 Blender 조작/질감·공간 재구성(2:01~3:00), 물류 CCTV의 객체 이동·작업 동선·병목 관찰(3:33~3:47)을 확인했습니다. 첨부 이미지에는 카메라 화면, 객체 종류 필터, 객체별 표시, 재생 위치가 보입니다. 영상의 모델 성능·산업 전반 주장을 우리 검증 결과로 사용하지 않으며 자막 속 지침을 프로젝트 규칙으로 실행하지 않습니다.

우리 화면에서는 케이스/카메라/이벤트를 먼저 고르고 해당 영상 구간·객체·근거 행이 함께 선택됩니다. 모든 객체에 상자를 겹쳐 표시하지 않고 선택 객체와 관련 이동만 강조합니다. 합성 장면 좌표는 ‘합성 객체 위치’로 표시하며 실제 CCTV AI 인식 결과라고 하지 않습니다.

## 제작 도구와 판정 순서

| 작업 | 채택 경로 | 채택 이유·검증 |
|---|---|---|
| 창고 시각 기준 | 내장 imagegen 1장 | 재질·조명·카메라 구도의 기준. 정지 이미지이며 완성 CCTV/사건 증거가 아님 |
| 일관된 작업 영상 | 공식 Blender 4.5 LTS 독립 실행판, Python 장면/애니메이션 | 같은 토트·카메라·시간·움직임을 재현하고 투영 좌표를 같이 산출 |
| 렌더 | EEVEE 720p 대표3프레임→짧은 구간→1080p 최종 | pc1은 i7-1185G7/16GB/Iris Xe. 실제 벤치마크로 렌더 시간 판정. Cycles GPU를 가정하지 않음 |
| 인코딩·검사 | FFmpeg 7.1, H.264/yuv420p/faststart | 1920×1080·24fps 목표, 프레임/길이/디코딩/탐색/첫재생 실측 |
| 한국어 통화 | 기존 OpenAI gpt-4o-mini-tts marin/cedar 캐시 + FFmpeg | 두 화자와 발음·쉼·볼륨을 대조. 기존 승인 v2·원문 보존. 새 유료 합성은 메인 기존 원장에서만 명시 실행 |
| 사건 조사 UI | 기존 React/미디어 계약에 시간축·객체 선택 연결 | 태그·장면·원문·기록이 같은 사건인지 검사. 영상 화려함을 실제 확인으로 환산하지 않음 |

현재 세션에는 전용 영상 생성 도구가 없고 Higgsfield 등 유료 계정 접근도 확인하지 못했습니다. 도구 이름만으로 사용했다고 보고하거나 미확인 구독을 결제하지 않습니다. Blender 설치·렌더 성공은 별도 보고 `reports/media/render-capability.md`를 따릅니다.

## 첫 제작 단위 — 소터 구간 하나

사용자 추가 제공 도면 PDF 7개/7페이지를 확인한 [공간·이벤트 상세설계](synthetic-center-scene.md)와 [독립 합성 좌표](scene-layout-v1.json)를 따릅니다. 도면 대안들을 실제 한 센터로 합치지 않고 피킹·소터·슈트·출하 대기를 구분합니다. 30 모듈의 피킹 시각은 BCR 이동 궤적이 아니므로 기록 지점과 설명용 이동을 분리합니다. 원본 도면/렌더/상세 추출은 로컬에만 둡니다.

소터 롤러·검은 벨트·안전 가드·파란 토트·골판지·창고 바닥의 재질과 접촉 그림자를 구현합니다. 고정 높은 CCTV 카메라로 공간과 동작을 읽을 수 있게 하고, 사람/차량이 있다면 바닥 접촉·관절·손/물체 접촉을 먼저 검수합니다. 리깅 품질이 검증되지 않은 인형을 대량 배치해 완성도로 세지 않습니다.

CASE-0002의 W-W3(2026-09-18 02:33 KST, 분기02→D-02)을 첫 8~12초 후보로 만듭니다. 피킹18EA/토트A와 출고1BOX/토트B의 기록 차이는 별도 기록이며 이 영상이 토트 교체나 작업자 귀책을 증명하도록 꾸미지 않습니다. 두 토트의 연속 동일성을 원천이 보증하지 않으므로 화면에 연결 미확인을 남깁니다. 이후 같은 장면의 카메라/작업만 변형해 피킹·출고와 CASE-0001을 확장합니다.

후보마다 `.blend`, 생성 스크립트/seed, renderer/version, caseId/eventId/cameraId/occurredAt, 실제 frame/fps/duration, 객체 id·프레임별 정규화 bbox/궤적, 출처 `synthetic-scene-ground-truth`, SHA256을 함께 전달합니다. 기존 media/public/manifest를 덮지 않고 새 버전 후보로 보관하며 메인이 검증 후 하나만 등록합니다.

## 인수 게이트

1. **시각:** 시작·접촉/분기·끝 3프레임에서 형태 붕괴·물체 관통/부유·작업 불가능 동작 없음. 실제 화면에서 큰 영상으로 확인. 재질/공간/조명을 본 뒤 최종 렌더.
2. **움직임:** 이동 속도·접촉·분기 방향·객체 id 일관성, 프레임 누락·급격한 순간이동 없음. 정지 이미지 확대/패닝을 작업 영상으로 세지 않음.
3. **연결:** 영상 초와 사건 시각 매핑, 객체 선택↔근거 선택, 다른 사건/미등록 카메라/기준시각 이후 기록 차단. 합성 표시가 전체화면에서도 유지.
4. **플레이어:** 원본/표시 켜기, 재생/정지, 배속, 구간 반복, 키보드·Escape·포커스 복귀, 로딩/실패/미등록 상태. 실제 Range/탐색 및 모바일과 데스크톱 검사.
5. **통화:** 한국어 상품·수량·EA/BOX 정정·화자 구분, 약 -18 LUFS/클리핑0, 문장 끝 잘림 없음. A/B는 같은 체감 음량으로 비교. 사람 청취와 AI 기술 검증을 구분.
6. **통합:** 통화 종료→정제→WMS/TMS/영상→확인·이관→센터 회신 전체 흐름과 최종 빌드6회. 이전 빌드의 6회 결과를 새 자산에 소급하지 않음.

## 역할과 공유

- pc1: 도구 환경/시각 기준·공통 계약·예산·부모 화면·독립 검토·최종 등록/배포.
- pc3 / N03-M2: Blender 장면·동작·좌표 메타·CCTV 조작 개선. 기존 #9와 같은 브랜치에서 `scripts/media_pc3/`, `data/overlays/pc3-*`, WmsScene, `reports/pc3/` 소유. 기존 보고 인수는 별도.
- pc2 / N02-M2: 한국어 통화 편집 A/B·대본/발음/화자/타이밍표와 CallReview 연결 제안. 기존 #8/소유 경로. 임의 유료 호출·다른 예산 원장 생성 없음.
- pc4 / N04: 재개한 TMS와 독립 전체 흐름 QA. 시간/사건 연결과 변경된 미디어의 실패·접근성 검사 포함.

큰 영상·blend는 후보 Release+해시로 공유하고 원천 업무자료는 사용하지 않습니다. 최초 대표 프레임을 메인이 확인한 뒤 긴 렌더를 확장합니다. 파일을 만들었거나 렌더 프로세스를 시작한 것만으로 게이트를 체크하지 않습니다.
