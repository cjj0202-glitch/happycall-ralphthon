## 이번에 바꾸는 것

기존 원고는 두 통 모두 8턴이고, 상담원의 접수·이관 설명에 업무 보고서 표현이 많았습니다. 이번 후보는 두 통 모두 14턴으로 나누어 **불편 제기 → 한 번에 한 질문 → 반응·정정 → 재확인 → 확인 가능한 범위와 후속 안내**로 전개합니다. 예상 목표는 60~90초지만 실제 길이는 TTS 이후 측정합니다. 길이만 맞추려고 침묵·동의·사과를 덧붙이지 않습니다.

- “미도착으로 접수하겠습니다” 대신 “오늘 배송을 통째로 못 받으신 거군요”로 실제 들은 내용을 되짚습니다.

- 오출고의 오류는 **상담원 1개 오청 → 경영주 1박스 정정 → 상담원 인정**입니다. 경영주가 자기 수량을 번복한 이야기로 바꾸지 않습니다.

## 목소리와 편집 지시

상담원은 낮거나 중간 음역의 차분한 업무 말투, 경영주는 상담원과 명확히 구분되는 음색으로 선택합니다. 성별 고정이나 실제 인물 복제는 요구하지 않습니다. 두 화자 모두 광고·뉴스 앵커·동화 읽기·성우의 과장된 분노를 피합니다. 감정은 작은 속도·문장 끝 억양 차이로 표현합니다.

- 상담원은 매번 같은 높이로 문장을 끝내지 않습니다. 확인 질문에서만 자연스럽게 높아집니다.
- 경영주는 긴 불만을 한 호흡으로 낭독하지 않고 의미 단위로 나누되, “어… 그…”를 기계적으로 삽입하지 않습니다.
- W03의 상담원 오청 “한 개”를 TTS가 문맥에 맞춰 “한 박스”로 고치면 실패입니다.
- W04의 “한 개가 아니라 한 박스요”에서 부정과 박스 단위가 모두 들려야 합니다. 한 개/한 박스 사이를 효과음이나 교차 재생으로 가리지 않습니다.
- `pauseAfterMs` 120~450ms는 초기 조립 제안입니다. 공급자 자체 말미 쉼까지 더해 실제로 지나치게 길어지면 실측 후 줄입니다. 350ms 고정 간격을 모든 턴에 일괄 적용하지 않습니다.
- 배경 음악·전화 연결음·과장된 노이즈를 넣지 않습니다. 음색의 어색함을 전화 필터로 감추지 않습니다.
- 합성임은 플레이어와 화면에 표시하고 통화 안에 “이것은 합성 시연입니다” 소개를 넣지 않습니다.

## 짧은 비교 시연

전체 두 통을 먼저 만들기보다 국내 공급자 후보의 공식 라이선스·접근·비용을 확인한 뒤 **같은 원고·유사한 체감 음량**으로 아래 고정 구간을 비교합니다. 도구 브랜드가 한국 기업이라는 이유만으로 자연스러움 통과를 주지 않습니다.

| 비교 | 사용 턴 | 보는 것 | 길이 |
|---|---|---|---|
| 불확실성 응대 | M06~M09, 4턴 | 추측의 억양, 질문과 대답 연결, 업무 말투 | 합성 후 측정 |
| 단위 정정 | W02~W07, 6턴 | 두 화자 구분, 18개·1개·1박스, 오청과 정정, 불만의 절제 | 합성 후 측정 |

A/B는 같은 대본을 사용해야 목소리 차이를 비교할 수 있습니다. 대본까지 동시에 바꾼 기존 v3 대 v4 비교는 “전체 시연 선호”로 따로 기록하고, 공급자 효과만으로 해석하지 않습니다. 사용자 청취 의견이 오기 전에도 제작·기술 검증은 진행할 수 있으나 사람 청취의 빈칸을 AI가 채우지 않습니다.

## 대본 품질 기준

먼저 사실 보존 필수 게이트를 모두 확인합니다. 하나라도 실패하면 주관적 자연스러움 점수가 높아도 대본을 채택하지 않습니다.

1. 위 16개 사실이 모두 해당 턴에 남아 있고, 원본에 없는 운영 사실·수량·단위·개인정보·ETA·보상 약속이 0건입니다.
2. CASE2 오청 발화자는 상담원, 정정 발화자는 경영주입니다. 주문과 수령, EA와 BOX를 구분합니다.
3. 미도착 수량·단위 null, 공사 추측, 확인 전 도착 시각 미정, 센터 최종 안내를 보존합니다.
4. 대본·발음 원고의 의미가 같고, 두 화자·28턴·안내 지시 비낭독이 지켜집니다.
5. 실제 합성·청취·STT·통합 검증 미실행을 통과로 기록하지 않습니다.

독립 대본 검토자는 다음 다섯 축을 0~4점으로 평가하고 **정확한 턴과 개선 이유**를 남깁니다. 후보 채택 문턱은 각 축 3점 이상, 합계 17/20 이상입니다. 이는 내부 대본 편집 기준이며 대회 예상 점수나 사람 만족도가 아닙니다.

| 축 | 질문 |
|---|---|
| 업무 대화의 자연스러움 | 질문·반응이 앞말에 이어지고 입력 항목 낭독처럼 느껴지지 않는가? |
| 불만과 응대의 현실성 | 불만은 남고 과한 연기·새 욕설·장황한 사과는 없는가? |
| 정정의 이해 가능성 | 틀린 말·바로잡는 말·재확인을 한 번에 구별할 수 있는가? |
| 필요한 정보의 밀도 | 길이를 채우는 문장 없이 업무 요청이 남는가? |
| 발음용 원고의 충실성 | 수량·단위·점포·부정·추측의 의미가 일치하는가? |

0점은 의미 훼손·사실 오류, 1점은 여러 곳 재작성, 2점은 명확한 개선 필요, 3점은 대본 사용 가능하나 음성 확인 필요, 4점은 독립 검토자가 강점과 남는 한계를 구체적으로 확인한 경우입니다. **현재 점수는 미부여이며 독립 검토·사람 청취·실제 STT 모두 NOT_RUN입니다.** 대본 작가의 자체 확인을 독립 채점으로 세지 않습니다.

## 작성자 자체 대조 결과

2026-09-21 pc1에서 Python으로 **구조·참조·표기 대조 150/150**을 확인했습니다. 대상은 두 사례 28턴 전체이며, 기존 fixture SHA·점포/기준시각, 원고/발음용 숫자 변환, MD/JSON 28턴 일치, 16개 사실의 턴·원본 JSON Pointer, 비교 구간, 미측정 타임라인·미선정 목소리·미실행 검증 표기를 대조했습니다. 이 수치는 자연스러움 150회 시험이나 실제 음성 검증 결과가 아닙니다.

작성자의 의미 대조에서 16개 보존 사실은 모두 대응 턴을 가지며, 새로운 상품·수량·운영 시각·원인·개인정보·확정 ETA·보상 약속을 추가하지 않았습니다. 새로 넣은 것은 추측 확인, 즉시 답을 받을 수 있는지의 반문, 상담원의 오류 인정과 재확인 같은 대화 연결입니다. 이는 독립 검토 전 자체 판단입니다. 발음용 표기 변경은 **6턴**, 두 통의 발음용 길이는 **522자/583자**입니다. 초안 보고에서 발음 표기 변경을 7턴이라고 전달한 것은 6턴으로 정정했습니다.

잔여 판단은 실제 음색·억양·속도·쉼과 두 사람의 자연스러운 주고받음입니다. 국내 TTS 합성과 독립 청취 이전에는 이 대본의 최종 품질 점수를 부여하지 않습니다.

## 채택 전에 필요한 연결 작업

이 파일은 원고만 작성합니다. 기존 fixture·음원·manifest·고정 32개 AI 평가 원본은 수정하지 않았습니다.

- 새 원고는 14턴씩 총 28턴입니다. 기존 `scripts/generate_demo_audio.py`는 **전체 16턴**까지만 허용하므로 그대로 실행하면 실패합니다. 보호 한도만 풀어 유료 28호출을 만드는 것이 아니라 새 공급자 어댑터, 합성 단위, 최대 호출 수, 기존 공유 예산을 메인이 먼저 정해야 합니다.
- 새 음원은 별도 후보 버전으로 만들고 공급자·모델·voice ID·지원 언어·라이선스·합성 요청 값·원고 해시·실측 길이·PCM/인코딩·음량·SHA256을 기록합니다. 이 대본에는 목소리를 선정했다고 쓰지 않습니다.
- 자막은 새 음원의 실제 턴 경계로 다시 만듭니다. 기존 8턴 타임스탬프와 “발화 4”, “발화 3~5” 참조를 재사용하지 않습니다.
- 채택 시 정본 `data/fixtures/cases.json`과 화면 사본 `apps/web/public/cases.json`, 음원 버전 URL·manifest·타임라인을 함께 갱신하고 서로 같은 원고·음원을 가리키는지 검증합니다.
- 저장된 replay 설명에 발화 번호가 있다면 새 M06~M09, W03~W05와 맞게 별도 수정합니다. 고정 32개 평가 원본은 그대로 유지하고 새 음원 시험을 추가 증거로 남깁니다.
- 실제 STT에는 WAV만 보내며 대본을 전사 결과로 대신 표시하지 않습니다. 음원 교체 뒤 자연 재생 종료→정제→사람 확인→센터 이관·회신 흐름을 새 버전으로 다시 검증합니다.
