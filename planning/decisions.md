### DEC-001 — 첫 사용자와 협업자

- 일자 / 단계: 2026-09-21 KST / B01 일부 결정.
- 결정: 첫 사용자는 점포 문의를 받는 상담 담당자이며, 센터 담당자는 확인·이관을 받는 협업자로 둔다.
- 근거·결정자: 현재 메인 대화의 사용자 직접 지시 “첫 사용자를 점포 문의를 받는 상담 담당자로 두고, 센터 담당자는 확인·이관을 받는 협업자로 두는 안으로 진행해.”
- 실제 의견: 메인 사용자 진행 결정 1건. 나머지 세 사람의 개별 의견은 미수집이며 4인 전원 동의로 기록하지 않는다. 전달받은 GitHub 계정과 사람·PC의 대응도 아직 미확인이다.
- AI 추천 이유: 문의 접수부터 근거 확인·답변/이관까지 하나의 상담 업무 흐름으로 설계할 수 있다. 이는 AI의 설계 근거이며 사람의 발언이 아니다.
- 대안: 센터 담당자를 첫 사용자로 두는 안은 이번 선택에서 채택하지 않았다. 사용자에게서 별도의 기각 사유는 받지 않았다.
- 반영: docs/03_목표와_범위.md, planning/solution-map.md. 관련 작업 B01은 업무 종료 상태·측정 기준·실제 팀 의견 등이 남아 있어 미완료로 유지한다.
- 후속 결정: 역할과 이번 핵심 흐름은 DEC-002로 구체화했다. 문의 한 건의 정확한 종료 상태, 첫 Bolt 병목과 성공 기준, PC별 역할은 남아 있다.
- 다시 열 조건: 실제 상담 담당자 관찰에서 주요 병목이 센터 업무에 있거나 팀이 주사용자 변경을 요청할 때.

### DEC-002 — 경영주부터 시작하는 여정과 두 문의 유형

- 일자 / 단계 / 선행: 2026-09-21 KST / B01·B02 일부 결정 / DEC-001.
- 결정: 경영주가 필요한 내용을 말하며 문의를 시작한다. 상담 담당자는 문의 접수 → 근거 조회 → 사실관계 구분 → 답변 초안 작성 → 담당자 확인 및 이관의 흐름을 수행한다. 센터 담당자는 확인·이관 협업자다.
- 이번 범위: 빠른 목업 제작과 WMS·TMS 근거 연결 시연을 위해 미도착·오출고 두 유형을 우선 구현하며, 다른 문의 유형은 후속 확장으로 보존한다.
- 출처·결정자: 메인 대화 사용자가 전달한 토론 내용과 “일단 이렇게 진행하자”, 이어진 “의사결정은 되었으니까 이제 계속 진행해 봐”. 토론 속 발언자의 개인 신원은 제공되지 않아 계정별 동의로 배분하지 않는다.
- 이유: 사용자 발언상 빠른 제작, WMS·TMS까지 연결해 보여주기 적합한 유형, 이후 유형 추가 가능성.
- 경계: 경영주가 여정의 시작점이라는 결정은 별도 경영주 앱·실시간 통화 시스템의 채택을 뜻하지 않는다. 기존 합성 데이터 목업 기준을 유지하며 실제 회사 WMS·TMS 연결 완료로 표현하지 않는다.
- 반영: docs/03, planning/solution-map.md, planning/features.md, planning/product-prompt.md. 범위 결정은 기능 구현 완료와 구분한다.
- 미결정: 경영주 문의의 시연 입력 방식, 첫 Bolt 과업·판정 기준, 담당자 확인/이관의 저장·종료 조건, 실제 팀원별 의견·PC 역할.
- 다시 열 조건: 첫 사용자 실험에서 다른 유형의 우선 필요가 확인되거나 남은 시간·데이터 계약상 두 흐름 완주가 어려울 때.

### DEC-003 — 통화 인식·스크립트 활용 요구 추가

- 일자 / 선행: 2026-09-21 KST / DEC-002.
- 사용자 요청: 기존 목업을 참고해 통화 내용을 AI가 인식하고 스크립트를 표시하며, 그 스크립트를 활용하는 기능도 포함해야 한다. 앞선 First Bolt 질문에 이 단계가 빠졌다는 지적을 반영한다.
- 확인: 참고 HTML의 CALL_SCRIPT, renderCallCenterRight, initCallPlayer는 고정 발화·필드·추천 질문·제목을 타이머로 표시하고 필드와 근거 발화를 연결한다. 실제 음성 인식·생성 모델 구현으로 보지 않는다. 브라우저 렌더 확인은 로컬 URL 정책 차단으로 미실시다.
- 결정 범위: 통화 인식과 스크립트 활용을 설계 요구로 추가한다. 실제 STT의 이번 필수 구현 여부, 실시간/녹음 방식, 질문 추천·수정의 상세, API 권한·예산은 미결정이다.
- 반영: planning/product-prompt.md, planning/features.md. 기존 실제 STT P1 제안은 재검토 대상으로 표시한다. TODO나 제품 구현을 완료 처리하지 않는다.
- 출처: 메인 사용자 직접 요청. 팀원별 의견은 별도 미수집.

### DEC-004 — WMS 작업·소터 이동과 TMS 배송 이력

- 일자 / 선행: 2026-09-21 KST / DEC-002·003.
- 사용자 요구: 해피콜에 WMS·TMS를 연동해 피킹 과정, 소터 탑승/이동의 시각과 경로, 배송 도착 시각과 배송 루트를 보여주는 기능을 고려한다.
- 해석 경계: 조회 기능을 설계 요구로 반영한다. 실 회사 시스템 접속, 장비 제어, 실시간 위치 추적까지 승인·구현된 것으로 해석하지 않는다. 기존 합성 목업 범위는 유지한다.
- 확인 근거: hackathon-ai-kit/scripts/gen_fake_data.py의 build_wms_lines와 22개 테이블 컬럼 정의, data/seed의 실제 헤더·표본. 피킹·출고·배송 계획/실적은 존재하고 소터 투입·통과·분기 이벤트는 별도 보완 대상이다.
- 미결정: 작업 상태·피킹 방식·소터 이벤트 상세, 화면 표현과 갱신 방식, 연결 키 계약. 기존 피킹 스캔만으로 작업 시작·완료 전체를 추정하지 않는다.
- 반영: planning/product-prompt.md, planning/features.md, docs/04_제품_상세설계.md. 제품 구현·계약 고정·테스트 완료는 아니다.
- 출처·결정자: 메인 사용자 직접 요구. 구현 순서와 작업표 의존성은 계약 확정 후 갱신한다.

### DEC-005 — 상담원 보조 AI와 접수 정제·이관 정확성

- 일자 / 선행: 2026-09-21 KST / DEC-003·004.
- 결정: 경영주와는 상담원이 통화하고 AI는 대화록·추가 질문·접수서를 보조한다.
- 목적: 경영주의 욕설·문맥에서 벗어난 발언과 상담원의 휴먼 에러를 고려해 내용을 정제하고, 더 정확한 입력과 부서 이관을 지원한다.
- 출처·결정자: 메인 사용자 직접 응답. 실제 팀원별 의견을 임의로 배분하지 않는다.
- AI 설계안: 원문/정제본/확정본 구분, 의미 보존, 누락·모순·입력 불일치 표시, 근거 발화 연결, 이관 부서 추천 이유와 사람 확인. 각 세부 항목은 사용자 발언 자체나 구현 완료로 기록하지 않는다.
- 후속: 결과 제공 시점은 DEC-006에서 통화 종료 후로 결정했다. 입력·인식 방식, 부서 분류 기준, 불확실할 때의 처리·이관 정책, 첫 Bolt와 성공 기준은 남아 있다.
- 반영: planning/product-prompt.md, planning/features.md, docs/04_제품_상세설계.md. 기존 근거 조회 중심 Bolt 추천을 자동 확정하지 않는다.

### DEC-006 — AI 결과는 통화 종료 후 제공

- 일자 / 선행: 2026-09-21 KST / DEC-005.
- 결정·출처: 메인 사용자 직접 응답 “통화 중에 바로 제공하는 것보다는 통화가 종료되고 제공을 해주는 게 맞는 것 같아요.”
- 적용: 상담 종료 후 대화록·정제 내용·접수서 초안·오류/누락 표시·이관 추천을 제공한다. 앞선 AI의 통화 중 실시간 추천안은 채택하지 않는다.
- 추가 질문의 의미: 통화 후 재확인이 필요한 정보와 확인 질문으로 제안한다. 자동 재통화나 메시지 발송까지 승인된 것은 아니다.
- 남은 상세: 녹음 입력·실제 STT/API, 처리 대기·실패·재시도, 미확인 항목이 남은 상태의 접수·이관 정책.
- 반영: planning/product-prompt.md, planning/features.md, docs/04_제품_상세설계.md. 구현·실험 완료는 아니다.

### DEC-007 — 해피콜 사이트 텍스트 인입 사례 추가

- 일자 / 선행: 2026-09-21 KST / DEC-002·005·006.
- 결정·출처: 메인 사용자가 음성 외에 해피콜 사이트로 텍스트 인입되는 경우도 예시에 포함하도록 요청했다.
- 적용: 통화/사이트 텍스트 두 접수 경로를 다룬다. 미도착/오출고라는 문의 유형과 구분한다. 통화는 종료 후 제공 원칙을 유지하며 사이트 접수는 제출된 글의 정제·구조화로 공통 처리 흐름에 합류한다.
- AI 설계안: 제목·본문·원문 필드 보존, 원문 문장과 추출 항목 연결, 두 경로에 공통 누락·모순 검증, 사이트 오출고 예시 추가. 예시 유형 배정과 데이터 계약은 상세 조정 가능하다.
- 경계: 실제 사이트 자동 수집·외부 쓰기·새 경영주 앱 전체 구현을 완료하거나 승인된 것으로 확대하지 않는다.
- 반영: planning/product-prompt.md, planning/post-call-demo.md, planning/features.md, docs/04_제품_상세설계.md. 기존 두 통화 예시를 텍스트 예시로 대체하지 않는다.

### DEC-008 — 미확인 사실은 확인 요청으로 이관, 대상 불명확은 대기

- 일자 / 선행: 2026-09-21 KST / DEC-005~007.
- 결정·출처: 사용자가 직전 제안의 접수·이관 기준에 “그 기준으로 진행을 해줘”라고 응답했다.
- 채택 기준: 점포·문의 대상·담당 부서가 식별되면 미확인 사실은 확인 요청사항으로 명시해 이관할 수 있다. 점포나 문의 대상이 불명확하면 접수 확인 대기로 남긴다.
- 구현상 구체화: 필수 대상 키는 문의 유형별로 정한다. 배송 전체 문의에 상품코드를 무조건 요구하지 않는다. 부서 미식별도 이관 불가 사유다. 상담원의 내용·부서 확인 절차는 유지한다.
- 상태 구분: 이관 완료와 물류 사실 확인·문제 해결을 구분한다. 미확인 상태를 지워 이관하거나 원인을 자동 확정하지 않는다.
- 반영: planning/product-prompt.md, planning/post-call-demo.md, docs/04_제품_상세설계.md. 필수 키·상태 계약·반례 검사는 P02/P03에서 고정한다.

### DEC-009 — 센터 담당자가 최종 회신

- 일자 / 선행: 2026-09-21 KST / DEC-001·002·008.
