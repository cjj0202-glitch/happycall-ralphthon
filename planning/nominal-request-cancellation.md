# 명사형 정보 문의와 별도 취소 요청

2026-09-22 pc1 · 기준 `da33d4dfd72b59aa1301d9ed97f713c2f43dc44e`

## 사용자 결과와 좁은 범위

웹 접수와 통화 정제에서 `배송 시각 안내 요청입니다. 배송 상품 반송 요청은 취소합니다.`의 첫 요청을 원문 그대로 보존합니다. 현재 명령형 `배송 시각을 알려 주세요.`는 유지되지만, 같은 정보 문의의 명사형이 비워지는 P2를 수정합니다. 요청 없는 내용을 채우거나 취소한 물류행위를 다시 활성화하지 않습니다.

BMAD 관점: 상담원이 필요한 요청을 다시 입력하는 누락을 줄이고, 원문·AI 추가질문·사람 확인을 유지합니다. API/스키마/화면은 그대로이며 `current_request_quote`의 제한적 취소 비교만 바꿉니다. Grill-me 결정은 기존 승인 계약(고객 원문 요청과 AI 제안 분리)으로 해결되어 같은 질문을 다시 하지 않습니다. 작은 Bolt는 명령형/명사형 표현 한 차이를 관측하고, 동일 정상·취소 입력으로 재시험하는 단위입니다. 사람 사용성 관찰을 수행한 것은 아닙니다.

## 상태 계약

- 정보 대상은 기존 단순 명사구 `배송/출고 시각/시간/일정`, `상품 라벨`, `주문 내역`만 사용합니다. 앞뒤 수식절·동사형 행위·복합 요청을 허용하는 식으로 넓히지 않습니다.
- 정보 문의에 명시된 현재형 `안내/확인 요청입니다` 종결을 허용합니다. 기존 명령형 전체문장 조건은 유지합니다.
- 별도 물류행위도 기존 반송/반품/회송/교환/재배송 및 방법/절차 범위 안에서 같은 명사형 종결을 인식합니다. 연속된 두 명사형 요청 다음 `그 요청`은 가장 가까운 요청에만 적용되는 기존 계약을 유지합니다.
- 조사·결합형 `시각과`, `라벨도`가 같은 정보 대상을 가리는 기존 P1이 확인됐습니다. 별도 문의 예외를 허용할 때 기존 정보명사5개의 원문 포함 여부를 보수적으로 확인합니다. 명사형 작업 추가분은 `배송/출고/주문`과 `상품`의 선택적 접두 명사구만 포함한 전체 문자열을 검사하여 과거 인용·복합 요청의 말미만 맞는 경우를 통과시키지 않습니다.
- 동일 대상·부분 대상·포괄 취소, 의존된 시간/절차 문의, 과거 전달·요청 예정·부정·화자 경계·복합 인용은 기존 보수적 처리를 유지합니다. 불용어 교집합 전체를 완화하거나 동의어 사전을 늘리지 않습니다.
- 원문이 없으면 null이고, 반환값은 원문 인용 또는 null입니다. 스키마·수량·단위·AI 확인질문을 변경하지 않습니다.

## 소유와 검증

pc1이 `server/request_grounding.py`, `tests/test_request_grounding.py`, 이 설계 및 새 검증 보고를 소유합니다. 읽기 전용 보조가 현행·메모리 후보를 독립 합성 입력으로 대조합니다. 다른 PC 소유 파일·기존 보고·원응답·키·원장을 수정하지 않습니다.

먼저 명사형 정보문의 4종 이상과 양쪽 명사형+최근요청 취소를 실패시킵니다. 명시 같은/부분 취소, 작업 의존 수식어, 과거/예정/부정·예문·조건, 같은/다른/없는 화자 경계를 음성 대조로 함께 고정합니다. 유지/차단을 각각 뒤집는 변이가 assertion 실패를 내야 합니다. 실제 normalize_analysis 경로와 관련 분석 회귀를 실행하며 모델 호출은0입니다. 수정된 제품 SHA를 별도 검토하고, 실행 API 적용·실모델 효과·전체 UI·사람 검증을 완료로 쓰지 않습니다.

이 변경은 서버 코드만 바꿉니다. 기존 frontend 지문이 동일하면 검증된 정적 출력으로 새 묶음을 만들 수 있으며 불필요한 프런트 재빌드는 하지 않습니다. 배포/권한 상태는 별도 실제 관측을 따릅니다.
