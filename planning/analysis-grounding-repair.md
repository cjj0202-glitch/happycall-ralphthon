## 관측과 원인

실제 고정 평가 실행 `20260921T112012Z-62da8e1711`의 원응답과 최종 결과를 대조했습니다. 긍정 주문 인용 뒤의 수령량 ‘못 셈’이 문장 전체 부정 검사에 걸렸고, 인용 존재만 검사하여 인용에 없는 주문 수량과 과거 단위가 통과했습니다. 생성된 미확인 목록도 별도 검증 없이 남아 명시 수령과 충돌했습니다.

## 수정 계약

- `server/live.py`는 기존 공개 분석 스키마와 예산·호출 흐름을 유지합니다. `server/claim_grounding.py`는 인용 내 값의 지지를 검사하는 순수 함수만 둡니다.
- 긍정 주문과 수령의 연결절을 구분합니다. 주문 구문의 부정·조건·인용은 계속 거부하지만 뒤 수령절의 불확실성으로 앞 주문을 지우지 않습니다.
- 수량·단위는 해당 인용의 같은 주문/수령 절과 시점에서 명시된 토큰만 지지합니다. 새 값을 추출하여 채우거나 포장입수로 환산하지 않습니다. 명시 0, 단위만 알려진 경우, 수량만 알려진 경우를 보존합니다.
- 같은 숫자라도 다른 역할·상품·시점의 값이면 지지로 사용하지 않습니다. 범위가 모호한 경우 사람 대조 질문을 남깁니다. 숫자가 명시되지 않은 주문 상품 자체는 보존합니다.
- 검증된 수령 수량·단위와 단순 미확인 항목이 충돌하면 ‘진술은 존재하며 실제 인도·기록 일치는 별도 확인’으로 표현합니다. 다른 상품·시점·라벨 귀속 등 불확실성은 삭제하지 않습니다.
- 테스트·제품 코드에서 고정 평가 ID나 전체 입력 문자열을 분기하지 않습니다. 저장 원응답과 원장은 변경하지 않습니다.

## 수용 기준과 검증

1. 독립 새 합성 문장으로 동일 4결함을 먼저 실패시킵니다.
2. 긍정/부정/조건/인용/시간 대비/같은 숫자/포장입수/불명확 상품/0 및 부분 미확인 회귀를 수행합니다.
3. 수정 전후 저장 32응답을 로컬 사본에서 정규화하고 모든 결과의 스키마·수량·단위·변경 필드와 원본 36파일 해시를 대조합니다. 모델 재호출이 아닙니다.
4. 관련 분석 테스트 및 전체 백엔드 테스트를 수행합니다. 새 검사가 약화되면 핵심 회귀가 실패하는지 변이 대조합니다.
5. 원본 보존 여부, 실측 분모, 미검증 의미 정확도와 한국어 표면 검사 한계를 보고서에 남기고 메인이 독립 검토합니다.

## 독립 검토 후 2차 수용 기준

독립 G1~G5를 수정 없이 회귀로 고정했습니다. 기존 네 저장 응답만 좋아진 것은 인수 기준에 부족했습니다. 관형 주문절의 첫 숫자를 수령에 붙이는 새 회귀와 부정·미래·이웃 상품 수량의 기존 안전 공백을 함께 다룹니다.

숫자 선택 이전에 문장 성분을 `역할 → 극성/시점 → 대상 → 수량/단위` 순서로 좁힙니다. 관형 주문의 ‘중/가운데 실제 수령’은 주문 수량과 수령 수량을 별개 절로 분리합니다. 수령 부정·수령 예정·미확인 접속절도 다른 상품의 긍정 수령과 분리합니다. 같은 절의 명시 상품 또는 바로 앞 단일 상품을 받는 명백한 생략 구문에 한해서만 값을 지지합니다. 새 상품명이 있는 절은 앞 상품의 생략으로 취급하지 않습니다.

G3는 옳은 7 EA 보존과 틀린 7 BOX 차단을 동시에 검증합니다. 추가 상품·어미·단위 변형 네 문장도 옳은 값 보존과 이웃 값 차단을 쌍으로 검사합니다. 기존 원응답 32건과 앞선 독립 검토 산출물은 덮어쓰지 않고 새 비교 사본을 만듭니다.
