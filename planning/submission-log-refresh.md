# 최신 실행 로그의 로컬 보존과 제출 후보 정제

2026-09-22 02:55 KST · pc1 · 실제 제출/외부 전송은 별도입니다.

## 사용자 결과와 현재 병목

공식 주요 JSONL 한 개에 실제 Goal·실패·수정·검증 결과가 남아야 합니다. 21시 사본은 이후 제품 작업과 사용자가 제공한 API 키 입력을 포함하지 않습니다. 현재 원본은 265,774,680 bytes 관측으로 HowLong 256MiB 한도에 가깝습니다. 원본은 증거로 보존하고, 외부 공유 불가 값을 검토용 사본에서 명시적으로 가려야 합니다. 분할하거나 이벤트를 제거해 실행 시간을 유리하게 만들지 않습니다.

## 파일·동작 계약

- 명시된 메인 JSONL 한 개만 읽고 시작 시 관측한 바이트 길이까지 새 `.local/` 폴더에 스냅샷을 만듭니다. 마지막 미완성 행은 별도 바이트 수·해시로 기록하고 완료 사건으로 만들지 않습니다. 기존 원본/사본을 덮어쓰지 않습니다.
- 제출 후보는 NOT-APPROVED 이름과 상태를 사용합니다. JSON 객체 개수·순서·키·값 유형·숫자·불리언·null 및 timestamp/ID/role/type/name/model/effort/encrypted_content 같은 사건 식별·실행 정보를 보존합니다. 보호 필드에 의심값이 있어도 몰래 수정하지 않고 별도 미해결로 셉니다.
- 자유 텍스트의 알려진 자격증명 형식, 연락처 후보, 임베디드 미디어는 명시적 마스킹 표식으로 바꿉니다. 기존 내부자료 검토의 원문 leaf 해시를 정책으로 재사용할 수 있지만 값·키·원천 행을 stdout나 공유 보고에 쓰지 않습니다. 동일 문맥의 새 형식이나 자유서술은 자동 안전 판정을 하지 않습니다.
- 위치·종류·원본/후보 leaf SHA·길이와 전후 전체 SHA를 로컬 manifest에 보존합니다. 키 값·발견된 본문·앞뒤 문맥은 기록하지 않습니다. 외부 전송·네트워크 호출·원본 삭제/이동·실행 사건 합성은 없습니다.
- 실제 Goal 호출/응답의 객관적 관계와 원문이 유지되는지 독립 대조합니다. 전체 출력이 정제됐다면 응답 레코드 전체가 동일하다고 표현하지 않습니다.

## 구현과 인수 분리

메인이 최신 스냅샷과 정본 설계를 소유합니다. 도구 구현자는 `scripts/prepare_submission_log.py`, `tests/test_submission_log.py` 및 자체 검증 보고서만 맡고 합성 입력으로 검사합니다. 별도 검토자는 기존 로컬 정제 정책·보호 필드·스냅샷의 구조를 읽어 누락과 원문 노출을 반박합니다. 실제 정제 실행 전 정상·음성·경계·검사기 변이를 검증하고, 실행 뒤 독립 비교기로 보존과 마스킹을 다시 확인합니다.
