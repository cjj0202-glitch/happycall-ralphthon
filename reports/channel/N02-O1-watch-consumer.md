# N02-O1 — 같은 PC의 감시 소비자별 상태 분리

담당 pc2 안영일/MR-A83, 기존 #8, 메인 기준 `37de103d1f69959baca9a19e0b1a9ea679c06e23`. 기존 M5 도구는 신규8파일 범위 인수됐고 실제 WAV 인수는 별도 대기입니다. 실제 pc2 checkout에서 신원을 확인하고 자기 branch를 보존합니다.

## 왜 지금 / 결과

상주 `watch`와 메인 `watch --once`가 모두 `.mailbox_state.<slot>.json`을 갱신합니다. 상주 감시기가 먼저 새 댓글을 반영하면 메인 호출은 무출력이 될 수 있습니다. 실제 pc2/pc3 결과 인지가 늦어진 원인 후보이며, 무출력은 미처리 결과 부재를 증명하지 않습니다. 서로 다른 소비자가 같은 PC의 새 회신을 각각 확인할 수 있어야 합니다.

## 소유와 구현

- 소유: `channel/mail.py`, `tests/test_mail_watch.py`, 새 `reports/pc2/watch-consumer-review.md`만. 상주 프로세스·기존 스냅샷·watch launcher·공용 지침/ops는 수정하지 않습니다.
- `watch --consumer <이름>` 같은 명시 옵션을 추가합니다. 지정한 소비자는 슬롯과 소비자명을 포함한 별도 ignored 스냅샷을 사용합니다. 미지정 기본 경로와 기존 명령 동작을 유지합니다.
- 소비자명은 제한된 짧은 ASCII 이름으로 검증하고 경로·슬래시·상위경로·다른 슬롯 강제 지정에 쓰지 않습니다. `whoami`/계정/수신 라벨은 기존 정본을 유지합니다.
- 탐지일 뿐 처리 완료/ACK가 아니라는 도움말과 한계를 남깁니다. 상주 감시기나 자동화를 새로 띄우지 않습니다. 실제 GitHub 메시지 발송·이슈 종결·스냅샷 삭제를 테스트로 하지 않습니다.

## 실행 / 기대값

자기 checkout에서 `python channel/whoami.py`, GitHub 사용자·HEAD·변경 확인 후 고정 main과 자기 branch의 파일 차이를 먼저 대조합니다. 관련 검사 `python -B -m unittest discover -s tests -p test_mail_watch.py -v`와 실제 CLI `watch --help`를 실행합니다.

처음에는 GitHub 응답을 메모리로 대체하고 임시 디렉터리만 사용합니다. 소비자 A가 먼저 0→1 댓글을 읽어도 B의 0→1이 남아 각각 회신1건을 탐지해야 합니다. 같은 소비자의 재조회는 무출력, 미지정 기존 경로 불변, 잘못된 이름 거절, 다른 슬롯/경로 탈출 차단을 확인합니다. 소비자 분리를 제거한 변이가 최소 한 검사에서 실패해야 합니다. 원격 실제 GitHub 새 댓글을 만들지 않으며 실제 전달/사람 수신 검증으로 보고하지 않습니다.

## 중단 조건 / 인계

기존 변경과 충돌, 신원 불일치, 정책 거부, 외부 쓰기 필요 시 해당 부분을 멈추고 근거를 회신합니다. 우회·강제 pull/reset/stash·새 서버/browser/보안변경 금지. 명시3파일만 커밋하고 자기 branch push/원격SHA 대조 후 #8에 기준/결과SHA, 정상·반례·변이 실측, 한계와 권장 메인 호출 명령을 회신합니다. 첫 결과 목표는 01:30 KST입니다. 메인은 검토 후 실제 소비자 이름을 적용합니다.
