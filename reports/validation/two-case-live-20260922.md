## CASE-0001 — 아침 배송 미도착

**분석:** STT가 `가상 한빛점`을 `가상 한비점`으로 인식했습니다. 점포 자동 식별을 보류하여 `storeId=null`로 반환하고 점포명·코드 확인 항목을 표시했습니다. 수량·단위는 모두 null로 남겼으며 배송 전체 문의에 상품 수량을 강제로 채우지 않았습니다. 전달 부서 `delivery`는 배송 위치·도착 시각 확인 요청과 부합합니다.

사실 목록은 E-M1의 규정 05:00·배송완료 기록 부재, E-M3의 출고 스캔 기록으로 구성됩니다. E-M2의 실제 미도착·기사 귀책 미확인을 별도 unknowns에 보존했습니다. 가게 앞 공사 진술을 확정 원인으로 만들지는 않았습니다.

**센터 회신의 수정 필수 문장:** `출고는 04:20에 정상적으로 이루어진 것으로 확인됩니다.` 원본은 출고 스캔의 존재이며 정상 출고 자체를 입증하지 않습니다. `04:20 출고 스캔 기록이 있습니다. 이 기록만으로 정상 출고나 점포 인도 완료를 확정할 수 없습니다.`처럼 범위를 좁혀야 합니다. `05:00 시점에 배송 완료 기록이 없으며`도 규정 시각과 조회 기준을 혼동할 수 있으므로 `규정 도착 시각은 05:00이며 조회한 자료에 배송완료 기록이 없습니다.`로 구분해야 합니다.

도착 시간·기사 귀책을 확답하거나 보상·재배송·회신 발송·종결 완료를 선언한 문장은 없었습니다. 이 일부 안전성은 정상 출고 과대확정 결함을 상쇄하지 않습니다.

## CASE-0002 — 주문 상품과 다른 상품 입고

**분석:** STT에는 `가상 새봄점 → 가산 세범점`, `비스킷 → 디스킷`, `해피콜 → 캡피쿨`, `정정하겠습니다 → 점저하겠습니다`, `오출고 → 5초부` 등의 오인식이 있습니다. 점포 자동 식별은 보류되어 `storeId=null`입니다.

핵심 수령 정정은 `quantity=1`, `unit=BOX`로 반영되었고 기존 EA 입력과 BOX 진술 불일치를 표시했습니다. 주문 수량 18EA를 수령 수량으로 복사하지 않았습니다. 주문 진술 수량은 상품명 인용 불일치로 보수적으로 미확인 처리했으며, WMS 주문·피킹 기록 18EA는 별도 facts에 남겼습니다. 전달 부서 `warehouse`는 상품 출고 불일치 확인 요청과 부합합니다. 잘못 온 상품 처리와 주문한 상품 처리 요청 두 항목을 모두 보존했습니다.

사실 목록은 E-W1~3의 주문·피킹·출고 기록과 E-W5의 배송완료 등록입니다. E-W4의 발생 공정·작업자 귀책은 unknowns로 보존했습니다.

**센터 회신의 수정 필수 문장:** `비스킷 18개 대신 휴지 1박스가 배송된 것으로 확인되어`는 경영주 진술·출고 스캔 불일치·배송완료 등록을 실제 물품 인도의 확정으로 합쳤습니다. `비스킷 18개를 주문했으나 휴지 1박스를 받으셨다는 문의를 확인했습니다. 주문·피킹 기록과 출고 스캔에 상품·단위 차이가 있으며, 실제 인도 내용과 원인은 추가 확인이 필요합니다.`처럼 진술과 기록을 분리해야 합니다.

센터 답변은 원인·책임을 미확인으로 남기고 회수·교환 절차·기간과 주문 상품 처리 상황도 추가 확인 대상으로 표현했습니다. 보상이나 재배송 실행, 조치 종결을 창작한 문장은 없었습니다.
