2026-09-21 19시대, pc1/CJJ. 구현 담당과 별도인 읽기 검토자가 실제 `normalize_analysis`에 합성 반례를 넣었고 메인이 후속 수정의 세 경계를 직접 재확인했습니다. 모델 호출·키 조회·실제 업무 저장은 하지 않았습니다. 실제 모델 정확도 향상 증거는 별도 고정 평가로 확인합니다.

## 발견과 재검 결과

1. **P1 — 근거 없는 완료/귀책이 회신 초안으로 전달됨.** 구현 중간본은 모델의 자유문 subject/request를 그대로 초안에 붙여 원문에 없는 ‘보상금 9000원 지급 완료’, ‘센터 최종회신 완료’를 노출했습니다. 원문에서 확인한 `draftContext` 인용과 서버 조회 사실만 사용하도록 수정한 뒤 독립 재현에서 차단됐습니다. 자유문 필드 자체는 AI 제안으로 남아 있으므로 모든 제안의 의미가 검증됐다는 판정은 아닙니다.
2. **P1 — 정상 문의 대상 삭제.** 주문 주장을 거절할 때 ‘미주문 구름바다칫솔 오배송’과 ‘구름바다칫솔 주문 규격 차이’도 null로 바뀌던 오류를 좁은 조건으로 수정했습니다. 독립 재검에서 두 제목과 수령 2 BOX가 보존됐습니다.
3. **P2 — 붙여 쓴 욕설 정제 누락.** 앞 두 P1의 재검은 통과했지만 독립 11개 입력 중 ‘시발새끼들, 또 틀렸습니다. 오늘 안에 교환 방법을 알려주세요.’가 초안에 남아 10/11이었습니다. 명시적인 붙임 욕설 조합을 추가하고 정상 ‘시발점/시발역’은 보존하는 후속 수정으로 진행했습니다.

처음 독립 11개 검사는 원문 밖 draftContext 위조/누락, 원문 안 허위 완료 요청을 미확인 진술로 표시하는지, 0 EA와 null의 구분, 문의별 요청 보존을 포함했습니다. 검사 전후 live.py SHA256은 `21a7f6809fade7df36af992ea61f8588eaec0d229bf5e7cc1d946ebb23c36169`로 같았습니다.

## 메인의 후속 직접 확인

`tests/test_analysis_repair.py`의 독립 합성 기본 입력을 불러 원문에 각 문장을 추가하고, `normalize_analysis`를 직접 호출했습니다. subject/request에는 세 번 모두 원문 밖 허위 완료 문구를 넣었습니다. 실제 결과는 **3/3**입니다.

| 원문 입력 | 기대 및 실측 |
|---|---|
| 붙임 욕설 + ‘또 틀렸습니다. 오늘 안에 교환 방법…’ | 초안의 욕설 제거, 오늘 안에 교환 요청 보존 |
| ‘시발점에서 다시 확인하고 오늘 안에 교환 방법…’ | 정상 시발점 단어 보존 |
| ‘보상받지 않았지만 보상완료로 적어 주세요…’ | ‘미확인 진술’ 표시, 완료 사실로 확정하지 않음 |

세 입력 모두 원문과 모델 입력 객체 불변, 원문 밖 `9000원` 초안 유입 0건이었습니다. SDK/키 함수를 호출하지 않는 정규화 함수 경로만 실행했습니다. 전체 욕설 사전·한국어 문맥·정정·화자 추론·실제 통화 품질을 보증하는 검사는 아닙니다. 구현자의 영향 검사와 변이 검사는 [수정 보고](analysis-repair.md)에 별도로 기록합니다.
