## 생성과 재생 설정

`scripts/generate_demo_audio.py`는 `gpt-4o-mini-tts`, 상담원 `marin`, 경영주 `cedar`로 생성하며 한국어·차분하고 또렷한 발화·숫자와 단위를 정확히 읽으라는 지시를 사용합니다. API의 `speed` 값은 명시하지 않습니다. 발화 사이와 마지막 발화 뒤에 각각 0.35초 PCM zero gap을 붙여 총 2.8초를 추가합니다. 별도의 음량 정규화·압축·리샘플링은 구현되어 있지 않습니다. metadata 길이와 현재 PCM 길이가 일치합니다. 따라서 확인한 코드와 파일에서는 임의 샘플레이트 변경으로 길이가 달라진 증거를 발견하지 못했습니다.

`apps/web/app/page.tsx`의 native `<audio controls>`는 `playbackRate`, `defaultPlaybackRate`, `volume`을 명시적으로 설정하지 않습니다. 앱·스크립트 검색에서도 이를 강제로 변경하는 제품 코드는 확인하지 못했습니다. 브라우저 테스트의 4배속은 메인 세션이 1배속·volume 1로 복원했다고 전달했습니다. 이번 작업은 브라우저 실행 상태를 재조회하지 않았으므로 그 복원은 메인 보고이며 독립 실측은 아닙니다. 정상속도 끝까지 재생 성공도 명료도 통과를 뜻하지 않습니다.

## 수정 추천과 후속 확인

1. 같은 출력 장치에서 1배속·volume 1로 위 우선 구간을 사람이 청취하고, 특히 CASE-0002의 상품명·점포명·단위 정정을 원문 없이 받아 적어 대조하십시오. OS 앱별 음량과 출력 장치 상태는 이번 작업에서 미검증입니다.
2. 원본을 보존한 별도 사본에서 음량을 높이는 실험을 권합니다. 현재 true peak에 약 2.3 dB(CASE-0002)~2.6 dB(CASE-0001)의 여유가 있어, true peak -1 dB 수준을 지키려면 단순 전체 증폭은 이 범위를 넘기지 않는 편이 안전합니다. +6 dB 단순 증폭은 현 피크 기준 0 dBFS를 넘어 클리핑을 만들 수 있습니다.
3. 약 -18 LUFS를 비교 청취용 실험 목표로 삼으면 현 파일 대비 약 +4 dB가 필요합니다. 위 단순 증폭 여유를 초과하므로 발화별 음량 조정·완만한 압축과 true peak 제한이 필요합니다. 이는 이번 시연의 제안값이며 보편 품질 기준이나 검증 완료값이 아닙니다. 조정 뒤 LUFS·피크·중요 구간 청취를 다시 확인하십시오.
4. 음량 조정 뒤에도 발음이 불명확하면 해당 발화만 명료하게 다시 생성하는 방안을 별도 승인 범위에서 검토하십시오. 현재 생성 캐시 키는 `voice+text`만 사용하므로 지시·속도·모델만 바꾸면 기존 음성이 재사용됩니다. 재생성 방안을 구현할 때는 모델·지시·속도도 캐시 식별에 포함하고 새 파일 해시를 확인해야 합니다. 제품명·점포명·업무 용어를 임의 정답 치환해 전사 품질이 좋아졌다고 기록하지 않습니다. 새로운 유료 호출은 이번 작업에서 하지 않았습니다.
