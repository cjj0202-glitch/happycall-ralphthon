# N03-M2 선택형 정적 배경 설비 `staging_v1`

**설계 상태: 좌표·추가 범위 확정. 새 환경의 Blender 대표 렌더와 시각 검수는 미실행이다.** root가 인증한 pc1 #9의 2026-09-21 21:00 후속 피드백에서 기존 A/B 6장 렌더 완료와 B 선택을 전달받았다. 그 선택을 새 배경 설비의 승인으로 확장하지 않는다. 이번 추가 장면도 대표 1/133/288 검수가 필요하다.

이번에 직접 읽은 근거는 `origin/main:planning/media/synthetic-center-scene.md`, 현재 `build_scene.py`, `BLENDER.md`이며, `.local/pc3-blender/input/warehouse-look-v1.png`를 이미지로 확인했다. 기준 이미지에서는 성긴 대기 설비, 낮은 적치, 열린 통로와 재질 구분을 참고했다. 실제 회사 도면·치수·설비 수·업무 이동을 가져오지 않았다.

## 보여줄 결과와 변경 경계

- 사용자는 고정 CCTV의 선택 분기 사건을 계속 읽으면서 주변이 합성 물류 공간임을 이해할 수 있어야 한다. 카메라 앞을 소품으로 채우거나 인물·작업·귀책을 만들어 설명하지 않는다.
- 옵션은 `--environment-detail none`(기본값)과 `--environment-detail staging_v1` 두 가지다. `none`은 추가 객체가 없는 기존 장면을 유지한다.
- `staging_v1`은 정적인 빈 롤케이지 2대, 낮은 2단 랙 1개, 그 위의 상자 4개, 얇은 바닥 구역선 1개만 추가한다. 랙·케이지는 소수의 cube/cylinder로 구성하며 촘촘한 wire mesh·사람·자율 이동·확률 배치를 넣지 않는다.
- 기존 geometry·랜덤 소비·재질·조명·카메라·선택 상자 경로·tracked 목록은 변경하지 않는다. 새 객체는 기존 재질을 참조할 뿐 기존 노드를 수정하지 않는다. 환경 옵션은 B look과 독립된 명시적 장면 조건이다.
- 각 객체에 `synthetic=true`, `role='synthetic-environment'`, `businessToteId=null`, `tracked=false`를 남긴다. 업무 토트나 `SYN-VIS-PARCEL02`로 등록하지 않는다. 움직이는 사건 상자의 `businessToteId=null` 계약도 유지한다.

## 확정 배치 — 독립 30×18m, z는 위쪽

| 그룹 | 위치와 크기 | 지지·높이 조건 | 의도 |

| 낮은 2단 랙 | 중심 xy=(18.3,12.4), footprint 3.6×1.0m | 다리 바닥 z=0, 최고 z=1.65, 선반 상단 z=0.22/1.0 | 기존 기둥·분전함과 구분되는 낮은 적치 배경 |

| 케이지 대기 구역선 | 외곽 x=[12.4,16.0], y=[10.2,11.6] | 선폭 0.04, 두께 0.008, 중심 z=0.004 | 얇은 바닥 도색을 단순 geometry로 표현; 업무 구역 확정 증거가 아님 |

롤케이지의 바닥 판은 중심 z=0.16/두께 0.04, 하단·상단 0.14/0.18m다. 바퀴는 반경 0.07m/중심 z=0.07/axis X로 바닥에 닿는다. 4개 세로 기둥의 중심 z=0.85/높이 1.4m, rail 높이는 0.75/1.535m이며 부품 전체의 바깥 경계가 위 footprint와 최고 높이를 넘지 않아야 한다. 바닥 판과 기둥의 소량 겹침은 연결부 삽입이며 부유를 가리는 대안이 아니다.

구역선 중심은 y=10.22/11.58과 x=12.42/15.98로 잡아 선폭을 포함한 외곽이 표의 범위 안에 남도록 한다. 케이지·랙·상자의 표기 footprint는 중심 좌표가 아닌 **실제 부품 전체 AABB의 경계**로 검사한다. 원통은 회전축을 반영한 보수적 AABB를 사용한다. 초기 랙 중심 x=19.5 안은 root의 순수 카메라 투영에서 오른쪽 끝이 약1352px로 1280px 화면을 벗어나, 랙과 상자 전체를 x방향 -1.2m 옮긴 현재 표의 배치로 수정했다. 이 수치는 렌더 픽셀 측정이 아니다.

## 비워둘 영역과 가림 방지 근거

- 기존 conveyor/outfeed와 선택 경로는 그대로다. 선택 상자 중심 경로는 x=10..18.5, y=7.5에서 4.5로 이어진다. 카메라는 (24,1,8), lookAt=(17,7,0.85), lens=32mm다.
- 추가 고형물의 최소 y는 10.5m이며, 바닥선도 y≥10.2m다. 선택 상자 각 꼭짓점과 카메라 사이의 선분은 이 뒤쪽 y 영역에 이르지 않는 배치다. 단, 이 설명을 실행된 광선 검사나 픽셀 가림 검증으로 표시하지 않는다.
- **열린 통로 AABB: x=[10,20.5], y=[8.6,10.2], z=[0,2.2].** 이 공간에 새 고형물이 교차하면 거부한다. 바닥 도색은 물리 장애물 검사에서 제외하되 원래 경계에 있어야 한다. 통로 폭 1.6m는 독립 시연 배치의 선택이며 실제 현장의 법정 안전 규격을 인증하는 값이 아니다.
- 랙 x=[16.5,20.1]/y=[11.9,12.9]m는 기존 (22,13) 기둥과 분리되고, 기존 (21.2,8.7) 분전함 앞에 놓이지 않는다. 롤케이지 두 대 사이의 빈틈은 주 통로라고 주장하지 않는다.
- 모든 추가 물체는 floor x=[0,30], y=[0,18] 내부에 있어야 한다. shadow나 반사는 기존 사건 영상 판독을 방해할 수 있으므로 좌표 검사 이후에도 새 대표 PNG를 확인해야 한다.

## 구현·검증 계약

순수 함수 `environment_specs(name)`은 이름·합성 환경 metadata와 결정적인 `objects` 배열을 반환한다. `none`은 빈 배열, `staging_v1`은 위 배치다. 알 수 없는 이름은 거부한다. 반환값 변이가 후속 호출에 남지 않아야 하며 I/O·Blender import·랜덤·현재시각을 사용하지 않는다.

| 검사 | 기대 | 한계 |
|---|---|---|
| 결정성·기본 호환 | none 추가 수=0, 같은 staging 이름은 동일 값, 기존 장면 설정·경로 불변 | Python 검사만으로 Blender 객체 생성 호환을 증명하지 않는다 |
| 공간·접촉 | 부품 전체가 허용 AABB 내부; wheel/leg bottom=0; 상자 bottom=shelf top | 보수적 원통 AABB는 실제 mesh보다 커 거짓 양성을 만들 수 있다 |
| 통로·선택 상자 | 새 고형물이 통로·288개 pose의 사건 상자와 교차하지 않는다 | 기존 장면 전체의 충돌·현장 안전성 검사와 다르다 |
| 카메라 광선 | 288프레임마다 카메라→상자 8개 corner 선분이 새 prop AABB와 만나지 않는다 | 8개 광선만으로 모든 픽셀 가림이 없음을 일반적으로 증명하지 않는다; 본 배치의 y 분리 근거와 대표 이미지도 대조한다 |
| 대표 이미지 | 같은 B·카메라·32 실효 샘플로 1/133/288을 비교; 사건 상자·분기·가드 접촉·물성이 계속 읽힌다 | 원래 B의 승인이나 이전 PNG는 새 환경의 시각 검사를 대신하지 않는다 |
| 영상 확장 | pc1이 새 대표 장면을 수용한 뒤 같은 설정으로 short 72프레임만 진행 가능 | 288프레임 후보 렌더는 이번 범위에서 금지 |

구현은 n03_media, 순수 좌표·광선·회귀 검사는 handoff_audit, 실제 인수·렌더 지시는 pc1이 맡는다. 이 문서 작성자는 설계와 명령 문서만 수정하며 렌더를 실행하지 않았다. none/staging은 geometry가 다른 두 조건이므로 **동일 geometry A/B 검사기를 이 환경 비교에 억지로 통과시키지 않는다.** 환경별 조건·새 객체 목록·해시를 별도로 기록한다.
