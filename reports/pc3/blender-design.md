## 4. 움직임·프레임·시각 계약

공동 구현 계약은 `evaluate_motion(t_seconds, layout)`의 position `[x,y,surface_z]`, `surface_z=0.85`, seed `20260921`입니다. 첫 분기는 반경 1m의 둥근 코너로 연결하고 yaw는 +x 진행에서 -y 진행까지 연속적으로 전환합니다. 반경과 12초 타이밍은 합성 연출 설계값이며 실제 설비의 반경·속도를 측정한 값이 아닙니다.

| 0≤t<3초 | 직선 접근 | 지지면·객체 ID 유지, 시작 위치/속도 과도 없음 |

## 5. bbox·객체 선택·프레임 metadata

각 프레임에서 애니메이션을 평가한 동일 객체와 **동일 CCTV 카메라**로 투영합니다. 정규화 bbox는 top-left 원점의 `[xmin,ymin,xmax,ymax]`, x/y 범위 0…1로 정의하고 해상도·카메라 ID·frameIndex·t_seconds를 함께 기록합니다. Blender의 카메라 좌표와 화면 y 방향의 차이는 내보내기 단계에서 한 번만 변환합니다.

1. 카메라가 보는 평가된 객체 형상/경계점을 world-space로 변환하고 실제 렌더와 같은 카메라·종횡비로 투영합니다. 객체 origin 한 점이나 평면 overview 좌표를 bbox로 쓰지 않습니다.
2. 카메라 뒤/near-plane 교차·프레임 이탈은 먼저 검출합니다. 잘못된 투영을 0…1로 clamp해서 정상 bbox로 만들지 않습니다. 화면에 잘린 bbox와 원래 투영 bbox가 필요하면 이름을 분리합니다.
3. **전체 형상의 투영 bbox와 실제 보이는 픽셀 bbox는 다릅니다.** 가림이 있으면 visible/occluded/truncated의 판정 근거를 별도로 남깁니다. 실제 마스크·깊이 검사 없이 가림을 검증했다고 표시하지 않습니다.
4. 대표 3프레임에 bbox를 별도 검수 이미지로 그려 원본 프레임과 나란히 대조합니다. 가능한 경우 객체 마스크의 화면 경계와 투영 결과를 비교하고 픽셀 차이·오차 기준을 기록합니다. 색 상자를 모든 사물에 겹치지 않고 선택 객체만 강조합니다.
5. 메타데이터의 동일 `visualObjectId`가 전체 구간을 유지해야 합니다. 업무 토트 연결은 null이며, 움직이는 상자가 피킹 토트A 또는 출고 토트B라고 자동 지정하지 않습니다.

권장 산출 필드는 `frameIndex`, `blenderFrame`, `t_seconds`, `caseId`, `eventId`, `cameraId`, `visualObjectId`, `businessToteId`, `positionWorld`, `yaw`, `bboxNormalized`, `resolution`, `visibilityStatus`, `trackSource`, `synthetic`, `eventOccurredAt`입니다. 가림/투영 검사를 하지 않은 필드는 미확인으로 남깁니다. 실제 렌더 투영을 수행하기 전의 평면 경로 샘플은 bbox 검증 성공이 아닙니다.

| G2 대표 3장 | EEVEE 720p 시작/분기/끝에서 공간·물성·접촉 확인 | 3 PNG, 각각 frame/time/camera·소요시간, bbox 검수 이미지, 원본/수정 비교 | 부유·관통·형태 붕괴·객체 가림·카메라 불일치면 핵심 원인 한 가지 수정 후 같은 3장 재검 | 미렌더 |
| G3 짧은 움직임 | 정지 3장으로 판단할 수 없는 분기·속도·yaw 확인 | 3~6초 구간 72프레임의 실제 렌더/디코딩/연속 재생과 경계 좌표 검사 | 점프·분기 중 지지면 이탈·yaw 뒤집힘·프레임 누락이면 최종 확대 보류 | 미렌더 |
| G4 최종 후보 | 같은 장면·seed·카메라로 1920×1080, 24fps, 12초 확장 | 실제 288프레임·12초, 전 프레임 decode, metadata 288개, H.264/yuv420p/faststart, MP4/SHA | 프레임/시간/객체/카메라/해시 불일치 또는 3프레임 품질 미충족이면 후보 미인수 | 미렌더 |
| G5 실제 재생·연결 | 파일 존재를 사용자 동작 성공으로 오인하지 않음 | 재생·정지·배속·구간 반복·Range/seek·전체화면·Escape/포커스·3폭·실패 복구 | 다른 사건·INT 자동상속·미등록 camera·잘못된 구간이 허용되면 연결 차단 | 미실행 |
| G6 통합 인수 | 새 자산이 전체 시나리오를 깨뜨리지 않음 | 동일 최종 빌드/자산에서 두 사례 각각 3회, 음성→정제→근거→이관→센터 회신 결과 | 이전 빌드 6회 결과를 소급하지 않음. 남은 P0/P1이 있으면 인수하지 않음 | 미실행 |

G3의 3~6초는 반열림 구간 `[3,6)`으로 고정하면 frameIndex `72…143`, Blender `73…144`의 72장입니다. 재생 경계의 앞뒤 운동값은 별도 수치 검사합니다. 최종 G4를 시작하기 전 pc1이 G2/G3 증거를 검토해야 하며, 이 절차는 사용자에게 다시 허가를 요청한다는 뜻이 아닙니다.

First Bolt 기록은 `가설 → 실제 3장/짧은 동작의 관측 → 핵심 수정 1개 → 동일 입력/카메라/프레임 재시험 → 차이·남은 한계`로 작성합니다. 재질과 경로와 카메라를 동시에 바꾼 뒤 어떤 수정이 개선했는지 단정하지 않습니다.

## 7. 성능·실패·pc1 인계

pc3의 초/프레임·전체 소요시간·메모리 사용량은 **미측정**입니다. CPU/GPU 모델명이나 기존 코드 애니메이션 인코딩 시간에서 Blender 성능을 추정하지 않습니다. pc1도 첫 준비·smoke·대표 프레임의 실제 wall time, 해상도, 엔진, 장면 설정을 기록한 뒤 다음 작업 크기를 정합니다. 추정 속도나 1080p 완료 시각을 이 문서에 만들지 않습니다.

root의 `scripts/media_pc3/build_scene.py`는 준비(`--mode prepare`)와 대표 프레임(`--mode representatives`) 실행을 분리합니다. 최종 실행 인자는 실제 `--help`/pc1 환경에 맞춰 인계 기록에서 고정하며, 이 설계 작성자가 CLI 실행·`.blend` 생성에 성공했다고 주장하지 않습니다. pc1은 동일 코드와 입력 사본으로 실행하고 사용한 절대 경로·버전·명령·종료코드·로그·실제 출력 해시를 회신합니다.

인계 묶음에는 아래를 함께 넣습니다.

- 코드 SHA와 생성 스크립트, 입력 JSON/SHA, seed, 설치·실행 전제, 정확한 재현 명령.
- 원천 도면이 들어 있지 않은 `.blend`, 대표 PNG, 실제 생성한 프레임별 메타데이터, 단계별 검사 결과.
- 최종 렌더를 수행했다면 MP4·인코딩 정보·크기·SHA·프레임 수·길이·디코딩 결과. 수행하지 않았다면 해당 칸에 미렌더.
- 후보 파일명과 기존 등록 자산을 구분한 목록. 공용 fixture/manifest/public 및 실제 배포 등록은 pc1이 인수 후 담당.

Blender가 없다는 환경 제약을 숨기기 위해 다른 도구의 결과를 Blender 렌더로 바꾸지 않습니다. 보안/권한 차단을 다른 PC로 우회하지 않으며, 이번 pc1 인계는 확인된 도구 가용성에 따른 승인된 역할 분담입니다. 30분 진전 없음 또는 같은 실패 3회면 원인·실제 출력·독립 진행 항목·도구 대안을 #9의 인계 자료로 정리합니다. 원천·키·원본 로그를 게시하지 않습니다.

## 8. 작성 시점 완료 구분

완료한 것은 정본 4개 문서/JSON의 읽기, 허용된 기준 PNG 관찰, 입력 사본 SHA 확인, 공동 접촉/카메라/대표 프레임 계약의 문서화입니다. 수정 파일은 이 보고서 한 개입니다.

Blender 설치·실행, `.blend` 생성, 대표 3프레임, 짧은 동작, bbox 렌더 대조, 최종 288프레임, MP4 실제 재생, 메인 인수·배포는 **이 설계 작성 작업에서 수행하지 않았습니다**. 실제 실행 결과는 후속 증거로 별도 갱신하며, 문서를 작성했다는 이유로 게이트·작업표·이슈를 완료 처리하지 않습니다.
