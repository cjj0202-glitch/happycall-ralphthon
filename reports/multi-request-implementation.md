## 사용자 결과와 변경

서로 떨어진 단위 정정·수령 상품 처리·주문 상품 처리 요청을 하나의 가짜 연속 인용으로 합치지 않고 각각 검증합니다. 같은 명시 화자의 인접 구간만 원문 공백 하나로 연결하며, 실제 전사·모델 원응답은 수정하지 않습니다. 공개 HTTP의 `fields.request: string|null`은 유지하고 두 개 이상이면 번호와 줄바꿈으로 구분합니다. 회신은 여전히 담당자 검토용 초안입니다.

PC2 독립 입력 `af288becf6e53261c242d8afae3336718b37250b`의 두 원본 파일은 수정하지 않았습니다. 메인이 보수적 정책 8행을 채택한 뒤 구현했습니다.

## 계약과 호환 경계

- raw9개는 자르거나 중복 제거하기 전에 요청 전체를 검토로 남깁니다. 신/구 key 혼용은 빈 신형 배열도 거절합니다. 잘못된 배열/항목 타입도 요청만 검토하며 다른 정상 분석값을 버리지 않습니다.
- 구형 `requestQuote` 한 개는 명시적으로 변환합니다. 신형 배열은 PC2의 보수적인 지시어 모호성 정책을 적용합니다. 구형 저장 응답은 기존 단일 인용의 전체 문맥·최근 지시어 처리 의미를 유지합니다. 명시된 대상 철회는 화자 교대 뒤에도 확인합니다.
- 다른 화자의 취소는 원 요청자의 철회로 확정하지 않습니다. 같은 문자열이 여러 위치에 있으면 발생 위치를 임의 선택하지 않습니다.
- 단위 정정 문맥이 잘린 인용을 자동 확장하거나 그 인용에서 수량/단위를 새로 추출하지 않습니다.
- 출처의 `startChar/endChar`는 Python Unicode code-point, 끝 제외입니다. 원본 segment의 시각을 그대로 보존하며 문자별 시각을 추정하지 않습니다. 정상 인용의 출처는 resolver 결과로 대조하고 기존 UI 문제 목록을 오염시키지 않습니다.
- STT fallback `화자`·unknown·None·빈 라벨은 같은 화자라는 증거가 아니므로 인접 구간을 연결하지 않습니다. A 등의 명시 분리 라벨도 고객 신원 확인을 뜻하지 않습니다.

## 첫 검증에서 드러난 회귀와 보완

메인 환경의 첫 요청 관련 5파일 실행은 **175 PASS /18 FAIL /230 subtests**였습니다. 신규 PC2 31행은 통과했으나, 기존 단일 요청의 지시어 처리와 취소 검사기 변이에서 회귀가 발생했습니다. 구형 단일 인용의 문맥 검사를 보존하는 호환 분기로 수정했습니다. 신형 배열의 R18/R19 기대값은 낮추지 않았습니다.

기존 의미검사 12건은 새 모델 schema를 구형 fixture로 직접 검증하는 setUp에서 실패했습니다. 메인 승인으로 fixture 1행을 신형 배열로 이전했고 구형 normalizer 입력 검사는 별도로 유지했습니다. 원문 가드가 분리되면서 무해해진 기존 변이는 요청 검토 문구를 정확히 분리하여 제목 원문 가드 우회도 기존 검사가 계속 드러내도록 했습니다. 기존 의미·안전·변이 기대값은 수정하지 않았습니다.

## 재현 명령과 최종 검증

하위 에이전트의 venv 실행은 base Python 프로세스 생성 오류로 실패했습니다. 권한을 우회하지 않고 메인이 같은 작업 파일을 실행합니다.

```powershell
$env:PYTHONUTF8 = '1'
.venv/Scripts/python.exe -m pytest -q tests/test_multi_request_provenance.py tests/test_request_grounding.py tests/test_analysis_repair.py tests/test_analysis_grounding_regression.py tests/test_analysis_semantics.py tests/test_receipt_review_guidance.py tests/test_two_flow_asgi_workflow.py
```

메인이 위 7파일을 동일 작업 트리에서 재실행한 초기 결과는 **205 PASS /250 subtests /5 deprecation warnings,7.81초**입니다. PC2 31행의 활성·거절·이유·출처/시각과 HTTP투영, 기존 요청/의미/수량/단위/ASGI 두 흐름 회귀가 이 범위에 포함됩니다. 하위 에이전트의 `git diff --check`도 통과했습니다. 정상 인용 전부 삭제·문맥 검사 전부 허용·후속 철회 무시의 세 변이는 신규 검사가 구별했고, 기존 변이 검사의 기대값도 유지했습니다.

추가 정적 대조에서 같은 segment의 마침표 없는 후속 취소가 문장 시작 위치 때문에 누락될 수 있어 실제 취소 문자의 위치로 수정하고 반례를 추가했습니다. 위 최종 7파일 결과에는 이 반례와 익명 STT 라벨4개 반례가 포함됩니다. 독립 검토·전체 제품 패키징·커밋 인수는 메인이 별도로 수행하며 이 결과는 실모델 정확도·브라우저·배포 성공이 아닙니다.

## 독립 검토 P2 반례와 보완

위 초기 통과 뒤 독립 검토자가 추가로 발견한 반례를 별도로 수정했습니다.

- “반송 방법”과 “교환 방법” 또는 “치약 반송”과 “컵 반송”을 모두 철회하는 오류: 공통어 하나만으로 대상을 확정하지 않도록 양쪽이 명시된 단순 작업·상품을 좁게 구별합니다. 축약 철회 이름과 반송/반품/회송·방법/절차 호환 정책은 유지합니다.
- “저는 ‘반송 방법 요청은 취소합니다’라고 말한 적이 없습니다”를 실제 취소로 처리하는 오류: 인용된 철회문에도 기존 부정/예시/계획 문맥 가드를 적용합니다. 첫 보완 뒤 독립 재검에서 인용 안 마침표 때문에 부정 문맥이 잘리는 경계도 발견하여, `. ! ?` 뒤 닫는 따옴표/라고·라는에 붙은 맥락을 검사하도록 보완했습니다. 구형 단일 계약에도 같은 가드를 적용합니다.
- “한 개가 아니라 한 박스예요. 단위를 기록해 주세요”에서 부사가 없으면 단위 정정 앞 문맥 누락을 허용하는 오류: ‘제대로/정확히’를 필수 조건에서 제거합니다. 원문을 자동 확장하거나 단위를 추출하지 않습니다.
- `화자/unknown/speaker/none` fallback 라벨을 후속 발화의 동일인 증거로 쓰는 오류: 명시 화자가 아닌 라벨의 후속 취소는 확정 철회하지 않고 원요청과 역할·화자 검토 사유를 보존합니다.

첫 P2 보완 뒤 메인 7파일은 **221 PASS /250 subtests /5 deprecation warnings,8.55초**, 독립 재검의 고정14개와 PC2 31행도 통과했습니다. 다만 인용 안 마침표 추가 반례는 그 통과 범위 밖에서 발견되어 다시 보완했습니다.

문장부호 경계를 포함한 고정 반례의 resolver/HTTP projection·신구 계약·화자 교대·인접 구간·부사 변형은 초기 결과보다 총28개 추가했습니다. 기존 PC2 원본31행과 회귀 기대값은 수정하지 않았습니다. 마지막 경계 보완 후 메인 7파일의 **최종 결과는 233 PASS /250 subtests /5 deprecation warnings,9.06초**입니다. 독립 검토자의 마지막 문장부호 경계 재검은 별도 진행 중이며, 구현 파일은 최종 회귀 통과 상태로 동결했습니다.

## 남은 한계

검사는 독립 합성 기대값·작성 모델 대조군이며 실제 STT/모델 재호출이 아닙니다. API/과금 호출과 실제 원장 변경은 없습니다. 이전 pc1의 `.local` 실제 원응답은 이 PC에 수신되지 않았으므로 실제 canary 재처리·새 정확도 평가도 하지 않았습니다. 이전 실제 canary의 12필드 중 **8 PASS /4 FAIL** 기록은 유지합니다.

한국어 의미·철회 대상 판단은 제한된 규칙입니다. 모든 동의어/화자 신원을 판별한다는 보장이 없으며 불명확한 것은 검토로 남깁니다. 같은 현재 요청 원문이 여러 번 등장하면 모두 현재 요청처럼 보여도 발생 위치를 임의 선택하지 않고 `AMBIGUOUS_OCCURRENCE`로 보수적으로 유보합니다. 이는 메인이 유지한 현재 범위의 한계입니다. 제목 손실·수령 근거의 화자 귀속·새 브라우저 전체 흐름·영속 저장·Production·실제 외부 알림·사람 청취는 이번 인수 범위 밖입니다. 커밋·push·이슈 종결은 메인의 독립 검증 뒤에 수행합니다.
