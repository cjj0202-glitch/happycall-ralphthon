## 사용자 과업과 상태

상담원은 draft/review에서 문의 점포의 유효 근거를 연결합니다. 센터 담당자는 이관 후 사건의 배송 순번·시각·GPS·미확인 및 이미 연결된 근거를 조회하지만 연결을 변경하지 않습니다. closed는 처리완료 이유를 표시합니다. 화면 선택은 실제 인증·새 권한을 뜻하지 않습니다.

| 상태 | 조회 | 유효 근거 연결 | 화면 이유 |
|---|---|---|---|
| draft/review 및 기존 status 미지정 | 기존대로 | 기존 관계·선택·pending·중복 조건 모두 충족해야 허용 | 기존 안내 |
| handed_off | 기존대로 | 버튼과 실제 함수 진입 모두 차단 | 센터 전달 · 이관된 접수의 근거는 조회만 할 수 있습니다 |
| in_progress | 기존대로 | 버튼과 실제 함수 진입 모두 차단 | 센터 조사 중 · 이관된 접수의 근거는 조회만 할 수 있습니다 |
| closed | 기존대로 | 버튼과 실제 함수 진입 모두 차단 | 처리완료 · 이관된 접수의 근거는 조회만 할 수 있습니다 |

## 인터페이스와 구현 경계

Props에 backLabel?: string을 추가합니다. 기본값은 상담으로 돌아가기, 메인은 센터 진입 시 센터 업무로 돌아가기를 전달합니다. onBack은 그대로 한 번 호출합니다. status는 기존 CaseData 값만 사용하며 새로운 role/auth 계약은 만들지 않습니다. 상태 전환을 컨텍스트 갱신 대상으로 포함하고 이미 실행된 비동기 요청은 취소됐다고 주장하지 않습니다. 서버의 쓰기 허용 판단·부모 UI 연결은 pc1 범위입니다.

고정 main TmsScene에는 이전 pc4 버전에 없는 ApiError 기반 확정/미확정 실패 구분이 있습니다. main의 이 코드와 CSS를 보존한 상태에서 추가합니다. main 공용 파일은 편집하지 않고 고정 의존 파일의 읽기 전용 사본으로 타입 검사합니다. 기존 pending·busy·연결됨·비교 방문·잘못된 관계 차단을 약화하지 않습니다. 새로운 색·폰트·라이브러리 없이 기존 notice 스타일을 재사용합니다.

## 작은 대조군과 검증

가설: 상태별 실제 함수 진입과 버튼을 함께 차단하면 이관 후에도 근거는 조회되지만 UI 호출로 연결은 쓰이지 않습니다. 수정 전 고정 main의 정상/차단 대조를 먼저 기록합니다.

- draft/review 양성: 정상 근거 버튼 활성, onLinkEvidence 정확히 1회.
- handed_off/in_progress/closed 반례: button.disabled=true, disabled를 무시하고 실제 onClick→link를 호출해도 onLinkEvidence 0회.
- 이전 조건: 비교 방문·타점포·잘못된 관계·중복·pending 중 연결 0회; 이미 연결된 근거와 조회 내용 유지.
- 기본/센터 복귀 문구와 onBack 1회.
- 메모리 소스의 함수/버튼 상태 가드 제거 변이를 각각 검사하여 차단 해제 결함을 검출.
- 순수 TypeScript/JSX 및 고정 main 의존 기준 타입 검사. 실제 UI 클릭·브라우저·서버·소켓·과금·설치·배포는 미실행.

소유: TmsScene.tsx, 필요 시 TmsScene.module.css, 새 tms-role-readonly-unit.mjs, reports/pc4/tms-role-readonly-*. 기존 다른 소유 코드·PDF·중앙 작업표는 변경하지 않습니다. 결과 SHA와 명시 경로·명령·실측·실패/수정·한계를 #10에 제출하고 pc1 독립 인수를 기다립니다.

독립 코드 검토에서 handed_off를 이미 조사 중으로 표시하지 말라는 의견을 반영해 센터 전달/센터 조사 중/처리완료를 구분했습니다. 상태 전환 remount는 선택 방문과 정렬도 초기화하며, 연결 요청 취소나 센터의 실제 조사 착수 증거를 뜻하지 않습니다.
