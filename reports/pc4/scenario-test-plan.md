## 고정 6회와 상태 격리

| 실행 | 고정 입력 | 기대 종료 | 실제 UI 완료 판정 |
|---|---|---|---|
| CALL-1, CALL-2, CALL-3 | CASE-0001 합성 미도착 통화·저장 분석 replay | 수량 null 유지, 사람 검토, 근거 연결, 센터 최종 회신·closed, owner 조회 | 음성 재생·UI 조작·최종 화면을 실행한 경우에만 PASS |

현재 서비스는 신규 텍스트의 저장 분석 replay를 `409 REPLAY_NOT_AVAILABLE`로 거부합니다. 이를 숨은 분석 성공으로 바꾸지 않고 원문 기반 사람 검토·이관 경로를 검사합니다. 따라서 HTTP 상태 흐름 6회가 통과해도 실제 AI 정제·브라우저 6회 완주를 자동 PASS로 기록하지 않습니다.

각 회차는 별도 `TemporaryDirectory`의 새 합성 접수 저장소를 사용합니다. 원본 `.local/cases-store.json`, 예산 원장, fixture를 변경하지 않습니다. 유료 분석기는 실패하는 대조 구현으로 대체하고 외부 socket 접속을 거부합니다. 실제 서버 `server.app.create_app()`의 OpenAPI/handler/service를 고유 loopback 포트 18104에서 호출합니다. 기존 API·감시기·다른 프로세스를 종료하지 않습니다. 서버는 검사 프로그램 자신이 만든 객체만 종료합니다.

시작·종료 HEAD와 검사 대상 API/fixture/page/types의 SHA-256을 기록합니다. 중간 소스 변경이면 동일 릴리스 검사를 통과시키지 않습니다. 결과에는 HTTP 실행/통과/실패, UI 실행/통과/실패/미실행을 별도 분모 6으로 기록합니다.

## 실행과 증거

`python tests/remote/pc4/scenario-check.py --port 18104`로 실행합니다. 기본 결과는 UTC 타임스탬프를 포함한 `reports/pc4/scenario-results-*.json`으로 남기며 기존 결과를 덮어쓰지 않습니다. 실패는 입력·기대·HTTP 상태·오류코드·회차·같은 조건 재검증 경로로 보고합니다. 응답 원문 전체·키·원천자료는 결과에 넣지 않습니다.

첫 Bolt의 병목은 ‘감지·단위 PASS와 실제 사용자 완주가 혼동됨’입니다. HTTP 6회와 UI 6회를 분리해 측정하고, 실제 실행되지 않은 UI/미디어 단계를 표시하는 한 가지 변경을 확인합니다. 발견한 공통 API 결함은 소유자 pc1에게 재현으로 전달하며 이 작업에서 공유 API·fixture·page·types를 수정하지 않습니다.
