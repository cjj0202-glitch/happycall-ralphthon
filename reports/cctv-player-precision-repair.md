# 실제 플레이어 프레임 이동 정밀도 수정

2026-09-22 pc1/CJJ, 기존 IAB와 실행 중인 Next 3100에서 v4 미디어를 확인했습니다. 서버·브라우저를 새로 시작하지 않았습니다.

## 실제 실패와 수정

시작점에서 `+1 프레임`을 누르면 실제 HTMLMediaElement.currentTime이 `0.041666`초로 반환됐습니다. 표시 좌표는 1프레임에 머물렀고 두 번째 클릭도 같은 시각에서 멈췄습니다. 기존 `floor(time * fps + 1e-6)`의 여유값은 프레임 단위라 브라우저의 마이크로초 절삭을 흡수하지 못했습니다.

`CctvInspector.step`과 `cctv-tracks.frameAt`을 `floor((time + 1.001e-6) * fps)`로 맞췄습니다. 1마이크로초 절삭과 1나노초 수치 여유만 허용하고, 기존 마지막 프레임 제한·구간 제한·이동 방향 보존은 유지합니다. 최초 1마이크로초만 적용한 시도는 확장 검사에서 202 대신 201이 나오는 부동소수 경계를 놓쳐 실패했고, 이 결과를 확인한 뒤 수치 여유를 보완했습니다.

경계 직전 최대 약 1.001마이크로초를 다음 프레임으로 보는 편향은 의도한 한계입니다. 전체 EOF는 frameAt의 null 판정을 유지하며 제품은 마지막 유효 프레임을 표시합니다.

## 실행 검증

기존 Node 실행파일로 아래 각 검사를 실행했고 최종 exit 0을 확인했습니다.

```powershell
node tests/e2e/cctv-player-precision-unit.mjs
node tests/e2e/cctv-inspector-step-unit.mjs
node tests/e2e/cctv-trusted-tracks-unit.mjs
```

- 새 정밀도 검사는 실제 TS/AST 함수를 실행합니다. `b1ca8f2`에서 두 클릭 정지를 재현하고, 수정 후 24/25/29.97/30/60/120fps의 exact·절삭·반올림 시계에서 전진/후진 20,772회·경계108개·수정 한쪽 제거 변이2개를 통과했습니다. 기대값은 이동 순서로 정하며 수정식을 복제하지 않습니다.
- 기존 이동 검사는 20/20, 방향·구간96/96, 기존 클램프/방향 변이2/2입니다. 변이 대상 문자열만 새 표현으로 맞췄습니다.
- 좌표 등록 검사는 기존49개와 실제 v4 파일·사건 연결4개를 포함해 53/53입니다. 타입검사도 exit 0입니다.
- 별도 읽기 전용 검토자는 실제 frameAt 경계111/111 및 부분 구간·EOF 조작9/9를 실행했습니다. 1·24·120fps와 최대72,000프레임을 포함하고 −2µs/−1.002µs는 이전 프레임, −1µs는 의도한 보정, EOF는 null임을 확인했습니다.

수정 후 기존 브라우저에서도 `0.041666/2프레임 → 0.083333/3프레임`, 추가 다음2회·이전1회 후 `0.125/4프레임`을 확인했습니다. 끝 12초에서 다음은 12초/288을 유지하고 이전은 11.916666초/287로 이동했습니다. 실제 영상 메타데이터는 1920×1080·12초·error null입니다.

브라우저 관측과 미세 정밀도 모사는 실제 디코더의 모든 픽셀·requestVideoFrameCallback 순서를 전수 증명하지 않습니다. 전체 플리커·물리 접촉 검증으로 확대하지 않습니다. 원장·API·과금 호출은 변경하지 않았습니다.
