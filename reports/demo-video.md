## 영상 내용과 사용 범위

- 3D풍 창고 랙, 피킹 암, 이동 토트, 컨베이어 롤러, 스캐너, 소터 분기, D-01~D-03 도크를 절차적으로 렌더링했습니다.
- 주황색 데모 토트는 작업대 → 피킹 투입 → 스캐너 → 소터 분기 → D-02 도크로 이동합니다. 번호가 붙은 네 노드와 현재 단계 표시를 제공합니다. 메인에서 전달한 CASE-0002 fixture 도크와 표기를 맞췄으며, 도크명 중복을 피하도록 보조 도크 표기 D-01과 위치를 교환했습니다. 이동 경로와 12초 길이는 그대로입니다.
- 모든 프레임에 `AI SYNTHETIC / DEMO ONLY`, `CASE-0002 / REFERENCE ONLY`, 가상시간과 실제 CCTV가 아니라는 안내, 영상만으로 원인을 확정할 수 없다는 안내를 표시합니다.
- 02:15~03:02는 12초로 압축한 가상시간 연출입니다. 실제 이벤트 시각이나 실제 토트의 이동 기록이 아닙니다. `DEMO TOTE`와 도크 번호 또한 설명용 표기입니다.
- 사용자의 이번 배정에 따라 CASE-0002 참고용으로 표기했습니다. 주문·점포·토트 원본 행과의 실증적 연결을 검증한 자료가 아니므로, 오출 원인 확정이나 상품 식별 근거로 채택하면 안 됩니다.
- 실제 회사 데이터, 개인정보, 원본 CCTV, 외부 영상은 사용하지 않았습니다. AI가 작성한 Python 애니메이션이며 영상 생성 모델 호출 결과가 아닙니다.

## 재현

Python과 Pillow, numpy, imageio-ffmpeg가 필요합니다. 이 PC에서는 기존 Python 3.14의 Pillow/numpy와 설치한 imageio-ffmpeg 0.6.0을 사용했습니다. 생성기는 네트워크와 API를 호출하지 않습니다.

```powershell
python scripts/generate_demo_video.py
```

선택적으로 실제 인코딩 영상에서 추출한 4장 검수 이미지를 별도 경로에 저장할 수 있습니다.

```powershell
python scripts/generate_demo_video.py --preview C:/Users/choi8/AppData/Local/Temp/oneflow-sorter-preview.jpg
```

Windows에서는 맑은 고딕을 사용합니다. 다른 환경은 영문 자막으로 대체합니다.

## 검증 근거

2026-09-21 16:50 KST, pc1 CJJ에서 도크 표기를 수정한 최종 파일을 다시 확인했습니다.

1. imageio-ffmpeg로 최종 MP4 전체를 디코딩했습니다. 메타데이터는 960×540, H.264, 24fps, 12초이며 실제 읽힌 프레임은 288개입니다. 0·96·192·287번 프레임의 해시 4개가 서로 달라 정지 이미지 영상이 아님을 확인했습니다.
2. 별도로 FFmpeg 7.1에서 `-i apps/web/public/demo/sorter-demo.mp4 -f null -`을 실행했습니다. 결과는 `frame=288`, `time=00:00:12.00`, 종료코드 0이었습니다. 독립 ffprobe 실행은 하지 않았습니다.
3. 최종 영상에서 추출한 대표 프레임 4장을 직접 열어 피킹/이동/도크, 번호 노드, 워터마크, 가상시간, 한글 한계 안내를 검수했습니다. 최종 도착 도크가 D-02이고 하단 D-03 표기가 단계 표시와 겹치지 않는 것을 확인했습니다. 대표 4장 시각 검수와 전체 288프레임 디코딩의 범위는 다릅니다.
4. `git check-ignore apps/web/public/demo/sorter-demo.mp4`가 해당 경로를 반환했습니다. 영상은 현재 Git 추적 제외 상태입니다. 커밋·push·배포는 실행하지 않았습니다.
