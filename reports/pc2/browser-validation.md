# N02 독립 브라우저 검증 실측

검증 대상은 실제 `apps/web/components/CallReview.tsx`와 CSS module이다. `tests/remote/pc2/harness.tsx`가 실제 파일 및 앱 tokens/globals를 import하며 컴포넌트나 스타일을 복제하지 않는다. Next 내장 webpack, 기존 TypeScript/React 및 `tests/e2e`의 Playwright를 사용한다. 독립 서버는 `127.0.0.1:3122`에만 연결하며 기존 서비스 프로세스를 사용하거나 종료하지 않았다.

## 실제 v2 WAV 전체 재생

최초 전체 수용에서는 두 실제 WAV를 각각 별도 페이지에서 1배속으로 처음부터 자연 종료까지 재생했다. 시간을 건너뛰거나 인위적인 ended 이벤트로 첫 완료를 대신하지 않았다. 브라우저의 native played 범위도 0부터 파일 끝까지 연속으로 확인했다.

## 실패와 같은 조건의 재검

1. **소수 구간 표시 결함:** 실제 0.15~0.8초 구간이 화면에서는 `0:00–0:00`으로 보여 구간을 식별할 수 없었다. UI 담당자가 소수 구간용 밀리초 표시를 보완했다. C02가 정확한 `0:00.150~0:00.800` 라벨과 실제 정지를 함께 확인한다.
2. **RAF 단독 종료 감시 반례:** 정상 재생의 requestAnimationFrame만 억제하고 실제 음원 디코더와 trusted timeupdate를 유지했다. 구버전은 0.8초를 지나 1.76513초에도 계속 재생했다. UI 담당자가 timeupdate 경계 확인과 hidden 선택 구간 정지를 추가했다. 동일 RAF 중단 조건에서 0.8초로 정지·커서 보정됨을 재검했다. 실제 재생 범위는 0.900211초까지이므로 정확한 0.8초 절단 성공이라고 주장하지 않는다. 최종 assertion은 cursor와 실제 played 끝 모두 구간 끝+350ms 이내인지 확인한다.
3. **시험 준비 과정의 문제:** 처음 일부 하위 에이전트 실행에서 실제 WAV Node 읽기가 EPERM이었다. ACL·보안 설정을 변경하거나 음원을 대체하지 않았다. 루트의 정상 실행 권한에서 두 실제 파일을 읽고 전체 1배속 재생을 확인했다. C06 저장 응답 검사는 전사/분석 표시 검사이며 하위 실행 화면의 WAV 접근 오류를 실제 음원 성공으로 사용하지 않는다.
4. **하네스 판정 보완:** React props가 커밋되기 전 disabled를 확인한 C05 대기 문제, 0초 WAV에서 native error만 기다린 가정, 설명문 전체에서 출처 단어를 찾던 C06을 수정했다. C18 최초 고정 대기 시도는 음원 시작 지연으로 0.224초만 관측했으므로 반례 근거에서 제외했고, 실제 0.3초 진행 확인 후 관측하도록 수정했다. 제품 장애와 시험기 가정을 구분한다.

기존 전체 runner는 정상 exit0로 종료되었다. 종료 실패는 없었다. 이후 자기 BrowserServer와 HTTP 서버에만 유한 종료 대기·결과 기록을 추가했으며 영향 재검의 종료 단계는 모두 complete였다.

## 화면 검토와 제한

AI가 실제 렌더 스크린샷을 열어 확인했다. `comparison-1440.png`의 AI 1 BOX/현재 1 EA/주문 18 EA 구분, 3개 폭의 `long-layout-*.png`와 `viewport-*.png`에서 긴 토큰·인용·오류의 줄바꿈과 버튼/초점, 두 실제 WAV 완료 화면, 저장 STT의 A/B 대화록과 텍스트 접수 화면을 확인했다. 390px는 한 열로 이어지고 문서 가로 넘침이나 주요 버튼 잘림을 발견하지 못했다. 스크린샷 파일은 최신 실행으로 갱신되므로 판정 시각과 source hash는 JSON을 기준으로 한다.

실제 두 탭을 전환해 관측했지만 headless Edge의 원래 페이지는 계속 `visible`이었다. 따라서 **실제 hidden/background 탭 시험은 미검증**이다. document.hidden/visibilityState와 visibilitychange를 명시적으로 주입한 분기 검사는 별도의 기술적 증거다. 주입 시 구간이 0.318369초에서 멈추고 hidden 중 재시작이 막혔으며, 전체 3초 재생은 계속되어 완료 콜백 1이었다.

헤드리스 media 종료는 OS 스피커 출력·음성 내용의 정확성·사람 청취 명료도를 증명하지 않는다. 사람 청취와 Silent Test는 별도다. 저장 STT 응답은 이미 수행한 승인 합성 호출의 읽기 전용 자료이며 새 live 호출이나 전체 STT 정확도 측정이 아니다. 현재 `caseData.intake`와 AI 제안을 비교할 뿐, 상위 서버가 이미 덮어쓴 최초 상담 입력의 보존을 보장하지 않는다. 부모 화면의 분석 게이트·API 저장·담당 이관·전체 서비스 통합은 pc1 인수 범위다.

## 최종 실행 후 네트워크 수신 범위 보완

사용자가 반복 접근 허용 팝업을 보고해 추가 브라우저·보조 검사를 중단했다. 테스트 HTTP 서버는 기존부터127.0.0.1이었지만 BrowserServer의 WebSocket host는 미지정이었다. 설치된 Playwright1.58.2 구현과 타입 설명에서 미지정 시 모든 인터페이스(::/0.0.0.0)에 바인딩함을 확인해 run.mjs의 host를127.0.0.1로 한정했다. 사용자 팝업의 직접 원인은 미확인이고 보안/방화벽 설정을 변경하지 않았다.

이 하네스 설정 변경은26개 전체 실행 **후** 적용했고 `node --check tests/remote/pc2/run.mjs` 구문 검사만 수행했다. 제품 컴포넌트 소스와26개 판정 로직은 바뀌지 않았다. 팝업 재발 여부나 변경된 수신 주소의 실제 실행은 재검하지 않았으며 해결 완료로 주장하지 않는다. 기존 최종 실행의 브라우저·HTTP 서버 종료는 모두 complete다.
