## 사용자와 완료 결과

상담원이 한 사건의 합성 통화를 재생하고 화자·정정 발화를 다시 들으며 원문/전사, AI 제안, 현재 상담 입력의 차이와 추가 확인 사항을 구분한다. 원대본을 실제 STT로 가장하거나 불명 점포를 fixture 점포로 확정하지 않는다. 주문18EA와 수령1BOX를 별도 맥락으로 유지한다. 값 저장·이관·실제 모델 호출은 부모/서버 소유다.

## 계약과 파일 소유

필수 계약: 기본 export `CallReview`, `caseData: CaseData`, `disabled?: boolean`, `onPlaybackEnded?: () => void`.

부모의 분석 중/실패 상태는 CaseData에 확정 타입이 없으므로 다음 선택적 확장을 제안한다. 추가해도 기본 계약으로 렌더할 수 있으며 연결 예시는 integration.md에 남긴다. `analysisState?: 'idle' | 'loading' | 'error'`, `analysisError?: string`, `onRetryAnalysis?: () => void`, 필요시 명시적인 replay/live 구분. 부모가 연결하지 않으면 실행 버튼을 만들거나 임의 API를 호출하지 않는다. 이 확장은 메인 통합 검토 대상이다.

소유: `apps/web/components/CallReview.tsx`, `CallReview.module.css`, `scripts/media_pc2/`, `planning/media/voice-scenarios.md`, `tests/remote/pc2/`, `reports/pc2/`.

읽기 전용: page.tsx, globals.css, lib/types.ts, fixture, manifest, server, 중앙 작업표. 검증용 렌더는 별도 로컬 harness에서 실제 컴포넌트를 가져오며 공용 제품 페이지를 수정하지 않는다. 의존성 설치와 생성 파일은 무시된 로컬/기존 node_modules에 둔다.

## 상태·행동

| 상태 | 표시와 행동 |
|---|---|
| 준비/재생/일시정지/완료 | native audio controls, 현재시각/전체길이, 배속·볼륨·음소거 상태를 제공한다. 자동재생하지 않는다. |
| 전사 시각 있음 | 유한수이며 0≤start<end≤duration 범위의 발화만 구간 재생한다. 재생 위치에 대응하는 발화를 표시하고 구간 끝에서 멈춘다. |
| 구간 재생 중 탭 숨김 | 선택 발화를 즉시 중단·해제하고 사용자가 다시 선택한다. 전체 통화 재생과 전체 완료 판정은 별도로 유지한다. RAF 외 timeupdate에서도 구간 끝을 확인한다. |
| 시각 없음/불량/범위초과 | 텍스트를 보존하고 구간 재생 불가 이유를 표시한다. 음원 길이를 발화 수로 나눠 시각을 만들지 않는다. |
| 음원 없음/404/디코드 실패 | 인라인 오류·음원 재시도. 완료 콜백을 발행하지 않고 다른 사건 파일로 대체하지 않는다. |
| 분석 전 | 원문과 현재 입력을 유지한다. 샘플 대본/리플레이 전사는 실제 STT로 표시하지 않는다. |
| 분석 중/오류 | 로딩/부모 오류를 표시한다. 재시도는 부모가 제공한 콜백으로만 수행하고 전체 재생/disabled 조건을 지킨다. |
| 미식별 점포/수량 없음 | null·빈 값은 미확인으로 표시하고 0은 0으로 보존한다. 미식별 AI 점포를 원본 fixture 점포로 채우지 않는다. |
| 사건/음원 전환 | 이전 음원을 멈추고 구간·오류·완료 상태를 초기화한다. 이전 사건의 ended/error 이벤트가 새 사건에 영향을 주지 않아야 한다. |
| disabled | 재생·구간 선택·재시도 등 의도한 상호작용을 막고 중간 재생을 멈춘다. 읽기 정보는 유지한다. |

`onPlaybackEnded`는 정상 음원 전체 재생 완료만 나타낸다. 선택 구간 완료, 404, seek로 끝 건너뛰기, 이전 사건 이벤트로 분석 허용을 만들지 않는다. 사용자 청취 만족도·OS 스피커 출력 성공의 증거는 아니다. 동일 사건·음원의 불필요한 반복 완료 알림도 막는다. 필요한 경우 부모가 case/음원 key로 완전히 remount하는 연결 예시를 제공한다.

## 정보·출처와 접근성

- sourceText는 입력/합성 원문, transcript는 분석 모드·출처가 확인되는 전사 또는 replay 자료로 구분한다. 확인할 수 없으면 출처 미확인이라고 표시한다.
- AI fields와 intake는 점포ID, 대상, 수령 수량, 단위, 요청을 같은 순서로 비교한다. 변경/동일/미확인을 색 외 텍스트로도 표시한다. 분석 질문과 issues의 인용을 함께 보여준다.
- 원문·AI fields·intake를 직접 수정하지 않는다. 분석 모드가 모호하면 live라고 단정하지 않는다. 주문과 수령 값은 각 출처 이름으로 표시한다.
- 기존 디자인 토큰·글꼴을 재사용한다. CSS module 범위를 지키며 native audio의 접근성과 Tab 초점을 보존한다. 버튼에 동작/화자/구간 이름을 넣고 오류는 role=alert, 변화 상태는 적절한 aria-live로 읽는다. 재생시간의 초 단위 변경을 계속 읽어주지 않는다.
- 1440/1024/390px에서 문서 가로 넘침0, 긴 문자열·긴 질문이 버튼을 숨기지 않음, reduced-motion에서 불필요한 애니메이션 없음.

## First Bolt와 Ralph 검증 순서

첫 병목은 `1 EA` 상담 입력과 `1 BOX` AI 제안의 차이·인용 근거를 같은 화면에서 찾기 어려운 점이다. 기준 화면/입력 구조를 기록하고, 비교 영역 한 가지 변화 후 동일 합성 입력으로 차이·원문 보존·인용 노출을 렌더 검증한다. 이는 AI 기술 검증이며 실제 Silent Test를 수행했다고 보고하지 않는다.

설계 → 컴포넌트/음성 기준 병렬 작업 → typecheck/build → 실제 렌더·정상/음성/경계 검사 → 독립 적대 검토 → 같은 조건 수정 재검 → 한 브랜치 결과를 메인에게 회신한다. 검증되지 않은 숫자를 PASS로 만들지 않는다.
