# OneFlow UI/UX 참조 조사와 단계별 개선안

작성: 2026-09-21, 개발 PC CJJ(pc1)의 로컬 코드 정적 확인 및 공식 문서 조사. 이 문서는 설계 제안이며 실제 픽셀 검수·사람 사용성 평가·구현 완료 증거가 아닙니다. 배정 범위는 이 파일뿐이며 코드·계약·Git 작업은 수행하지 않았습니다.

## 1. 설계 결론과 현재 기준

우선 개선 대상은 **어느 사건인지, 무엇이 확인됐는지, 지금 할 일이 무엇인지**를 모든 화면에서 읽을 수 있는 사건 중심 워크벤치입니다. 현재 상단 메뉴와 원문/정제의 두 패널, WMS/TMS 별도 화면을 보존하면서 선택 사건의 맥락과 다음 행동을 가까이 둡니다. 장식 효과나 새 색상보다 조회→대조→확인→회신의 정보 순서를 먼저 개선합니다.

- 근거: `PROMPT_team.md`, docs/24·25·21, `apps/web/app/page.tsx`, `apps/web/components/LogisticsView.tsx`, `apps/web/app/globals.css`를 읽었습니다. 등록 신원은 `python channel/whoami.py`의 2026-09-21 17:29 KST 출력에서 pc1/CJJ로 확인했습니다.
- 현재 코드에 원문·AI 요약/원본 필드·사람 편집/확인, 전사 재생 모드, 이관 잠금, 명시적 기존 사건 연결, 낡은 수정 버전, 센터 회신 상태가 존재합니다. 이를 신규 기능처럼 다시 만들지 않고 정보 위치와 설명을 정돈합니다.
- LogisticsView에는 기록 확인/원인 미확인 배지, 원본 행 펼침, 기준시각 검사, 사건·시스템·이벤트 조건 영상 연결, 합성 표시, 오류 재시도, Escape/배경/버튼 닫기와 포커스 복귀 코드가 있습니다. 실제 동작 성공 여부는 별도 실행 검수 대상입니다.
- 현재 상담 근거 영역의 연결 결과가 근거 ID 나열로 표시됩니다. ID에 출처·발생시각·관측값·미확인 상태를 함께 붙이는 것이 작은 변경으로 판단 가능성을 높이는 첫 후보입니다.

## 2. 기존 토큰을 사용하는 브리프

대상은 상담 입력 대장과 물류 근거 조회입니다. `DESIGN_SYSTEM.md` §11의 **CRUD 입력 대장 → Split-Pane 워크벤치**를 상담 과업의 기준으로 삼고, TMS 표의 전수 비교 능력을 보존합니다. 작업 큐는 기존 상단 탐색 안의 사건 목록이며 전역 좌측 메뉴를 추가하지 않습니다.

색/폰트/치수는 현재 `--surface-*`, `--text-*`, `--border-*`, `--action-*`, `--focus-*`, `--space-*`, `--control-*`, `--font-*`, `--radius-*`, `--motion-*` 및 상태 토큰을 재사용합니다. 정본 `75_하네스_클라우드배포/01_프론트엔드/01_토큰/src/{primitive,semantic,scale,biz}.json`과 패턴 카탈로그를 참조합니다. 새 hex·폰트쌍·UI 킷을 반입하지 않습니다. 외부 스킬의 타이포 교체, 질감·패럴랙스·유리 효과는 이 업무 화면에 적용하지 않습니다.

현재 골격: 상단 메뉴 → 사건 선택 → 원문/정제 2열 → 하단 근거 → 별도 센터 회신.

목표 골격: 사건 큐/선택 → 사건 헤더와 다음 행동 → 원문/AI/사람 대조 작업 → 인접한 근거·미확인 맥락 → 같은 사건의 회신과 조치 상태. 기존 페이지 이동·표·원본행 접근은 보존합니다.

## 4. 단계별 화면·상태 설계

| 순서 / 사용자 과업 | 구체 변경안과 주요 행동 | 빈 값·대기·실패·성공 / 수용 기준 |
|---|---|---|
| 1. 처리 큐에서 문의 선택 | 현재 사건 선택을 `접수번호 · 점포 · 유형 · 상태 · 다음 행동`으로 읽게 구성. 전체/상담원 확인/센터 처리/종결 필터는 상태 정본을 사용. 저장되지 않은 입력이 있으면 전환 시 이를 인지할 수 있게 처리 | 조회 전 로딩, 필터 결과 0건과 서버 조회 실패를 분리. 선택 표시와 상세 사건 ID 일치. 상태별 건수는 실제 조회 집합에서 계산; 임의 우선순위·SLA 수치 생성 금지 |
| 2. 원문·AI 초안·사람 확정 대조 | 원문은 읽기 전용, AI는 `확인 전 초안`, 편집폼은 `상담원 확인값`으로 명시. 점포/상품/수령수량/단위/요청을 같은 순서로 읽게 하고 수정 필드에 AI 제안값 보기 제공. 핵심 모순·추가 질문은 펼침 밖에 둠 | 텍스트에는 전사 실행/전사 결과라는 표현 대신 `문의 정제`와 `입력 원문` 사용. 통화만 종료 후 STT. 주문량과 수령 진술 별도. 0과 미확인 구분. 원문 불변·변경 후 확인 해제·기존 버전 충돌을 검증 |
| 3. 근거와 미확인 판단 | 사건 헤더에 점포·유형·현재 상태·기준시각·데이터 모드. 연결 근거를 출처(WMS/TMS)·발생시각·라벨·관측값·기록/미확인 상태로 표시. 원본 행은 펼침 제공 | 기록 없음은 `조회 기준 내 기록 미등록`, 원인은 `추가 확인 필요`. 사람 진술/시스템 기록/AI 제안의 출처 분리. 선택 사건 밖 근거 거부. ID 목록만으로 판단하도록 두지 않음 |

| 5. 이관하고 회신 확인 | 현재 상태에서 한 주행동을 강조: 확인 전 `접수 내용 저장`, 확인 후 `확인 후 센터 전달`, 센터는 `중간 회신 등록` 또는 조건 충족 시 `최종 회신·처리 완료`. 다음 단계 조건은 CTA 가까이 표시 | 필수 점포·문의 대상·부서·사람 확인과 선택 수량을 구분. 남은 조치가 있으면 처리 중. 저장 응답 전 성공 금지. 충돌 시 `다른 화면에서 변경됨`과 입력 보존·최신 내용 확인 동선 제공 |

## 6. 가장 작은 첫 실험과 인수

첫 Bolt의 병목은 **연결한 근거 ID만 보고 상담원이 출처·시각·관측 내용을 다시 찾아야 하는 것**입니다. 첫 변경은 상담 근거 ID 목록에 근거 라벨/출처/시각/상태 요약을 붙이는 한 가지로 제한합니다. 기존 데이터와 API를 유지하며 같은 합성 미도착·오출고 사건으로 수정 전후를 비교합니다.

기술 관측 기준: 근거 연결 전/후 선택 집합, 다른 사건 혼입 없음, 실패 시 연결됨 표시 없음, 3폭에서 근거 요약 읽힘, WMS/TMS 복귀 후 사건 유지. 사람이 실제로 판단 속도가 빨라졌는지는 별도 관찰 전까지 미확인입니다.

후속 순서는 ①사건 헤더/다음 행동 ②원문·AI·사람 대조 ③큐 조회/상태 ④센터·경영주 회신 ⑤3폭 마감입니다. 각 단계는 docs25의 T10~T12, T16~T24, T26과 연결하여 입력·기대·실측·실패·수정·재검증을 남깁니다. pc2 CallReview, pc3 WmsScene, pc4 TmsScene 소유 경로는 메인 인계 없이 수정하지 않습니다.

현재 완료한 것은 정적 구조 확인·공식 참조 조사·적용 설계입니다. 브라우저 렌더, 3폭 스크린샷, 키보드·영상 재생, 대비 실측, 사람 피드백은 이 작업에서 실행하지 않았습니다.
