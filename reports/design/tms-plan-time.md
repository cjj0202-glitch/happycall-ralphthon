# TMS 계획 도착과 실제 기록의 시간 경계

2026-09-21 pc1. 독립 탐색에서 현재 `LogisticsView.tsx`가 계획 도착에도 asOf 제한을 적용해 미래 계획을 지도·표에서 숨기고 원본 보기에서는 null로 바꾸는 것을 재현했습니다. 현재 합성 fixture는 6방문 모두 계획이 asOf 이전이라 기존 시연만으로는 드러나지 않았습니다.

## 수정 전 상세설계

- 사용자 결과: 상담원이 앞으로의 방문 계획과 지금까지 등록된 실적을 구분해 읽습니다. 계획 대상시각이 미래라고 해서 계획을 누락하지 않습니다.
- 구조: TMS 지도와 표의 planned 표시는 시간 형식만 검사합니다. 원본 보기에서는 원래 planned를 보존합니다. actual/mobileEntry/mobileExit의 asOf 경계와 WMS/evidence 검사는 그대로 유지합니다.
- 불확실성: 계획은 인도 확정이나 실제 GPS가 아닙니다. null은 미등록, 잘못된 시각은 확인 필요로 표시하며 원본은 남깁니다. asOf가 잘못돼도 계획은 표시하되 실적을 확정하지 않습니다.
- 파일: 메인이 `apps/web/components/LogisticsView.tsx`, `tests/e2e/tms-time-semantics.cjs`, 이 보고서만 소유합니다. pc4의 별도 TmsScene 경로와 겹치지 않습니다.
- 검증: 미래 계획/미래 실제·진출입/동일시각 경계/null계획/잘못된계획/잘못된asOf 6개 입력을 실제 컴포넌트 렌더로 대조합니다. 실제기록 가드를 없애는 변이체가 실패해야 합니다. SSR 결과와 실제 브라우저 화면 검수를 분리합니다.

## 수정 전 관측

asOf 07:00, planned07:01, actual07:02, mobileEntry07:03, mobileExit07:04를 넣으면 계획은 지도·표에서 2회 `기준시각 이후 / 미표시`, 원본은 `planned:null`이었습니다. 실적3종은 미표시되고 완료0/3이었습니다. 독립 메모리 A/B는 원본3/6, 3곳 수정안6/6, 모든실적허용 변이4/6으로 관측했습니다. 이 단계는 파일 수정이나 브라우저 검수가 아닙니다.

## 수정과 독립 검증

실제 컴포넌트의 계획 표시 2곳에서 asOf 인수를 제거하고 원본 planned를 null로 바꾸던 1곳을 제거했습니다. `node tests/e2e/tms-time-semantics.cjs`는 실제 TSX를 React SSR로 렌더해 6/6 통과했고, 모든 미래 실적을 허용하는 변이체는 2건에서 실패했습니다.

19:12 KST 독립 `/root/tms_plan_ui_review`가 Chromium 151·로컬 3100에서 인메모리 GET fixture 5종을 실제 화면으로 확인했습니다. 미래 계획 07:01은 지도·표·원본에 남고 미래 실적 07:02/03/04는 미등록·원본 null·완료0/3이었습니다. null/잘못된 계획·기준시각과 동일한 실적·잘못된 asOf도 기대와 일치했습니다. 지도 Tab/Enter/Space, 표 Space 선택, 계획 오름/내림 정렬과 aria-sort가 일치했고 console error/warning/pageerror는 각각 0건이었습니다. POST/PATCH·외부 요청 시도는 0건입니다.
