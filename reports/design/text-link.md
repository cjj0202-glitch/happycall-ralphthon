# 텍스트 접수의 기존 사건 선택 연결

범위: `apps/web/app/page.tsx`의 Owner 함수. 기존 원문과 다른 작업자 변경을 보존한다.

## 동작

- `referenceCaseId` 기본값은 null이다. 동일 점포·제목·유형을 입력해도 자동 연결하지 않는다.
- 관련 기존 접수 선택기는 합성 원본 사례(CASE 계열)와 사건 ID·조회 기준일시·제목을 표시한다. 기준시각을 확인한 사용자가 명시적으로 선택한다.
- 선택하면 점포코드·문의 유형·문의 제목만 한 번 채운다. 상세 내용/원문은 바꾸지 않는다.
- 점포·유형·제목을 변경해 일치가 깨지면 선택을 해제하고 해제 사유를 알린다. 선택 해제는 원문과 입력값을 지우지 않는다.
- 선택하지 않으면 새 원문 기반 접수이며 기존 물류 근거를 연결하지 않는다고 안내한다.

## 서버 계약

`server/service.py::intake`를 대조했다. referenceCaseId 키가 전달되면 null/빈값도 오류다. 미선택 상태에서는 요청에서 해당 키를 생략한다. 선택 시 문자열 ID만 전송한다.

서버는 원본 fixture의 ID, type, intake.storeId, intake.subject를 정확히 대조한다(intake 키가 없을 때는 최상위 storeId/subject). 클라이언트도 같은 키 우선순위를 사용하며, 서버의 최종 일치 검증 오류를 사용자에게 그대로 보여준다. 선택 후보는 편집·분석된 현재 접수 값이 아니라 `/cases.json`의 원본 사례를 읽는다. 정본 로드 실패 시 선택 후보를 임의 복원하지 않고 연결 없는 새 문의만 가능하다. 배포된 정적 fixture와 서버 fixture가 달라지면 서버가 거부할 수 있다.

## 수용 기준

1. 최초 선택 없음, 기존 사례를 연 상태에서도 자동 선택 없음.
2. 선택 시 ID·기준시각·제목 확인, 세 입력 채움, 상세 내용 보존.
3. 세 연결 키 중 하나라도 변경하면 referenceCaseId 해제.
4. 미선택 POST는 referenceCaseId 키 없음, 선택 POST는 해당 ID 포함.
5. 저장 실패 시 입력과 원문 보존, 서버 오류 표시.
6. 기존 진행상황 영역·타 함수·API·fixture는 수정하지 않는다. 유료 API를 호출하지 않는다.
