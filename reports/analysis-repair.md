2. **모델 추출 계약:** public `ANALYSIS_SCHEMA`의 모양을 유지한다. model-only 스키마 설명과 시스템 지시에 subject/request는 발화에서 새로 추출, 주문은 명시적인 긍정 주문 진술만, 현재 문의의 최종 수령을 과거 수령과 분리, 수량과 단위를 각각 추출, 발화 요청과 허용 부서 id/name 연결을 구체화한다. 주문이 없으면 null이며, 수령 정정 전 값·주문 규격 확인 요구·기록은 주문 진술이 아니다.
3. **보수적 주문 투영:** 인용 존재 검사에 더해 좁은 긍정 주문/발주 행위 표현만 주문 후보로 허용한다. 부정·가정·인용·불확실 표현 및 수령 문장만 인용한 후보는 주문을 null로 낮추고 확인 질문을 남긴다. 이 필터는 주문 정보를 새로 추출하거나 업무·부서를 추정하지 않는다. 지원하지 않는 표현은 미확인으로 남는 손실을 허용한다. **출처 문장 존재는 의미 검증이 아니며**, 이 필터 통과도 수량·화자·시점·최종 정정의 의미 정확도나 실제 인도를 증명하지 않는다.
4. **처리 결과와 초안 경계:** 모델 자유문 `replyDraft`를 공식 회신·완료·귀책 진술로 내보내지 않는다. 서버가 실제 조치·담당자 회신을 확인하지 않았음을 밝힌 검토용 초안을 만든다. 부서는 허용 목록 중 추천이며 서버 상태 전이·회신 등록은 기존 서비스 계약대로 사람이 담당한다. 모델이 쓰는 나머지 자유문도 AI 제안이므로 의미 검토가 계속 필요하다.
5. **실패와 비용:** 모델 호출 수·예약/완료 처리·실패 비용 유지·HTTP 오류 처리는 변경하지 않는다. 모델 품질 개선을 확인하는 실제 과금 재실행은 메인만 수행한다.

## 1차 구현 결과 — 후속 P1 수정 전 이력

- 모델 payload는 `transcript`, `syntheticStoreMaster`, `syntheticEvidence`, `allowedDepartments` 네 항목이다. `intake`, 대본, replay/expected 등은 전달하지 않는다. 원본 intake와 요청 객체는 변경하지 않는다.
- 주문 인용은 명시적 긍정 활용형/명사절의 필요조건과 원래 문장 주변의 부정·인용·불확실 표식을 보수적으로 검사한다. 잘린 긍정 구절만 제출한 경우와 반복된 동일 구절의 상충 문맥을 검사한다. 거절된 주문 후보에 값이 하나라도 있었고 모델 subject에 주문/발주가 들어 있으면 subject를 null로 낮추고 확인 질문을 남긴다. 상품·수량·단위·부서를 정규식으로 새로 추출하지 않는다.
- 주문·수령 claim이 명시적으로 모두 null인 전체 배송 문의에는 무조건 수량 질문을 추가하지 않는다. subject/request가 비었거나 부서가 비었으면 대상/요청/담당 업무의 확인 질문을 남긴다.
- 모델 부서 id와 이름이 서로 다른 허용 부서를 가리키면 어느 쪽도 추정해 확정하지 않고 빈 부서와 질문으로 반환한다. 올바른 id/name의 업무 적합성은 여전히 모델 추천이며 수동 검토 대상이다.
- `replyDraft`는 모델이 생성한 처리결과 문장을 재사용하지 않는다. 정규화된 **문의 대상·요청·현재 수령 진술·확인 기록(최대 2행과 출처)·미확인 사항·추천 부서**를 담은 사례별 경영주용 검토 초안을 만든다. 실제 배송·반품·보상 처리 결과·귀책·센터 최종 회신은 담당자 확인이 필요하다고 구분한다. 서비스 상태를 확인하지 않은 “접수했습니다”도 생성하지 않는다. 부서 reason은 AI 검토 제안으로 표시한다. `facts`는 기존과 같이 합성 원천 fact 행만 렌더한다.
- public HTTP `analysis`의 필드·타입은 유지했고 model-only schema는 설명만 보강했다. 기존 raw 모델 응답 32개를 모두 다시 검증·투영할 수 있다. API 호출 횟수, 예약/완료 동작과 오류 처리는 변경하지 않았다.

## 기존 실제 출력의 무과금 재투영과 남은 한계

32건을 다시 모델에 보내지 않고 기존 `rawModelOutputs[0].content`를 `normalize_analysis()`에 넣었다. `record.input`, 기존 `result.transcript`와 허용 부서만 사용했다. 제품 코드는 평가 파일이나 oracle을 읽지 않는다. 기존 결과를 덮어쓰거나 기존 평가 점수를 수정하지 않았다.

| 기존 입력 | 재투영 관측 |
|---|---|
| EDGE-05 | 수령 정정 전 1 EA를 주문으로 쓰던 요약 → 주문 미확인, 최종 수령 1 BOX 유지 |

최종 재투영에서 주문 요약이 달라진 건은 위 첫 6개 ID뿐이다. 나머지 26개 주문/수령 요약은 동일했다. 모든 부서 reason의 제안 표시와 사례별 replyDraft 구성은 출력/안전 경계 변경이며 모델 추출 정확도 향상으로 세지 않는다. 기존 raw에서 subject/request를 잘못 복사한 경우 새 초안도 그 잘못된 추출 내용의 영향을 받는다. 입력 경계 변경의 효과는 신규 모델 응답에서 확인해야 한다.

**인용 존재나 이 필터 통과는 의미 검증이 아니다.** 긍정 표현의 제품/수량 정합, 화자, 최신 정정, 전체 담화의 부정과 실제 인도를 보증하지 않는다. 자유문 subject/request/issues/unknowns의 의미 검토도 남는다. 부정·인용의 모든 한국어 표현을 정규식으로 증명하려 하지 않는다. 넓은 인용에 다른 상품의 부정이나 수령 불확실성이 섞이면 유효 주문을 잃을 수 있으며, 모델에는 가장 짧은 자족적 근거 문장을 선택하도록 지시했다.

실제 사용자가 intake.subject에만 상품을 넣고 text에는 “그 상품”처럼 적은 경우도 의도적으로 자동 보충하지 않는다. 원본 subject는 보존되지만 모델 추출 대상은 원문이므로 null·확인 질문이 나올 수 있다. 원래 사용자 입력과 상담 수정값의 별도 출처 계약을 추가하지 않은 현재 구조에서의 보수적 경계다.

이 작업자의 신규 실모델 호출은 **0회**, 키 조회 **0회**다. 유료 재평가는 메인이 기존 원장 잔여 한도와 최소 호출 수를 확인해 결정한다. 위 통과 수와 재투영은 T27 실제 정답률이나 음성 품질 20건의 증거가 아니다.

## 후속 독립 P1 재현과 수정 설계

메인 독립 검토자가 model.replyDraft를 안전한 값으로 두어도 model.fields.subject/request에 근거 없는 귀책·보상 지급·이관·센터 회신 완료를 넣으면 초안에 전파됨을 재현했다. 원문과 request의 욕설도 순화 없이 복사됐다. 또한 주문 claim을 거절할 때 제목에 “주문”이라는 단어만 있으면 정상적인 “미주문 상품 오배송”·“주문 규격 차이”까지 null로 지우는 회귀 2개를 확인했다. 이 결함은 위 이전 통과 수로 덮지 않으며 유료 재평가는 보류 상태다.

후속 구현 전에 다음 경계를 정한다.

1. 내부 모델 스키마에 초안용 `draftContext.subjectQuote/requestQuote`를 추가한다. 각 값은 실제 원문 한 구간의 인용이어야 한다. 초안은 자유문 fields·unknowns를 그대로 사용하지 않는다. public HTTP analysis 모양과 AI fields의 제안 지위는 유지한다.
2. 초안은 확인된 원문 인용·수령 근거 인용·서버 fact 행·허용 부서로 구성한다. 수령 claim의 자유문 product도 원문 근거 없이 초안으로 옮기지 않는다. 기존 raw 모델 응답에는 새 인용 필드가 없으므로 nullable 근거 없음으로만 호환하고 자유문을 소급해서 근거로 승격하지 않는다.
3. 원문에서 고객이 완료·귀책을 주장하더라도 인용한 **미확인 진술**임을 표시하고 담당자의 확인이 필요하다고 구분한다. 근거가 없는 모델의 완료/귀책 문구는 초안에서 제외한다. 초안의 욕설은 순화하되 원문·요청·긴급성은 보존한다.
4. 거절 주문 때문에 subject를 null로 내리는 조건은 명확한 “상품 주문 / 상품 수령” 결합 형식으로 좁힌다. 단지 주문이라는 단어가 있다는 이유로 “미주문 상품”·“주문 규격 차이”를 지우지 않는다.
5. 자유문·수령 상품·근거 위조·실제 고객의 완료 주장·욕설+오늘 안 요청·유효 제목 보존의 새 반례와 기존 4종 사례별 초안 기능을 검사한다. 고정 초안으로 축소하지 않는다. 실제 API·키·운영 원장·동결 평가 파일은 수정/사용하지 않는다.

## 후속 P1 수정 결과

- 새 호출의 model-only 계약에 `draftContext: {subjectQuote, requestQuote}`가 추가됐다. 두 값은 nullable 원문 인용이다. **public HTTP analysis 계약은 그대로**이며 draftContext는 외부 분석 필드에 추가하지 않는다. 다른 소유 파일을 바꾸지 않고 두 소유 테스트의 모델 helper만 갱신했다.
- 초안은 각 인용이 실제 transcript 한 구간에 존재하는지 확인한다. model.fields, model.unknowns, model.replyDraft 및 receivedClaim.product/quantity 자유문을 초안으로 복사하지 않는다. 수령도 실제 `evidenceQuote`를 인용한다. 따라서 모델 필드에 허위 완료·귀책·이관·회신 또는 가짜 상품 문자열을 넣어도 초안에 확산하지 않는다.
- 원문에 실제로 완료·귀책 주장이 있으면 “검증된 사실이 아닌 미확인 진술”과 담당자 확인 필요를 명시한다. 인용을 센터 확인 사실로 바꾸지 않는다. 시스템 기록은 서버 fact 행의 출처를 붙여 별도로 제시한다.
- 흔한 욕설은 초안에서만 제거하고 “불편 표현을 순화”했다고 표시한다. “또 틀리니까 정말 화가 납니다 / 오늘 안에 / 교환 방법”은 보존하며 원문과 모델 응답은 수정하지 않는다. 제한된 표기 사전이며 모든 은어·우회 표기나 한국어 유해성을 판정하는 분류기가 아니다. 담당자 검토가 계속 필요하다.
- “상품 주문 / 상품 수령”이라는 긍정 결합 제목의 근거가 거절된 경우만 제목을 비운다. 독립 재현의 “미주문 가상솔컵 오배송”과 “가상솔컵 주문 규격 차이”는 그대로 보존하고 문의·요청 인용도 초안에 남긴다.
- legacy raw에는 새 인용이 없으므로 입력 사본에 null 근거만 추가해 호환한다. fields 문자열에서 근거를 만들어 채우지 않는다. 이 경우 문의/요청 근거 확인 질문과 기존 수령 근거·서버 fact에 한정된 초안으로 반환하며, 구체성이 부족한 구형 결과를 새 모델 성과로 세지 않는다.
