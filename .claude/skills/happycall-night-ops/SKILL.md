# 해피콜 야간 운영

이 파일에서 세 단계 위가 저장소 루트입니다. 실제 checkout에서 실행하며 pc1 경로를 다른 PC 경로로 추정하지 않습니다. 이 스킬은 반복 판단 절차이며 스케줄러나 자동 재개의 증거가 아닙니다.

## 시작과 중단 경계

처음에는 [AGENTS](../../../AGENTS.md)·[팀 프롬프트](../../../PROMPT_team.md) 전체와 [결정대장](../../../planning/decisions.md), [야간 계획](../../../docs/24_야간_4PC_작업계획.md), [실제 배정](../../../docs/27_원격PC_실제배정과_인수.md)을 읽습니다. 재개 때에는 변경분과 맡은 작업의 계약을 대조합니다. 사용자 사전 승인 DEC-018 안에서는 구현·검증·공유·배포 승인을 다시 묻지 않습니다. 후속 사용자 중단·범위 변경은 우선합니다.

1. 현재 KST, `python channel/whoami.py`, `gh api user --jq .login`, `git status --short`, `git rev-parse HEAD`, `python ops/tasks.py status`, `python ops/tasks.py check`를 확인합니다. 미등록/계정 불일치는 작업·편지 처리를 중단하고 신원과 실패를 메인에 보고합니다. 자신의 슬롯을 추정하거나 등록표를 임의 변경하지 않습니다.
2. 메인은 사용 가능한 `get_goal`로 실제 Goal을 확인합니다. [실제 시작 기록](../../../reports/goal-start-20260921.md)은 과거 증거이고 `GOAL.md`는 참조 초안입니다. 도구가 없으면 현재 Goal 상태를 미확인으로 남깁니다. 워커는 메인 Goal을 새로 만들거나 완료 처리하지 않습니다.
3. **기한은 `2026-09-22T09:00:00+09:00`**입니다. 기한 이후 새 구현·새 배정·새 과금 평가를 시작하지 않습니다. 현재 변경과 진행 중 작업 상태를 보존해 실제 HEAD·완료/미달·배포 상태·재현법을 인계하고, 메인은 기존 heartbeat를 PAUSED로 갱신합니다. 미달인 Goal을 완료로 바꾸지 않습니다. 사용자 중단에도 해당 예약을 중지합니다.

## 편지와 소유권 확인

명령·회신 형식은 [mailbox 정본](../mailbox/SKILL.md)을 사용합니다. 새 세션은 자기 `inbox`와 배정 이슈를 한 번 읽고, 이후 루프는 `python channel/mail.py watch --once`의 변경만 처리합니다. 무출력은 미처리 업무가 없다는 증거가 아닙니다. 조회 오류면 수신 여부를 미확인으로 남기고 이미 배정된 독립 작업은 계속합니다.

| 역할 | 읽고 이어갈 작업 | 책임 |
|---|---|---|
| pc1 | N01 및 보낸 [#8](https://github.com/cjj0202-glitch/happycall-ralphthon/issues/8)·[#9](https://github.com/cjj0202-glitch/happycall-ralphthon/issues/9)·[#10](https://github.com/cjj0202-glitch/happycall-ralphthon/issues/10) 회신 | 배정·계약·공통 파일·독립 검증·통합·배포·인수 |
| pc2 | N02 / #8 | 통화 검토 UX·음성 명료도, 편지의 소유 경로 |
| pc3 | N03 / #9 | WMS 공정·애니메이션·합성 CCTV, 편지의 소유 경로 |
| pc4 | N04 / #10 | TMS·타 모듈 두 흐름 6회 검증, 편지의 소유 경로 |

- 배정 이슈는 이미 있습니다. ACK가 없다고 같은 작업을 새 이슈로 재발송하지 않습니다. `python channel/mail.py read <번호>`로 본문·댓글·담당자를 대조하고, 계약 변경과 결과는 같은 이슈에 `reply --body-file`로 남깁니다. 워커끼리 직접 지시하지 않습니다.
- 배정 발송, ACK, 구현 보고, 메인 인수는 다른 상태입니다. 원격 PC의 실제 hostname·계정·HEAD·소유 파일·결과 증거가 있어야 다음 상태로 기록합니다. 같은 pc1의 보조 에이전트는 원격 PC 실적이 아닙니다.
- [docs24](../../../docs/24_야간_4PC_작업계획.md)의 파일 소유와 해당 이슈 계약을 지킵니다. 같은 checkout의 다른 작업자 변경을 되돌리지 않습니다. 겹친 파일은 편집을 멈추고 메인과 소유를 정리하며 독립 부분을 진행합니다. 미완료 TEST는 독립 작업 배정 예외와 별도로 보존합니다.

## 한 번에 검증 가능한 덩어리

신규/후속 배정은 [PC 배정 기준](../../../docs/28_PC_업무배정_기준.md)의 6칸 카드와 인수 단계로 만듭니다. 결과·소유 파일·기준 SHA·기대값이 없는 지시를 보내지 않으며 PC당 구현 카드 하나를 유지합니다.

1. [현재 TODO](../../../CURRENT_TODO.md)·[야간 작업표](../../../ops/overnight-tasks.json)·새 회신에서 자기 소유의 다음 한 덩어리를 고릅니다. 메인은 P0/P1와 통합 차단을 우선하고 독립 구현/검토는 파일 소유를 나누어 병렬 배정합니다. 완료 조건·입력·기대값·테스트 환경을 시작 전에 정합니다.
2. [상세설계·테스트 정본](../../../docs/25_단계별_상세설계와_전체테스트.md)에 따라 필요한 설계를 작성합니다. BMAD는 사용자 과업·UX·계약·검증을 대조하고, Grill-me는 조사 가능한 사실을 확인한 뒤 남는 결정만 기록합니다. 이미 승인된 범위·기술 선택을 반복 질문하지 않습니다. First Bolt는 병목 하나·관측·핵심 수정 하나·동일 조건 재시험, Ralph는 [기존 루프](../ralph-loop/SKILL.md)의 구현→검증→수정으로 수행합니다.
3. 일반 검사는 무과금 replay/mock입니다. 음성 재생·STT·GPT·원문·AI 제안·사람 수정을 구분하고 합성 표시를 유지합니다. 합성 영상으로 실제 작업·귀책을 확정하지 않습니다. 20개 입력·12개 경계·동일 릴리스 6회는 각각 실제 실행 분모로 기록합니다. AI 브라우저 검사는 사람 청취·사용성 관찰의 대체 증거가 아닙니다.
4. 변경 영향에 맞는 단위·기능·화면 검사를 실행하고 기대/실측·실패·수정·재검증을 남깁니다. 위험한 상태/근거/예산/접근 제어와 최종 통합은 독립 검토자에게 결과물·계약·재현 입력을 전달합니다. 검토 의견도 실제 재현으로 확인하며 자기 모듈의 자체 검사를 독립 검사로 세지 않습니다. 이미 통과한 검사는 새 변경·실패·미해결 위험이 있을 때만 반복합니다.
5. 같은 실패를 같은 방법으로 3회 반복하거나 한 문제에 30분 진전이 없으면 그 접근을 중단하고 원인·시도·다음 독립 작업을 메인/보고서에 남깁니다. 기존 루프의 사람 확인 문구는 이번 사전 승인 범위에서 반복 승인 질문을 만드는 이유가 아닙니다. 필수 정보가 없으면 의존 작업만 보류하고 조사·격리 검증 등 가능한 부분을 진행합니다.

공식 점수 대응은 [전략](../../../docs/11_점수전략과_증거설계.md)과 [실측 대조](../../../reports/scoring-review.md)를 연결합니다. 위임·검증 60점 영역의 완료 기준→실패→수정→같은 조건 재검증 근거를 남기고, 실제 Goal·주로그·발표·제출 준비를 빠뜨리지 않습니다. 형식 검사만으로 로그 비밀정보 검토나 공식 제출을 완료 처리하지 않으며 로그 원문을 자동 전송하지 않습니다. 예상 득점이나 병렬 수·시간 자체의 가점을 만들지 않습니다.

## 커밋·공유·인수

[WORKSPACE](../../../WORKSPACE.md)에 따라 검증한 기능·테스트·정제된 증거를 한 단위로 저장합니다. `git status --short`와 자기 diff를 확인하고 **소유 경로만** add 후 `git commit -- <명시 경로>`로 커밋합니다. 커밋 직후 파일 목록을 대조하고 해당 branch를 push한 뒤 `git ls-remote origin refs/heads/<실제 branch>`의 SHA를 대조합니다. 워커는 자기 branch만 공유하고 main 통합은 메인에게 맡깁니다. force push·reset·stash·원장 초기화·일괄 add로 충돌을 숨기지 않습니다.

회신에는 작업 ID·실제 PC/계정·기준/결과 SHA·소유 파일·입력/명령·기대/실측·실패/수정·재검증·한계를 적습니다. push 성공을 다른 PC의 수신 완료로 보고하지 않습니다. 키·원천 행·운영 식별값·원본 JSONL은 보내지 않고 합성 미디어만 Release+해시로 전달합니다.

**인수 경로를 구분합니다.** 기존 `ops/tasks.json`의 45개 ID는 pc1이 해당 `review`→증거 검증→`accept --evidence` 절차를 수행합니다. 야간 **N01~N04는 이 CLI의 ID가 아닙니다.** `ops/tasks.py accept N02` 같은 명령을 만들지 않습니다. 메인이 배정 이슈의 커밋/계약·격리 검사·실제 UI/기능·반례를 검증한 후 `ops/overnight-tasks.json`과 관련 보고에 인수 증거를 기록하고 같은 이슈에 회신한 뒤 종결합니다. 워커는 표나 이슈를 스스로 완료 처리하지 않습니다. 기존 3개 준비 DONE을 제품 구현 완료율로 사용하지 않습니다.

## 배포·비용·재개 경계

- 배포 때만 [docs12](../../../docs/12_Vercel_행사계정_연결.md)·[계정 보고](../../../reports/deployment/account-auth-status.md)와 최신 실행 증거를 다시 읽습니다. 대상은 **52g Studio / g-28**, 명시 scope는 `52g-studio`입니다. CLI의 의도한 target 대신 실제 배포 API의 target·상태·URL과 보호된 화면/API/상태 지속을 검증합니다. READY나 URL 발급만으로 최종 배포 완료를 쓰지 않습니다.
- 기존 Blob 생성 **403**, TEST 발송·로컬 API 재시작·AWS 설치의 **정책 거부**는 다른 도구/PC/계정/자동화로 우회하지 않습니다. 명시적인 권한 또는 외부 상태 변경 증거 없이 같은 거부 동작을 재시도하지 않습니다. 새 거부도 명령·시각·주어진 사유를 기록하고 독립 가능한 부분만 진행합니다. 정책 거부와 단순 테스트 실패를 혼동하지 않습니다.
- 영속 상담 상태·전역 예산 원장이 준비되지 않은 배포를 전체 흐름 성공으로 세지 않고, 실패를 로컬 임시 저장으로 숨기지 않습니다. 과금 호출은 자동 재개 루틴에 넣지 않습니다. 이미 승인된 합성 시연/고정 평가라도 메인이 기존 원장·잔여 한도·호출 수·입력을 확인해 **명시적으로 한 번** 실행할 때만 수행하며, 실패 기록을 보존하고 자동 재시도·새 원장·병렬 PC별 예산 분리를 하지 않습니다.
- 메인에는 30분 heartbeat **`automation`**이 있습니다. 현재 설정·소유 작업을 확인하고 그 예약을 사용하며 중복 생성하지 않습니다. 스킬 설치나 watcher 출력은 재개 성공을 보장하지 않습니다. 워커는 자기 PC의 실제 예약·앱 유지 여부를 별도로 보고합니다. 변동 없는 주기에는 새 상태 편지/사용자 알림을 만들지 않고, 결과·실패·차단·인계처럼 의미 있는 변화만 알립니다.
