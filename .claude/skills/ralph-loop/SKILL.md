# 랄프 루프

같은 프롬프트를 계속 물려 스스로 다음 할 일을 찾는 방식입니다. 사람이 매번 지시하지 않는
대신 **무엇을 끝났다고 볼 것인가**가 먼저 정해져 있어야 합니다.

## 시작 전 — 신원

```bash
python channel/whoami.py
```

「미등록」이면 **거기서 멈추고** hostname 을 사용자에게 보고합니다. `pcs.json` 을 스스로
고치지 않습니다.

## 🚨 감시기는 세션을 깨우지 못한다

`watch` 는 **터미널에 찍을 뿐** Codex·Claude 대화를 스스로 재개시키지 않습니다.
벨이 울려도 세션이 멈춰 있으면 멈춘 채입니다. 그래서 쓰는 곳이 둘로 갈립니다.

| 누가 본다 | 방법 |
|---|---|
| **사람** | 별도 터미널에 `watch --interval 30 --bell` 을 띄워 둔다. 사람이 보고 세션을 깨운다 |
| **루프 자신** | 루프 맨 위에서 **`watch --once` 를 직접 부른다** ← 이쪽이 랄프 루프의 정답 |

`watch --once` 는 변화가 없으면 **아무것도 출력하지 않습니다.** `inbox` 를 매번 부르는 것과
달리 목록으로 시야를 덮지 않고, 호출도 1회뿐입니다.

## 1회 루프

```
1. python channel/mail.py watch --once        ← 조용하면 새것이 없는 것. 그냥 넘어간다
2. 출력이 있었으면 → mail.py inbox / read 로 처리
3. 맡은 덩어리를 끝낸다                          ← 기본. 여기에 시간을 쓴다
4. mail.py status --set "<지금 하는 일 한 줄>"
5. 1 로
```

🚨 **1번에서 출력이 없으면 inbox 를 부르지 마십시오.** 부를 이유가 없습니다.

### 편지를 처리할 때

1. `read <번호>` — **「검증 방법 + 기대값」 칸을 먼저** 읽습니다. 그것이 끝난 조건입니다.
2. 작업합니다.
3. 기대값을 **대조**합니다.
   - 못 맞췄으면 `done` 하지 않고 `reply` 로 막힌 지점을 수치와 함께 적습니다.
   - 맞췄으면 `done <번호> --evidence "<대조 결과 — 수치·시각>"`.

## 🚨 멈춰야 하는 때

| 신호 | 무엇을 한다 |
|---|---|
| **한 가지에 30분** | 루프를 멈추고 **사람에게** 올린다. 다른 워커에게 넘기지 않는다 — 권한 세탁이다 |
| 「끝난 조건」을 모르겠다 | 메인에게 유형 C 로 묻는다. 추측해서 만들지 않는다 |
| 같은 오류를 3번 같은 방법으로 | 접근을 바꾼다. 같은 것을 반복하는 것은 진전이 아니다 |
| 다른 워커 산출물이 필요 | 더미로 인터페이스를 고정하고 계속한다. 기다리지 않는다 |

## 🚨 랄프 루프가 흔히 빠지는 것

| 함정 | 증상 | 대응 |
|---|---|---|
| **끝을 모른다** | 다 됐는데 계속 다듬는다 | 「끝났다고 말할 수 있는 조건」을 루프 시작 전에 적어 둔다 |
| **기다린다** | 남의 산출물을 기다리며 헛돈다 | 더미로 먼저 완성한다. 진짜는 나중에 갈아 끼운다 |
| **범위가 커진다** | 시킨 것 말고 다른 것을 고치고 있다 | 한 덩어리 = 한 편지. 벗어나면 새 편지로 분리한다 |
| **검증을 자기 자로 잰다** | 「에러 없음」으로 done 한다 | 편지에 적힌 기대값으로만 판정한다 |
| **상태를 편지로 만든다** | 편지함이 상태보고로 덮인다 | `status --set` 만 쓴다 |

## 덩어리 자르기

메인이 주는 덩어리가 너무 크면 **받는 쪽에서** 쪼개도 됩니다. 쪼갠 사실을 회신에 적습니다.

> 한 덩어리 = **한 번에 검증 가능한 것**. 검증이 두 갈래면 두 덩어리입니다.

## 네트워크가 끊기면

작업을 계속합니다. **루프를 멈추지 않습니다.** 편지는 복구 후 한 번에 보냅니다.
감시기는 실패해도 죽지 않고 재시도합니다(간격을 늘려 가며).

🚨 「보냈는데 조용하다」를 「상대가 안 한다」로 읽지 마십시오. `gh` 가 실패했는지부터 봅니다.

## 체크포인트에서 버리는 순서

시간이 부족하면 이 순서로 버립니다. 미리 정해 두면 새벽에 다투지 않습니다.

1. 관리자 통계 화면
2. 시나리오 수 축소
3. 실시간 생성 → 미리 만든 파일
4. 예쁜 화면
5. **핵심 경로 한 줄기** ← 마지막까지 지킨다

편지함 사용법은 `mailbox` 스킬, 전체 구조는 `docs/00_랄프톤_운영설계.md`.
