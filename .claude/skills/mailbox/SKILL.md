# 세션 간 편지함

노트북 4대가 랄프 루프로 동시에 돕니다. 서로 직접 대화할 수 없어 **GitHub Issues** 를
편지함으로 씁니다.

```
받은편지함 = to:<내슬롯> 라벨이 붙은 open 이슈
보내기 = 이슈 생성    회신 = 코멘트    처리완료 = close
상태보고 = 편지가 아니다 — 고정 이슈 body 를 덮어쓴다
```

## 🚨 무엇보다 먼저 — 신원

```bash
python channel/whoami.py
```

**「미등록」이 나오면 거기서 멈추십시오.** 편지함을 읽지 말고 사용자에게 hostname 을 보고합니다.
`pcs.json` 을 스스로 고치지 않습니다 — 슬롯 배정은 메인이 합니다.

등록 전에 읽으면 **남의 편지를 처리하는 사고**가 납니다. 실제로 났던 사고입니다.

## 명령

| 하려는 것 | 명령 |
|---|---|
| 내 앞 편지 | `python channel/mail.py inbox` |
| 본문 + 회신 전부 | `python channel/mail.py read <번호>` |
| 편지 보내기 | `python channel/mail.py send --to pc3 --type A --title "..." --body-file <파일>` |
| 회신 | `python channel/mail.py reply <번호> --body "..."` |
| 처리완료 | `python channel/mail.py done <번호> --evidence "..."` |
| 상태 갱신 | `python channel/mail.py status --set "지금 하는 일"` |
| 4대 현황 | `python channel/mail.py board` |

## 절차

### 편지를 받았을 때

1. `read <번호>` 로 본문을 봅니다.
2. **「검증 방법 + 기대값」 칸을 먼저** 읽습니다. 그것이 끝난 조건입니다.
3. 작업합니다.
4. 기대값을 **대조**합니다. 못 맞췄으면 `done` 하지 말고 `reply` 로 막힌 지점을
   수치와 함께 적습니다.
5. 맞췄으면 `done <번호> --evidence "<대조 결과>"`.

🚨 `--evidence` 에 **「에러 없음」·「정상 동작」을 적지 마십시오.** 그건 검증이 아닙니다.
무엇을 보고 됐다고 판단했는지 — 수치·시각·PID·건수를 적습니다.

### 편지를 보낼 때

본문은 6칸입니다. 상대는 **이 대화의 앞부분을 모릅니다.**

```markdown
## 왜 지금
배경 2~3줄

## 해줘야 할 일
- [ ]

## 실행 명령
```bash
# 복붙 가능하게 · 상대 PC 기준 절대경로
```

## 검증 방법 + 기대값
<무엇을 보면 됐다고 판단하는가. 구체적인 값>

## 중단 조건
<거부되면 멈추고 회신 — 상대가 임의로 밀어붙이지 않게>
```

제목은 **결론 한 줄**입니다. 목록에는 제목만 뜹니다. 인사·서론을 넣지 마십시오.

### 유형 고르기

| 유형 | 언제 |
|---|---|
| `A` 즉시조치 | 상대가 실행해야 한다 |
| `C` 결정요청 | 사람 승인이 낀다 — **가장 오래 걸리니 일찍 띄운다** |
| `D` 규칙전달 | 규칙·설계·인터페이스 계약 |
| `E` 경고정정 | 판정이 틀렸다 / 위험한 명령을 멈춰라 (`--urgent` 함께) |
| `F` 자료전달 | 산출물 **경로** (값 아님) |

## 🚨 이것은 편지로 만들지 않는다

| 유형 | 비중 | 대신 |
|---|---:|---|
| **B** 상태 보고 | **51.5%** | `status --set` |
| **H** 교차검증·판정 정련 | 5.8% | 기존 편지에 코멘트 |
| **G** 감시 개시·종료 | 1.4% | 아무것도 안 한다 (회신 도달률 10%) |

절반 이상이 편지가 아닙니다. 안 지키면 편지함이 상태보고로 덮여 진짜 지시가 묻힙니다.

## 금기

| # | 금기 | 왜 |
|---|---|---|
| 1 | 「그쪽」이라고 쓰지 않는다 | 한 PC 에 세션이 여럿. 합쳐 읽으면 자기가 한 적 없는 판단을 되돌려받는다. **슬롯명으로 인용한다** |
| 2 | 워커끼리 직접 지시하지 않는다 | 지시는 메인(pc1)만. 워커가 다른 워커 산출물이 필요하면 메인에게 유형 C |
| 3 | 시크릿 값을 본문에 넣지 않는다 | 경로만. `mail.py` 가 막지만 검사기를 믿고 붙여넣지 않는다 |
| 4 | 막힌 일을 남에게 넘기지 않는다 | 권한 세탁. 30분 막히면 사람에게 올린다 |
| 5 | 회신 없이 닫지 않는다 | 「조용하다」가 「안 했다」로 읽힌다 |
| 6 | 관측에 기준을 안 붙이지 않는다 | 「2시간째 그대로」가 **자기 기준**이면 상대 기준으로는 11분일 수 있다. 실제로 그랬다 |

## 합의했으면 파일로 옮긴다

> 채널은 **전달 수단이지 보관 수단이 아닙니다.**

규칙·판정 기준·인터페이스 계약을 이슈에서 합의했으면 그 자리에서 어느 파일 몇 절인지
정하고 옮깁니다. 정할 곳이 없으면 그 합의는 내일 없습니다.
PC 별 진행 상황은 옮기지 않습니다 — 낡아서 거짓이 됩니다.

## 보낸 뒤

`gh issue create` 성공은 **도달**입니다. 읽었는지는 **회신으로만** 압니다.
「조용하다」를 「안 했다」로 읽지 마십시오. `gh` 가 실패했는지부터 확인합니다.
