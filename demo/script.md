# OneFlow 5분 발표·시연 대본 — 검증 결과 반영 전 초안

목표는 경영주 문의를 상담원이 정확히 정리하고, WMS/TMS 근거와 미확인을 함께 센터에 넘겨 최종 회신까지 이어가는 것입니다. 이 대본은 발표 준비물이며 실제 녹화·리허설 완료를 뜻하지 않습니다. 최대 5페이지·발표5분·질의응답3분을 따릅니다. 실제 릴리스·URL·수치가 확정되면 아래 미확인 부분을 바꾸고 버전을 남깁니다.

## 1페이지 · 현장 문제와 목표 — 0:00~0:40

“점포에서 상품이 오지 않았거나 다른 상품이 왔다고 연락하면, 상담원은 통화 내용을 정리하면서 물류 기록과 담당 부서를 찾아야 합니다. 통화 중 단위를 잘못 적거나, 기록이 없다는 이유로 배송이 안 됐다고 단정할 수도 있습니다. OneFlow는 통화가 끝난 뒤 또는 웹 문의가 들어온 뒤, 원문·AI 제안·사람 수정을 구분해 정확한 확인과 이관을 돕습니다.”

화면: 상담 작업대의 문의 선택·현재 상태·다음 행동. 실제 운영 처리시간 절감률이나 사용자 만족도는 측정 전이므로 말하지 않습니다.

## 2페이지 · 실제 Goal과 결과 위임 — 0:40~1:30

“대표 목표는 미도착·오출고 두 흐름을 접수부터 센터 최종 회신까지 연결하는 것입니다. 메인은 계약·통합·독립 검증을 맡고, 통화 UX와 WMS 등은 결과와 수용 기준을 정해 분담했습니다. 각 기능을 구현하기 전에 설계하고, 작은 실험으로 병목을 확인한 뒤 수정·재검증합니다.”

화면: 실제 Goal 원문의 필요한 부분, 파일 소유와 검증 연결 그림. `reports/goal-start-20260921.md`와 실제 JSONL 사건 대조를 근거로 합니다. 계획 초안 전체가 실행됐다고 말하지 않습니다. 다른 PC의 착수·커밋·인수는 발표 직전 실제 회신으로 갱신하며 4대 모두 구현 중이라고 일괄 표시하지 않습니다.

## 3페이지 · 두 흐름 실제 시연 — 1:30~4:00

리허설로 이 150초 배분을 검증해야 합니다. 실제 대기시간이 넘으면 검증된 녹화 구간으로 전환하고 배속·편집·저장 결과 재생을 표시합니다. 실행하지 않은 AI 호출을 실시간 호출처럼 보여주지 않습니다.

| 구간 | 사용자 행동 | 확인할 결과 |
|---|---|---|
| 미도착·통화 | 사례 선택→합성 녹음 재생→종료→분석 | 원음/STT·AI 정제·사람 확인 구분, 미확인 점포·수량은 추정하지 않음 |
| 미도착·물류 | TMS에서 해당 사건의 계획/실적 확인 | 도착 기록 부재와 실제 미도착을 구분, 방문순서는 개념 표시 |
| 미도착·전달 | 점포/문의 대상/부서 대조→접수 저장→사람 확인→센터 전달 | 센터에서 같은 사건·선택 근거·남은 질문 조회 |
| 오출고·웹 입력 | 경영주 텍스트 제출→상담 작업대→실제 AI 정제 | 신규 접수 번호·원문 보존, AI 분석과 사람의 수동 입력 구분 |
| 오출고·물류 | WMS 피킹/분류 이벤트→연결 CCTV 구간 | 해당 토트·카메라·시각과 AI 합성 표시, 관측 차이를 귀책으로 단정하지 않음 |
| 센터 회신 | 확인한 범위로 회신 작성→남은 조치 등록→중간 회신→조치 완료→최종 회신 | 남은 조치가 있으면 종결 불가, 등록된 센터 회신만 경영주 화면에 표시 |

시연 데이터는 독립 합성 자료이며 실제 WMS/TMS 접속·실제 CCTV·실제 물류 조치를 수행한 것은 아닙니다. 새 웹텍스트는 저장 결과 재생이 지원되지 않으므로, 실모델이 준비되지 않으면 이 부분은 수동 검토 경로라고 밝히고 AI 경로 완주로 세지 않습니다. 클라우드가 읽기 전용이면 접수/회신 저장 시연을 주장하지 않고 검증된 로컬 환경 또는 실제 녹화를 사용합니다.

## 4페이지 · 실패를 어떻게 고쳤는가 — 4:00~4:40

“검사는 화면이 열리는지에서 끝내지 않았습니다. 실제 모델에 고정20건과 별도12개 경계 입력을 주고, 수량·단위·문의 대상·요청·부서를 독립 검토했습니다. 초기 평가에서 기존 상담 문구 복사와 주문/수령 혼동을 발견해, 원문 추출과 상담원 입력 대조를 분리하고 같은 입력으로 재검증했습니다.”

마지막 문장의 **재검증 완료 표현은 실제 재실행 결과가 있을 때만** 사용합니다. 현재 수정 전 증거는 고정85/120=70.83%, 경계52/72=72.22%, 안전 실패5건입니다. 발표 숫자는 최신 `reports/evaluation/`의 동결 입력·실제 실행·독립 검토가 연결된 결과를 사용합니다. 테스트 수·화면 수·모델 정확도의 분모를 합치지 않습니다.

## 5페이지 · 결과·한계·사용 — 4:40~5:00

“OneFlow는 원문과 근거를 보여주고, 확인되지 않은 내용은 질문으로 남기며, 최종 회신은 센터 담당자가 책임지도록 연결합니다. 운영 도입에는 실제 시스템 연결, 역할별 인증, 사람 사용성 검증이 필요합니다.”

화면: 발표 직전 접근 확인한 실행 링크·GitHub·검증 결과·남은 한계. 단순 Preview 발급을 배포 완료로 표현하지 않습니다. 09시 인계와 12시 공식 제출은 각각 별도 확인합니다.

## 질의응답 3분 준비

- **규칙만으로 충분하지 않나요?** 비정형 발화의 대상·요청 추출은 AI가 돕고, 버전 충돌·상태 전이·원장·사건 범위는 코드로 검사합니다. 모델 의미 정확도는 별도 평가합니다.
- **실제 데이터·영상인가요?** 시연 입력·음성·영상은 합성입니다. 원천자료는 로컬 구조 참고 범위이며 시연 데이터로 외부 전송하지 않았습니다.
- **AI가 틀리면 어떻게 하나요?** 원문과 제안을 나누어 보여주고 확인 질문·사람 수정·이관 확인을 거칩니다. AI 제안을 최종 회신이나 실제 처리 결과로 자동 확정하지 않습니다.
- **얼마나 효과가 있나요?** 실제 상담원 대조 실험은 아직 별도입니다. 현재 제시 가능한 값은 해당 릴리스에서 실행한 기능·품질 검사 결과입니다.
- **밤새 자동으로 완료됐나요?** 실제 Goal·로그·커밋·PC별 결과와 미달을 구분해 설명합니다. 예약 설정이나 긴 실행 시간만으로 자율 완성·가점을 주장하지 않습니다.
