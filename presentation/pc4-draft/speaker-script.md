# 5분 발표 대본과 조작 순서

**총300초 계획, 사람 낭독·제품 조작 리허설 NOT_RUN.** 이번 카드에서는 서버나 브라우저를 시작하지 않았습니다. 아래는 발표자가 검증된 빌드에서 사전 연습할 순서입니다. PDF에 보이는 화면은 기존 합성 사례의 정지 화면입니다. e1ef36f는 자료 고정 기준이고 그 최신 제품을 통합 검증했다는 뜻은 아닙니다. 최종 발표 전 pc1이 실제 사용할 빌드·음원 버전을 다시 확정해야 합니다.

## 1장 00:00–00:30 / 문제와 목표

“해피콜 OneFlow는 미도착과 오출고 문의를 다룹니다. 상담원은 통화나 웹 원문을 읽고, 주문·물류 기록을 확인한 뒤 센터에 전달합니다. 저희 목표는 이 과정을 한 사건의 근거와 함께 연결하고, 센터가 최종 회신하면 경영주가 확인할 수 있게 하는 것입니다. 지금 보여드리는 자료는 독립 합성 사례입니다. 업무시간 단축이나 실 운영 연동을 측정한 결과는 아닙니다.”

조작: PDF 1장 고정, 미도착·오출고 두 유형과 최종 회신까지의 목표를 가리킵니다. 별도 로그인·실운영 데이터는 사용하지 않습니다.

## 2장 00:30–01:35 / 통화·텍스트 접수와 사람 확인

“통화는 종료 후 정제합니다. 화면의 원문이나 STT와 AI 제안, 사람이 고친 값은 서로 구분합니다. 이 발표의 기본 모드는 이미 저장한 분석 결과 재생이며 새 API 비용은 발생시키지 않습니다. 실제 STT·GPT 실행 기록은 별도 평가 보고서로 구분합니다. 텍스트 문의는 입력 원문을 보존하고 STT 없이 같은 검토 흐름으로 들어옵니다.”

“첫 번째 Bolt는 수량과 단위가 누구의 어떤 시점 발화인지 확인하는 실험입니다. 주문 수량을 수령 수량으로 옮겨 쓰는 오류를 고쳤고, 저장된 모델 응답32건을 다시 처리해4건 변경·28건 유지를 관측했습니다. 자동 네 필드는128/128이지만 전체 의미 정확도나 새 라이브 평가 결과는 아닙니다. 요청을 지나치게 지우는 P2도 남아, 상담원이 원문을 확인하고 수정하는 단계가 필요합니다.”

조작 계획65초: 10초 원문/저장 결과 모드 표시, 15초 통화 종료 후 결과 영역과 인용 확인, 15초 수량·단위·요청·담당 부서 대조 및 사람 확인, 10초 텍스트 인입 시작점 설명, 15초 Bolt 근거와 한계. 통화 전체 청취를 건너뛰어 분석 게이트를 열지 않습니다. 완료 전 상태라면 이65초 안에 전체 음원을 급히 돌리지 말고 정지 증거 화면으로 설명합니다.

PDF 화면은 pc1의 기존 상담 화면 일부이며 **정제 실행 전·미저장 초안 상태**입니다. 새 정제 완료 화면으로 표현하지 않습니다. 발표자가 실제 시연하려면 검증 빌드의 완료 조건과 모드를 확인해야 합니다.

## 3장 01:35–03:10 / 물류 근거와 센터 최종 회신

“미도착 사례에서는 TMS의 계획 도착과 실제 등록을 나눠 봅니다. 실제 도착 기록이 없다고 실제 미도착이라고 확정하지 않습니다. 센터에 확인할 내용을 남깁니다. 오출고 사례는 WMS의 주문·출고 차이와 같은 사건의 근거를 대조합니다. 지도와 CCTV는 합성 설명 자료이고 실제 GPS나 귀책 판정 증거가 아닙니다.”

“두 번째 Bolt는 작업대에서 연결 근거를 읽게 한 실험입니다. 동일하게 선택한 근거 두 건이 ID만 보이던 화면에서 내용·출처·시각·상태를 갖춘 두 카드로 바뀌었습니다. 사건이나 시각이 맞지 않는 기록은 자동 채택하지 않습니다. 이해도나 처리시간 개선은 아직 측정하지 않았습니다.”

“상담원이 원문과 담당 부서를 확인해 이관하면 센터가 회신합니다. 남은 조치가 있으면 처리 중이고, 최종 회신과 조치 완료 후에 종결합니다. 경영주는 등록된 회신과 상태를 조회합니다. 실제 재배송이나 재고 변경을 실행한 것은 아닙니다.”

조작 계획95초: 25초 CASE-0001 TMS 계획/실적·미확인 확인, 25초 CASE-0002 WMS 주문/출고·해당 합성영상 위치 확인, 15초 작업대의 연결 근거와 원문 대조, 20초 사람 확인·센터 이관·회신·남은 조치/종결 구분, 10초 경영주 조회. 다른 사례의 영상이나 근거를 대체하지 않습니다. 전체12초 영상 재생이 필요하면 WMS25초 구간에 포함합니다. 이 카드에서 영상이나 제품을 재실행하지 않았습니다.

PDF의 TMS 화면은 pc1 기존 고정 빌드의 선택 방문 영역 일부입니다. 센터·경영주 전체 흐름의 실행 근거는 pc1의6/6 통합 보고이고 이 정지 화면 자체로 전체 흐름을 증명하지 않습니다. 새 CCTV 수정 UI와 v3 부모 흐름에 이전 통과를 소급하지 않습니다.

## 4장 03:10–04:15 / 결과 중심 위임과 실패 수정

“실제 Goal은9월21일17시22분02초에 시작했습니다. 접수부터 최종 조회까지의 결과와 검증 조건을 맡기고, 메인이 통합하며 각 PC가 통화·WMS·TMS와 독립 QA를 맡았습니다. 상세 Goal 문서의 긴 초안을 실제 실행 원문처럼 소급하지 않았습니다.”

“pc4의 복구 검수는c6f734f 제품에서8개 축·297개 관측을 통과했습니다. 첫 실행3/8, 다음7/8에서 검사기의 화면 선택자 오류를 발견했고 검사기만 고친 뒤 같은 조건으로8/8을 확인했습니다. 세 실행의 원본33개도 보존했습니다. 통과 후에도 새 저장이 미확정인데 이전 성공 알림이 남는 P2를 보고했습니다. 데이터 잠금이 통과했다고 화면의 혼선을 숨기지 않았습니다.”

조작 계획65초: 20초 실제 Goal 시각·완료선, 10초 역할별 결과 책임, 20초 Q3 실패/수정/재검증 경로와 원본 보존, 15초 기존390px 화면의 성공 알림·미확정 안내를 함께 표시합니다. 녹색 이전 알림을 현재 저장 성공이라고 설명하지 않습니다. 사람 발언·합의·사용성 관찰이나 실제 에이전트 수를 만들어내지 않습니다.

## 5장 04:15–05:00 / 검증 범위와 남은 인계

“pc1 고정 빌드에서 음성 두 흐름은각3회6/6, 텍스트는2/2였습니다. pc4의8축은 별도 제품과 실행이고 이를 더해 통과 총계를 만들지 않습니다. 고정 자료의 v3 부모 흐름은 미확인입니다. 이후 메인이 사용자 부정 청취 피드백 1건을 전달했습니다. 기술 검사와 자연스러움은 별개이고, v4는 대본 후보로 전체 합성·STT·제품 교체가 남았습니다.”

“남은 조건은 분명합니다. 원격 영속 저장이 연결되지 않았고 최종 배포는 완료가 아닙니다. 오프라인 읽기는 가능해도 전체 저장 처리는0/1로 막힙니다. 체계적 청취·사용성 검증과 남은 P2, 수정 CCTV의 새 브라우저 검수가 필요합니다. 시연 중 장애가 나면 기존 증거와 미확인 안내로 전환하고 성공을 만들지 않겠습니다.”

조작 계획45초: 20초 버전·실행주체별 분모 대조, 25초 저장·오프라인·P2·미실행 조건 공개. 공식20/20/30/30은 배점이며 확보 점수나 예상 점수를 말하지 않습니다. 발표 후 질의응답3분은 별도입니다.

## 질의응답용 짧은 답

- 실제 데이터인가요? 독립 합성 사례와 합성 음성·영상입니다. 실 WMS/TMS·GPS·CCTV 연동을 완료했다고 주장하지 않습니다.
- 한국어 음성이 자연스러운가요? 기존 v3에 사용자 부정 청취 피드백 1건이 메인을 통해 전달돼 개선 중입니다. 재생·전사·복구 검사는 자연스러움 통과나 MOS 점수가 아닙니다. v4 대본 후보는 전체 합성·STT·제품 교체까지 완료된 것이 아닙니다.
- AI가 틀리면요? 원문 인용·미확인·확인 질문을 구분하고 사람이 고칩니다. 요청 과잉 철회 P2와 라이브 품질의 미검증 범위를 남겼습니다.
- 인터넷이 끊기면 저장되나요? 이 범위에서는 아닙니다. 오프라인 읽기 전용이며 전체 처리0/1 BLOCKED입니다. 저장 미확정이면 서버 조회 후 대조하고 새 접수를 중복 생성하지 않습니다.
- 효과가 얼마나 있나요? 내용 카드0→2와 테스트 관측을 제시할 수 있습니다. 실제 업무시간·만족도·비용 절감은 측정하지 않았습니다.
- 배포가 끝났나요? 계정 연결과 배포 완료를 구분합니다. 고정 문서 기준으로 원격 영속 저장·최종 배포·공식 제출은 미완료입니다.
